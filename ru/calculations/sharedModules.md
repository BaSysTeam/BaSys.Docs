# Общие модули

**Общий модуль** — именованный JavaScript-скрипт, который возвращает объект экспорта (функции, константы) и доступен из любого скрипта платформы через обращение `$m.<имя_модуля>.<член>`. Одно и то же тело модуля исполняется и в браузере, и на сервере, поэтому функция, написанная один раз, работает везде, где BaSYS выполняет пользовательский код:

- формулы и источники элементов (`itemsSource`) колонок объектов метаданных;
- [программируемые команды](../commands/programmableCommands.md) объектов;
- [шаги процессов](../workflows/scriptStep.md) — синхронные и асинхронные;
- источники данных [отчётов Excel](../reporting/excelReport.md), [печатных форм](../reporting/printForms/dataRetrieval.md) и [представлений данных](../reporting/dataView.md);
- [источники записей регистров](../metadata/recordsCreation.md) и формулы колонок при записи движений;
- [программируемые формы](../userInterface/programmableComponents.md);
- консоль выражений конструктора.

Общие модули нужны для *вашего* повторно используемого кода: констант контура, разбора значений, ключей, типовых расчётов. Функции библиотеки [BaSYS.Fx](index.md) при этом остаются доступными напрямую — выносить их в модуль не нужно.

## Создание модуля в конструкторе

Модули редактируются в конструкторе, раздел **Общие модули** в группе **Системные** (между «Создать на основании» и «Консоль»). Редактор модуля — отдельная страница с полями:

| Поле | Описание |
| :--- | :--- |
| **Название** (`title`) | Обязательное. Отображается в списке модулей. |
| **Имя** (`name`) | Обязательное. Идентификатор для обращения `$m.<имя>`. Должно соответствовать `^[A-Za-z_][A-Za-z0-9_]*$`; уникально в базе без учёта регистра. |
| **Активен** (`isActive`) | Признак активности. У неактивного модуля тело не исполняется (см. [Активность, версия, обновление](#активность-версия-обновление)). |
| **Комментарий** (`memo`) | Необязательное краткое описание назначения модуля. |
| **Версия** (`version`) | Только для чтения. Увеличивается на единицу при каждом сохранении. |
| **Скрипт** (`script`) | Тело модуля в редакторе кода. |

На вкладке **Где используется** редактор показывает объекты и места, в скриптах которых встречается обращение к модулю (см. [Где используется](#где-используется-удаление-и-переименование)).

## Структура тела модуля

Тело модуля исполняется как функция, поэтому оператор `return` обязателен: то, что возвращено, становится объектом экспорта, всё остальное остаётся приватным. Возврат не объекта (числа, строки, `undefined`) — ошибка инициализации.

Минимальный модуль — одна функция:

```javascript
// Тело модуля: объявляем функции и константы, возвращаем объект экспорта.
function testFn() {
  return 'test';
}

return {
  testFn
};
```

Модуль с константой и функцией:

```javascript
const RATE = 0.2;

function withVat(amount) {
  return amount * (1 + RATE);
}

return { RATE, withVat };
```

Правила, которым должно соответствовать тело:

- Верхний уровень тела **синхронный**: `await` допустим только внутри функций. `await` на верхнем уровне не проходит проверку синтаксиса при сохранении. Сами функции модуля могут быть `async`.
- Модуль — не ES-модуль: `import`, `export` и npm-пакеты недоступны.
- Внутри тела доступны функции BaSYS.Fx и другие модули через `$m` (см. [Что доступно внутри модуля](#что-доступно-внутри-модуля)).
- Браузерные объекты (`window`, `document`, `alert` и другие) использовать нельзя — модуль исполняется и на сервере, где их нет. Это проверяется при сохранении.

## Обращение к модулю: `$m`

`$m` стоит в одном ряду с `$h` (шапка), `$t` (табличные части), `$r` (строка) и существует всегда, даже когда в базе нет ни одного модуля: обращение к неизвестному имени даёт ошибку `module '<имя>' not found`.

Обращение **синхронное**. Первое обращение к имени исполняет тело модуля, дальше возвращается закэшированный объект экспорта. Кэш живёт:

- на сервере — в пределах одного вычисления (каждый шаг процесса, каждый источник данных создаёт свой движок, поэтому тело исполняется в каждом из них заново);
- в браузере — до перезагрузки страницы.

Обращаться нужно точно тем именем, которым модуль записан: `$m.so_common`, не `$m.SO_Common`.

Формула колонки:

```javascript
return $m.so_common.positionKey($r)
```

Программируемая команда:

```javascript
const key = $m.so_common.positionKey($r);
return key;
```

Шаг процесса (`await` в тексте шага переводит его в Node.js, где внутри модуля работает `from()`):

```javascript
const method = await $m.so_common.loadMethod(_parameters.method);
return method.slice;
```

Программируемая форма — `$m` доступен в `data()`, `computed` и `methods`:

```javascript
methods: {
  refresh() {
    this.key = $m.so_common.positionKey(this.row);
  }
}
```

Деструктуризация работает и распознаётся поиском использований:

```javascript
const { positionKey, inputRowFields } = $m.so_common;
```

Динамическое обращение `$m[name]` работать будет, но такой модуль не найдётся ни в списке использований, ни в проверках при переименовании и удалении. Используйте его только при необходимости.

## Что доступно внутри модуля

Тело модуля видит функции той среды, где его вызвали, и **не видит контекст вызывающего скрипта**: `$h`, `$t`, `$r`, `_parameters`, `_data`, `_filters`, `item`, `context` и `this` формы внутри модуля всегда `undefined`. Контекст передают аргументами:

```javascript
// Модуль получает строку параметром.
function positionKey(row) { /* ... */ }

// Вызов из формулы или команды.
return $m.so_common.positionKey($r)
```

Набор доступных функций зависит от среды исполнения:

| Среда | BaSYS.Fx | `from()` | `$m` |
| :--- | :--- | :--- | :--- |
| Шаг процесса без `await` (ClearScript) | да | **нет** | да |
| Шаг процесса с `await` (Node.js) | да | да | да |
| Источник данных отчёта, печатной формы, представления без `await` | да | **нет** | да |
| Источник данных с `await` | да | да | да |
| Источник записей регистра | да | **нет** | да |
| Формула колонки при записи движений | **частично** | **нет** | да |
| Формулы, `itemsSource`, команды, консоль конструктора (браузер) | да | да | да |
| Программируемая форма (браузер) | да | да | да |

Две строки требуют пояснения.

**`from()` на сервере работает только в Node.js.** [Построитель запросов](queryBuilder.md) определён в Node.js и в браузере, но не в ClearScript. Отсюда правило: функция модуля, использующая `from()`, всегда `async`, и вызывать её нужно с `await` — из шага процесса (он уйдёт в Node.js), из источника данных с `await` или из браузера. В синхронной среде такая функция вернёт `Promise` вместо значения; конструктор предупреждает об этом при сохранении шага и при сохранении модуля.

**Формулы колонок при записи движений** вычисляются облегчённым движком, где из библиотеки определены только `isEmpty`, `isNotEmpty`, `iif`, `ifs`, `dateTimeNow`, `dateDifference` и [расширения дат](dateFunctions.md). `createTable`, `format*`, `from` там недоступны — если функция модуля их использует, вызывать её из формулы движений нельзя. Само выражение источника записей регистра при этом вычисляется в ClearScript, где BaSYS.Fx доступен полностью.

Полезная практика — указывать среду, для которой пригодна каждая функция, прямо в её комментарии (см. [пример из прикладного решения](#примеры-из-прикладного-решения)).

## Проверки при сохранении

Проверки выполняются по порядку, сохранение прерывается на первой ошибке. Сообщения об ошибках — на английском языке.

1. **Имя** соответствует `^[A-Za-z_][A-Za-z0-9_]*$`. Имена `1abc`, `rd-common`, `rd common` отклоняются.
2. **Имя уникально** без учёта регистра: если в базе есть `so_common`, модуль `SO_Common` не сохранится.
3. **Название** не пустое.
4. **`return`** присутствует как отдельное слово. `returned = 1` не считается возвратом.
5. **Запрещённые идентификаторы** отсутствуют: `alert`, `confirm`, `prompt`, `window`, `document`, `localStorage`, `sessionStorage`, `navigator`, `location`.
6. **Синтаксис**: тело компилируется движком V8 без исполнения; текст ошибки V8 возвращается автору как есть. Эта же проверка отсекает `await` на верхнем уровне.

Проверка запрещённых идентификаторов смотрит на отдельное слово: `row.location`, `$h.window`, `myAlert()`, `alertness`, `locationX` проходят, а `location` само по себе — нет. Строки и комментарии не разбираются: слово `alert` в комментарии тоже отклонит сохранение — перепишите комментарий.

Частая ошибка в объекте экспорта — точка с запятой вместо запятой; проверка синтаксиса её ловит:

```javascript
// Отклоняется: `testFn;` внутри литерала объекта.
return {
  testFn;
};

// Правильно:
return {
  testFn,
};
```

## Активность, версия, обновление

Снятый признак активности не удаляет модуль: он остаётся в списке и в пакете выгрузки, но любое обращение к нему даёт ошибку `module '<имя>' is inactive`, а тело даже не передаётся в браузер. Это способ временно отключить модуль, не теряя список использований.

`version` растёт на единицу при каждом сохранении, включая переключение активности из списка. Поле только для чтения.

Сервер подхватывает новое тело сам: после сохранения кэш сбрасывается сразу, а при нескольких экземплярах приложения — в течение секунды. Браузер загружает тела всех активных модулей один раз при старте приложения, поэтому после правки модуля страницу нужно **перезагрузить (F5)**; до перезагрузки формулы и команды работают по старому телу.

## Ошибки и диагностика

Сообщения времени выполнения всегда начинаются с `module '<имя>'`, поэтому их удобно искать в журнале по имени модуля.

| Сообщение | Причина |
| :--- | :--- |
| `module 'x' not found` | Модуля с таким именем нет в базе, или страница не перезагружалась после его создания. |
| `module 'x' is inactive` | Модуль есть, но у него снят признак активности. |
| `module 'x': body must return an object` | Тело вернуло не объект или ничего не вернуло. |
| `module 'x': <текст>` | Исключение при исполнении тела. Префикс ставится один раз; вложенная ошибка сохраняет имя того модуля, где произошла. |
| `module 'a': circular dependency a -> b -> a` | Модули ссылаются друг на друга при инициализации. |

Куда попадает сообщение:

| Среда | Канал |
| :--- | :--- |
| Шаг процесса | Журнал процесса |
| Формулы, `itemsSource`, команды в браузере | Лог вычислений прикладного объекта |
| Формула колонки при записи движений | Лог записи объекта |
| Программируемая форма | Исключение в скрипте формы |
| Консоль выражений конструктора | Панель лога консоли |
| Импорт метаданных | Сообщения сводки импорта |

Циклическая зависимость определяется в момент инициализации: если `a` при исполнении тела читает `$m.b`, а `b` — `$m.a`, обращение к `$m.a` даёт ошибку с полной цепочкой. Цикл между *функциями* модулей (функция `a` вызывает функцию `b`, которая вызывает функцию `a`) циклом инициализации не является и ошибки не даёт. Поэтому обращение к другому модулю лучше размещать внутри функций, а не на верхнем уровне тела — так сделано в модуле `so_fill` ниже.

## Где используется, удаление и переименование

В редакторе модуля есть вкладка **Где используется**: объект, вид, место. Места записываются как:

| Место | Что сканируется |
| :--- | :--- |
| `header.<колонка>.formula`, `header.<колонка>.itemsSource` | Формулы и источники элементов колонок шапки |
| `table.<таблица>.<колонка>.formula`, `table.<таблица>.<колонка>.itemsSource` | Колонки табличных частей |
| `command.<имя>` | Программируемые команды |
| `recordsSource.<заголовок>` | Источники записей регистров |
| `step.<имя>` | Шаги процессов: JavaScript, условие, сообщение, HTTP, SMTP, чтение файла, загрузка объекта |
| `form.<имя>` | Программируемые формы |
| `constructorForm.<имя>` | Формы конструктора (скрипт инициализации) |
| `dataSource.<имя>` | Источники данных печатных форм, отчётов Excel и представлений |
| `createFrom.<заголовок>` | Скрипты «Создать на основании» |
| `module.<имя>` | Тела других модулей |

Поиск текстовый, по `$m.<имя>`, поэтому находит и прямые обращения, и деструктуризацию, но не находит динамические (`$m[name]`) и не различает вхождения в комментариях.

Удаление и переименование модуля, у которого есть использования, требуют подтверждения: конструктор показывает список мест, где встречается `$m.<имя>`, и кнопку «Удалить всё равно» / «Переименовать всё равно». Переименование ссылки в скриптах **не правит** — их нужно поправить вручную.

### Предупреждение об асинхронной функции

Конструктор предупреждает, если `async`-функция модуля вызывается из синхронной среды, где она вернёт `Promise` вместо значения. Предупреждение появляется в двух случаях:

- при сохранении процесса, если синхронный шаг (без `await`) вызывает `async`-функцию модуля;
- при сохранении модуля, если функция стала `async`, а её синхронные вызовы уже есть в базе.

Текст предупреждения:

```
$m.so_common.loadMethod is an async function; called from a synchronous step it returns a Promise instead of a value.
```

Предупреждение не блокирует сохранение. Асинхронной считается функция, объявленная через `async function n`, `const n = async …` или `n: async …` и попавшая в объект экспорта.

## Модули в пакете выгрузки

Модуль выгружается в свою папку `modules/<имя>/` в корне пакета метаданных, так же как процесс или меню:

```
modules/
  so_common/
    module.so_common.json
    module.so_common.bjs
  so_fill/
    module.so_fill.json
    module.so_fill.bjs
```

`module.<имя>.json` содержит настройки, `module.<имя>.bjs` — тело. В поле `script` JSON лежит имя файла тела:

```json
{
  "$schema": "../../system/schemas/sharedModuleSettings.schema.json",
  "uid": "132b638a-d044-4038-ad18-ecf9a19237b6",
  "name": "so_common",
  "title": "Выработка смены (общее)",
  "memo": "Константы, ключ позиции, разрезы способа ввода и разбор значений контура «Выработка смены».",
  "version": 2,
  "isActive": true,
  "script": "module.so_common.bjs"
}
```

Неактивные модули выгружаются тоже, с `isActive: false`.

При импорте модуль сопоставляется по `uid`, а для файлов без `uid` — по имени. Если в пакете и в базе совпали имена при разных `uid`, импорт этого модуля завершается ошибкой: нужно переименовать один из модулей или выровнять `uid`. Скрипт пакета, который ссылается на `$m.<имя>`, отсутствующее и в пакете, и в базе, даёт предупреждение в сводке импорта; импорт при этом не прерывается.

## Примеры из прикладного решения

Ниже — два модуля контура «Выработка смены» из прикладного решения для строительства. Они показывают типовое разделение: базовый модуль с константами и синхронными вспомогательными функциями и прикладной модуль, который на него опирается.

### Модуль `so_common`: константы и разбор значений

Модуль собирает константы контура, ключ позиции регистра, разрезы способа ввода и разбор значений формы. Все функции синхронные и не обращаются к базе, поэтому их можно вызывать из любой среды, включая формулы при записи движений.

Сокращённое тело модуля (полный модуль экспортирует также `toRows`, `toNumber`, `toDate`, `sameCalendarDay`, `parseJsonRows`):

```javascript
// Общий модуль so_common: константы, ключи и разбор значений контура «Выработка смены».
// Функции синхронные и не ходят в базу: их можно вызывать из шага процесса и из формы.

/**
 * uid операции operation.so_shift_output.
 * По нему в records.rd_quantity отделяется расход выработки смены от прихода плана.
 *
 * Среда: синхронная константа, работает в любой среде, включая формулы при записи движений.
 * Пример: $m.so_common.SO_SHIFT_OUTPUT_UID
 */
var SO_SHIFT_OUTPUT_UID = '8e5ea831-1f80-e4a9-3b98-5f1d6c023c60';

/**
 * uid операции operation.rd_quantities.
 *
 * Среда: синхронная константа, работает в любой среде, включая формулы при записи движений.
 * Пример: $m.so_common.RD_QUANTITIES_UID
 */
var RD_QUANTITIES_UID = 'd22cf647-2029-cb53-cdca-5612541a5c2a';

// Имя разреза способа ввода → поля строки «Ввод пользователя». Пустой массив — разрез «шифр».
var SLICE_FIELDS = {
    rd_code: [],
    system: ['rd_system'],
    element: ['rd_system', 'rd_element'],
    item_group: ['rd_system', 'item_group_2'],
    item: ['rd_system', 'rd_element', 'rd_item'],
};

// Поля ключа позиции регистра: система / элемент / номенклатура / единица измерения.
var POSITION_FIELDS = ['rd_system', 'rd_element', 'rd_item', 'unit'];

/**
 * Ключ позиции регистра records.rd_quantity: система, элемент, номенклатура и единица измерения.
 *
 * @param {object} row Строка плана, расхода или результата. Может быть null.
 * @returns {string} Четыре части через «|». Пустое поле даёт пустую часть.
 *
 * Среда: синхронная, без обращения к БД — работает в любой среде, включая формулы при записи движений.
 * Пример: $m.so_common.positionKey(row)
 */
function positionKey(row) {
    var parts = [];
    for (var i = 0; i < POSITION_FIELDS.length; i++) {
        var value = row ? row[POSITION_FIELDS[i]] : null;
        parts.push(isEmpty(value) ? '' : String(value));
    }
    return parts.join('|');
}

/**
 * Поля строки «Ввод пользователя» для разреза и единицы способа ввода работ.
 *
 * @param {string} slice Имя разреза: rd_code, system, element, item_group, item.
 * @param {string} unit Имя единицы. При item_unit к разрезам добавляется unit.
 * @returns {string[]|null} Копия списка полей. null, если разрез неизвестен.
 *
 * Среда: синхронная, без обращения к БД — работает в любой среде, включая формулы при записи движений.
 * Пример: $m.so_common.inputRowFields(slice, unit)
 */
function inputRowFields(slice, unit) {
    var fields = SLICE_FIELDS[slice];
    if (!fields) {
        return null;
    }
    var copy = fields.slice();
    return unit === 'item_unit' ? copy.concat(['unit']) : copy;
}

/**
 * Строки ответа запроса или шага процесса. DataTable отдаёт .rows, массив возвращается как есть.
 *
 * Среда: синхронная, без обращения к БД — работает в любой среде.
 * Пример: $m.so_common.toRows(source)
 */
function toRows(source) {
    if (Array.isArray(source)) {
        return source;
    }
    return source && source.rows ? source.rows : [];
}

return {
    SO_SHIFT_OUTPUT_UID,
    RD_QUANTITIES_UID,
    positionKey,
    inputRowFields,
    toRows,
    // ... toNumber, toDate, sameCalendarDay, parseJsonRows
};
```

Обратите внимание на соглашение об оформлении: у каждой экспортируемой функции и константы в комментарии JSDoc указаны параметры, возвращаемое значение, строка **«Среда»** — в каких средах функцию можно вызывать — и строка **«Пример»** с образцом вызова. Такой комментарий избавляет от необходимости открывать тело модуля, чтобы понять, можно ли вызвать функцию из синхронного шага или из формулы при записи движений.

Приватные объекты `SLICE_FIELDS` и `POSITION_FIELDS` не входят в объект экспорта и недоступны снаружи модуля.

### Модуль `so_fill`: использование другого модуля

Модуль разворачивает строки «Ввод пользователя» в количества позиций выработки смены. Он показывает два приёма:

- **обращение к другому модулю** — `$m.so_common` читается внутри функций, а не при инициализации, поэтому циклической зависимости при инициализации не возникает;
- **зависимость от среды вызова** — функция `expand` использует `createTable` и поэтому не пригодна для формул при записи движений, а `spread` не использует ничего, кроме арифметики, и работает везде. Это отражено в комментариях «Среда».

Сокращённое тело модуля:

```javascript
// Общий модуль so_fill: разворот «Ввод пользователя» в количество позиции выработки смены.
// Оба вызова синхронные и не ходят в базу. $m.so_common читается внутри функций, не при инициализации.

// Округление количества до 3 знаков.
function round3(value) {
    return Math.round(value * 1000) / 1000;
}

// ... приватные функции разбора ввода и разворота по способам:
// parseInput, hasKeys, fromPlan, percentOf, fillRdCodePercent, fillSystemPercent, ...

// name записи enum.work_entry_method → функция разворота.
var FILL_BY_METHOD = {
    rd_code_percent: fillRdCodePercent,
    system_percent: fillSystemPercent,
    element_piece: fillElementPiece,
    element_percent: fillElementPercent,
    item_group_percent: fillItemGroupPercent,
    item_group_unit: fillItemGroupUnit,
    item_percent: fillItemPercent,
    item_unit: fillItemUnit,
};

// Свёртка по ключу позиции, округление до 3 знаков. Нулевые количества отбрасываются.
function aggregate(rows) {
    var byKey = {};
    var order = [];
    rows.forEach(function (row) {
        var key = $m.so_common.positionKey(row);   // другой модуль — внутри функции
        if (!byKey[key]) {
            byKey[key] = {
                rd_system: row.rd_system,
                rd_element: row.rd_element,
                rd_item: row.rd_item,
                unit: row.unit,
                qty: 0,
            };
            order.push(key);
        }
        byKey[key].qty += Number(row.qty);
    });

    var result = [];
    order.forEach(function (key) {
        var row = byKey[key];
        row.qty = round3(row.qty);
        if (isFinite(row.qty) && row.qty !== 0) {
            result.push(row);
        }
    });
    return result;
}

/**
 * Разворачивает строки «Ввод пользователя» в строки «Выработка смены» и сворачивает их по позиции.
 *
 * @param {string} methodName Имя способа ввода. Пустое и неизвестное имя — ошибка.
 * @param {string|Array} rawInput JSON или массив строк ввода.
 * @param {object|Array} plan План шифра: DataTable или массив.
 * @returns {object} DataTable с колонками rd_system, rd_element, rd_item, unit и qty.
 *
 * Среда: синхронная, без from(). createTable берётся из среды вызова — шаг процесса без await
 *     и браузер. Из формулы при записи движений не вызывать: там нет createTable.
 * Пример: $m.so_fill.expand(methodName, rawInput, plan)
 */
function expand(methodName, rawInput, plan) {
    var fill = FILL_BY_METHOD[methodName];
    if (!fill) {
        throw new Error('Неизвестный способ ввода работ: ' + methodName);
    }

    var planRows = $m.so_common.toRows(plan);
    var inputRows = parseInput(rawInput);
    var rawRows = [];
    inputRows.forEach(function (inputRow) {
        rawRows = rawRows.concat(fill(inputRow, planRows));
    });

    var output = createTable([
        { name: 'rd_system', dataType: 'number' },
        { name: 'rd_element', dataType: 'number' },
        { name: 'rd_item', dataType: 'number' },
        { name: 'unit', dataType: 'string' },
        { name: 'qty', dataType: 'number' },
    ]);
    aggregate(rawRows).forEach(function (row) {
        output.addRow(row);
    });
    return output;
}

/**
 * Раскладывает одно введённое число по позициям плана строки ввода, без округления.
 *
 * @param {number} value Значение ячейки.
 * @param {Array} planPositions Позиции плана этой строки. Читаются plan, element_qty.
 * @param {string} methodSlice Разрез способа: rd_code, system, element, item_group, item.
 * @param {string} methodUnit Единица способа: percent, piece, item_unit.
 * @returns {number[]} Количество по каждой позиции, в том же порядке.
 *
 * Среда: синхронная, без обращения к БД и без createTable — работает в любой среде,
 *     включая формулы при записи движений.
 * Пример: $m.so_fill.spread(value, planPositions, methodSlice, methodUnit)
 */
function spread(value, planPositions, methodSlice, methodUnit) {
    var amount = Number(value);
    if (!isFinite(amount) || amount === 0) {
        return planPositions.map(function () { return 0; });
    }
    if (methodUnit === 'percent') {
        return planPositions.map(function (position) {
            return position.plan * amount / 100;
        });
    }
    // ... остальные сочетания разреза и единицы
    return planPositions.map(function () { return 0; });
}

return {
    expand,
    spread,
};
```

### Вызовы модулей

Формула колонки — `positionKey` не обращается к базе и работает в любой среде:

```javascript
return $m.so_common.positionKey($r)
```

Синхронный шаг процесса записи выработки: план получен предыдущим шагом `plan`, строки ввода и способ переданы параметрами процесса. `createTable` внутри `expand` берётся из среды шага:

```javascript
return $m.so_fill.expand(_parameters.method, _parameters.input, _data.plan);
```

Программируемая форма периода пересчитывает дерево до записи той же арифметикой:

```javascript
methods: {
  recalculateRow(row) {
    const quantities = $m.so_fill.spread(row.value, row.positions, this.methodSlice, this.methodUnit);
    row.positions.forEach((position, index) => {
      position.qty = quantities[index];
    });
  }
}
```

### Асинхронная функция модуля

Если функция модуля обращается к базе через [построитель запросов](queryBuilder.md), она должна быть `async`, а вызывать её нужно с `await`. Ниже — образец такой функции (в модуле `so_common` прикладного решения её нет; способ ввода там загружается шагом процесса):

```javascript
// Async, потому что from() доступен только в Node.js и в браузере.
async function loadMethod(methodName) {
    const result = await from('enum.work_entry_method')
        .select(['analytics_slice', 'input_unit'])
        .where('name = @method')
        .parameter('method', methodName, DbType.String)
        .query();
    const row = result.rows.length ? result.rows[0] : null;
    return {
        slice: row ? row.analytics_slice : null,
        unit: row ? row.input_unit : null,
    };
}

return { loadMethod };
```

Вызов из шага процесса: `await` в тексте шага переводит его в Node.js, где `from()` внутри модуля работает:

```javascript
const method = await $m.so_common.loadMethod(_parameters.method);
return $m.so_common.inputRowFields(method.slice, method.unit);
```

Вызов той же функции без `await` из синхронного шага вернёт `Promise`, а не объект; конструктор предупредит об этом при сохранении процесса.

## Чего модуль не делает

- **Не заменяет BaSYS.Fx.** Библиотечные функции остаются доступными напрямую; модуль нужен для вашего повторно используемого кода.
- **Не хранит состояние между вызовами надёжно.** Объект экспорта живёт столько же, сколько движок (одно вычисление на сервере) или страница (в браузере); счётчик или кэш внутри модуля обнулится в следующем шаге процесса и не переживёт перезагрузку страницы.
- **Не знает, откуда его вызвали.** Контекст вызывающего скрипта (`$h`, `$t`, `$r`, `_parameters`, `_data` и другие) внутри модуля всегда `undefined` — передавайте его аргументами.
- **Не поддерживает `import`, `export` и npm-пакеты**, а на клиенте не имеет доступа к браузерным объектам — это проверяется при сохранении.

## Рекомендации

- Выносите в модуль код, который используется более чем в одном месте: константы контура, ключи, разбор значений, типовые расчёты. Логику одного шага или одной команды оставляйте на месте.
- Указывайте в комментарии к каждой экспортируемой функции среду, в которой её можно вызывать, и пример вызова — как в модулях `so_common` и `so_fill`.
- Функции, обращающиеся к базе через `from()`, объявляйте `async` и вызывайте с `await`. Разделяйте синхронные и асинхронные функции комментарием, чтобы автор шага сразу видел, какие из них требуют Node.js.
- Обращайтесь к другим модулям внутри функций, а не на верхнем уровне тела — так исключается циклическая зависимость при инициализации.
- Не вызывайте из формул при записи движений функции, которые используют `createTable`, `format*` или `from()`.
- После правки модуля в конструкторе перезагрузите страницу приложения (F5), прежде чем проверять формулы и команды в браузере.
