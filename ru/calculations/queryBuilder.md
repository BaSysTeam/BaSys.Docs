# Построение и выполнение запросов

Для выполнения запросов к базе данных в системе **BaSYS** применяется следующий подход. Нами был разработан построитель запросов (QueryBuilder), с помощью которого формируется запрос к базе данных. Построитель создаётся с помощью функции `from()`, в которую передаётся имя таблицы, к которой будет выполнен запрос. Далее, с использованием методов построителя, производится поэтапная сборка запроса. Построитель поддерживает использование цепочки вызовов, что позволяет удобно формировать запрос. Порядок задания разных частей запроса не обязан совпадать с SQL — например, **orderBy** можно вызвать до **select**, и это не повлияет на результат. При последовательном формировании условия порядок вызовов **where**, **whereAnd** и **whereOr** имеет значение. Запрос отправляется на выполнение методом **query**.

Важно понимать, что выполнение запросов к базе данных является асинхронной операцией. Поэтому метод **query** построителя запроса возвращает объект **Promise**. Для получения результата запроса обязательно следует использовать ключевое слово **await**. 

```javascript
// Выполняется запрос к регистру currency_rates.
// Полученный результат запроса присваивается в переменную tableResult.
var tableResult = await from('register.currency_rates').query();
```

Если результатом запроса является таблица, он возвращается в виде объекта **DataTable**. После получения результата можно продолжить обработку данных с помощью методов этого объекта.

```javascript
var table_payment = 
// Выполняем запрос к таблице операции payment.
(await from("operation.payment").query())
// После получения данных продолжаем обработку методами объекта DataTable.
  .groupBy(['partner'], [{name: 'amount', alias: 'amount_p'}]);
```

## Создание построителя запроса

### **from**
Создает построитель запроса.

#### Синтаксис
```javascript
from('kindName.objectName')
```
#### Параметры
objectName - string, описание объекта к которому выполняется запрос. Используется следующий шаблон `<kindName>.<objectName>`, где kindName - имя вида объекта метаданных, objectName - имя объекта метаданных. Например: catalog.currency. 

#### Возвращаемое значение
QueryBuilder.

## Момент операции

### **moment**
Создаёт момент операции по её дате, объекту метаданных и номеру. В отличие от обычной даты, момент позволяет различать операции, относящиеся к одной секунде. Используется в методах [beforeMoment](#beforemoment), [upToMoment](#uptomoment), [fromMoment](#frommoment) и [afterMoment](#aftermoment).

#### Синтаксис
```javascript
moment(header, metaObject)
```

#### Параметры
- header: object — шапка операции с полями `date` и `number`. Поле `date` обязательно и должно содержать корректный объект `Date` или строку даты, распознаваемую `new Date(...)`.
- metaObject: string — обязательное непустое имя объекта метаданных операции, например `'operation.supply'`. Значение необходимо передавать явно.

Если `header.number` равен `undefined`, `null`, `''` или `0`, номер в моменте будет равен `null`. Такой момент обозначает новую, ещё не сохранённую операцию. Отсутствие объекта метаданных, шапки или корректной даты вызывает ошибку.

#### Возвращаемое значение
Moment — объект с полями `date` (Date), `metaObject` (string) и `number` (number, string или null). Дата копируется: последующие изменения шапки и её даты не меняют созданный момент.

#### Пример
```javascript
var header = {
  date: new Date(2026, 10, 10, 12, 30, 0),
  number: 7
};
var operationMoment = moment(header, 'operation.supply');

// operationMoment содержит дату операции, 'operation.supply' и номер 7.
return operationMoment;
```

В скрипте формы операции вместо `header` можно передать шапку `$h`: `moment($h, 'operation.supply')`.

### **select**
Задает перечень извлекаемых полей, подерживается синтаксис выражений на SQL диалекте текущей 
базы данных.

### Синтаксис
```javascript
select(selectExpressions)
```
### Параметры
selectExpressions - string[], массив имен извлекаемых полей или SQL выражений на диалекте текущей базы данных.

### Возвращаемое значение
QueryBuilder.

#### Пример
```javascript
await from("operation.supply")
// Задаем алиас period для поля date, как принято в SQL с использованием as.
  .select(["number", "date as period", "amount"])
  .query()
```

При использовании **getDisplays()** выбранное ссылочное поле автоматически дополняется колонкой `<имя поля>_display`. Если полю задан алиас, представление получает имя `<алиас>_display`. Ключевое слово `AS` распознаётся без учёта регистра: `status as state` и `status AS state` возвращают `state` и `state_display`.

### **getDisplays**
Добавляет к результату запроса отображаемые значения (представления) ссылочных полей. Значение самой ссылки сохраняется в исходной колонке, а её представление возвращается в отдельной колонке с суффиксом `_display`.

#### Синтаксис
```javascript
getDisplays()
```

#### Параметры
нет

#### Возвращаемое значение
QueryBuilder.

#### Колонки результата

- Без **select** или с `.select(['*'])` возвращаются все хранимые колонки таблицы и представления всех ссылочных полей.
- При явном выборе ссылочного поля по его имени возвращаются само поле и его представление. Например, `.select(['status'])` возвращает `status` и `status_display`, а `.select(['status AS state'])` — `state` и `state_display`.
- Поля примитивных типов и SQL-выражения, например `Count(*) as count`, не дополняются представлениями.
- Поле с префиксом физического имени таблицы в **select**, например `regr_rd_quantity.rd_code`, не дополняется представлением автоматически. Выбор `regr_rd_quantity.*` возвращает только хранимые колонки этой таблицы. Для автоматического получения представлений используйте имена полей без префикса или `*`.

Порядок колонок результата не гарантируется; обращайтесь к ним по имени.

#### Имена полей и виртуальная таблица

При **getDisplays()** сервер формирует виртуальную таблицу из хранимых колонок запрашиваемого объекта и представлений его ссылочных полей. Пользовательские выражения работают с колонками этой таблицы. Поэтому имена полей без префикса в **select**, **where**, **groupBy** и **orderBy** больше не становятся неоднозначными, если в справочниках, используемых для получения представлений, есть одноимённые колонки. Имя источника в **from()** при этом не меняется.

Существующие префиксы физических имён таблиц, например `regr_rd_quantity.rd_code`, остаются допустимыми. Алиасы внутренних соединений для получения представлений, например `cat_rd_code_rd_code.title`, больше недоступны пользовательским выражениям. Представление доступно как колонка `rd_code_display`; пример сортировки сгруппированного результата по ней приведён ниже. Использование `_display` в условиях `where` и `having` не входит в гарантируемые возможности API.

Ограничения доступа к строкам применяются к исходным данным до пользовательской обработки. Без **getDisplays()** запрос строится прежним способом, без виртуальной таблицы представлений.

#### Пример

В примере предполагается, что `rd_code` — ссылочное поле регистра `records.rd_quantity`. Условие по `rd_code` не требует префикса, даже если в связанном справочнике тоже есть колонка `rd_code`. В результате возвращаются `rd_code`, `rd_code_display` и `quantity`.

```javascript
var quantities = await from('records.rd_quantity')
  .select(['rd_code', 'quantity'])
  .where('rd_code = @rd_code')
  .parameter('rd_code', 65)
  .getDisplays()
  .top(100)
  .query();
```

## **groupBy**
Задаёт группировку данных при выполнении SQL запроса. Метод позволяет выполнять агрегирование данных по указанным полям. В методе **select** необходимо указать как поля группировки, так и агрегатные функции (например, `COUNT()`, `SUM()`, `AVG()`, `MAX()`, `MIN()`) согласно синтаксису SQL диалекта используемой базы данных.

При использовании **getDisplays()** достаточно включить в группировку само ссылочное поле. Если его представление выводится в результате, сервер автоматически добавляет соответствующую колонку `_display` в группировку. Например, для выбранного поля `status` достаточно `.groupBy('status')`. Ранее написанные запросы с `.groupBy('status, status_display')` продолжают работать и дают тот же результат; повторно представление не добавляется.

Если ссылочное поле выбрано с алиасом, в **groupBy** указывается исходное имя поля: для `.select(['status AS state', 'Count(*) as count'])` используется `.groupBy('status')`, а результат содержит `state`, `state_display` и `count`.

Для подходящих сгруппированных запросов сервер сначала выполняет агрегацию исходных данных, а затем получает представления ссылок. Выбор способа построения запроса происходит автоматически и сохраняет состав групп, значения агрегатов и представления.

### Синтаксис
```javascript
groupBy(groupByExpressions)
```
### Параметры
groupByExpressions - string или string[], имя группируемой колонки или массив имен группируемых колонок. При передаче строки можно указать несколько полей через запятую.

### Возвращаемое значение
QueryBuilder.

### Пример
Данный пример демонстрирует вычисление количества задач в разрезе статусов. Колонка `status_display` добавляется в результат и группировку автоматически. Группы сортируются по представлению статуса.
```javascript
await from('operation.task')
  .select(['status', 'Count(*) as count'])
  .groupBy('status')
  .orderBy('status_display')
  .getDisplays()
  .query();
```

#### Синтаксис

#### Параметры

#### Возвращаемое значение

#### Пример

### **top** 
Ограничивает выборку указанным числом первых элементов.

При использовании **getDisplays()** ограничение применяется к итоговым строкам после фильтрации, ограничения доступа к строкам и группировки, с учётом **orderBy**. Например, `.top(100)` возвращает до 100 строк, подходящих под условие, а в сгруппированном запросе — до 100 групп.

#### Синтаксис
```javascript
top(numberOfItems)
```
#### Параметры
numberOfItems - number, число первых элементов, включаемых в выборку.

#### Возвращаемое значение
QueryBuilder

### **where**
Задаёт условие фильтрации для построителя запроса. Поддерживается параметризация: параметры указываются через символ `@` вне зависимости от используемой базы данных. Значения параметров необходимо установить с помощью метода **parameter** объекта QueryBuilder.

Повторный вызов **where** заменяет всё ранее собранное условие, а `where('')` очищает его. Для добавления условия используйте [whereAnd](#whereand) или [whereOr](#whereor).

#### Синтаксис
```javascript
where(whereExpression)
```
#### Параметры
whereExpression - string, выражение фильтрации на диалекте SQL используемой базы данных.

#### Возвращаемое значение
QueryBuilder

#### Примеры

Фильтрация данных по условию равенства значению параметра. В примере выбираются записи курса валюты, где поле `currency` равно значению `'usd'`, переданному через параметр `@currency`.
```javascript
from("register.currency_rates")
  .where("currency = @currency")
  .parameter("currency", 'usd')
  .query()
```

Фильтрация данных по условию вхождения в массив значений. В примере извлекаются задачи, у которых поле `number` соответствует одному из значений массива `[60, 61]`, переданного через параметр `@numbers`. Оператор `in` проверяет наличие значения в указанном списке.
```javascript
var tasks = await from('operation.task')
  .where('number in @numbers')
  .parameter('numbers', [60, 61])
  .query();

return tasks;
```

### **whereAnd**
Добавляет новое условие к ранее собранному через логическое И (`AND`). Если условие ещё не задано, переданный фрагмент становится первым условием без изменения.

#### Синтаксис
```javascript
whereAnd(whereExpression)
```

#### Параметры
whereExpression - string, непустой фрагмент условия на диалекте SQL используемой базы данных. Параметры задаются через `@`, как в [where](#where).

#### Возвращаемое значение
QueryBuilder.

#### Пример
```javascript
var supplies = await from('operation.supply')
  .where('amount > @amount')
  .whereAnd('date >= @date')
  .parameter('amount', 1000)
  .parameter('date', new Date(2026, 10, 1))
  .query();

// Условие: (amount > @amount) and (date >= @date).
return supplies;
```

### **whereOr**
Добавляет новое условие к ранее собранному через логическое ИЛИ (`OR`). Если условие ещё не задано, переданный фрагмент становится первым условием без изменения.

#### Синтаксис
```javascript
whereOr(whereExpression)
```

#### Параметры
whereExpression - string, непустой фрагмент условия на диалекте SQL используемой базы данных. Параметры задаются через `@`, как в [where](#where).

#### Возвращаемое значение
QueryBuilder.

#### Пример
Выбираются операции с одним из двух номеров, сумма каждой из которых больше 1000.
```javascript
var supplies = await from('operation.supply')
  .where('number = @first')
  .whereOr('number = @second')
  .whereAnd('amount > @amount')
  .parameter('first', 60)
  .parameter('second', 61)
  .parameter('amount', 1000)
  .query();

// Условие: ((number = @first) or (number = @second)) and (amount > @amount).
return supplies;
```

#### Порядок объединения условий
Начиная с версии BaSYS.FX 1.1.0, каждый вызов **whereAnd** или **whereOr** заключает в скобки как всё накопленное условие, так и новый фрагмент. Поэтому цепочка `where('a').whereOr('b').whereAnd('c')` формирует `((a) or (b)) and (c)`, то есть `(a OR b) AND c`. Ранее получалось `a or b and c`, то есть `a OR (b AND c)` по приоритетам SQL.

При обновлении проверьте цепочки, в которых смешаны **whereAnd** и **whereOr**. Для сохранения прежнего смысла объедините нужные части в одном фрагменте: `where('a').whereOr('b AND c')`. Здесь `a`, `b` и `c` обозначают непустые SQL-условия.

Методы не проверяют синтаксис SQL и не пропускают пустые фрагменты. Передавайте непустые строки с корректными условиями; для очистки используйте `where('')`.

### **parameter**
Устанавливает значение параметра запроса.  
Если значение `dbType` не указано, система попытается определить его автоматически на основе переданного значения:

- **Дата и время** — для значений типа `date` будет задано `DbType.DateTime` (6).  
- **Логический тип** — для значений `boolean` будет задано `DbType.Boolean` (3).  
- **Числа**:  
  - если значение является **целым числом** и попадает в диапазон `[-2 147 483 648, 2 147 483 647]`, будет выбран `DbType.Int32` (11);  
  - если целое число **вне указанного диапазона**, используется `DbType.Int64` (12);  
  - если число **дробное**, будет установлен `DbType.Decimal` (7).  

Если автоматически определить `dbType` невозможно или выбранный тип не подходит для конкретного случая, параметр `dbType` следует указать явно.


#### Синтаксис
```javascript
parameter(parameterName, parameterValue, dbType)
```
#### Параметры
- parameterName - (string, обязательный). Имя параметра запроса. Задается **без** символа @.
- parameterValue - (any, обязательный). Значение параметра запроса.
- dbType - (number, опциональный). Числовые значения перечисления [System.DbType](https://learn.microsoft.com/ru-ru/dotnet/api/system.data.dbtype?view=net-8.0). Указывается в тех случаях, когда система не может определить тип параметра автоматически.

#### Возвращаемое значение
QueryBuilder

#### Примеры

Система неявно устанавливает dbType = 11 (DbType.Int32), так как передано целое число.
```javascript
await from('operation.task')
  .where('number = @number')
  .parameter('number', 1)
  .query();
```

Явно устанавливаем dbType = 7 (DbType.Decimal), чтобы указать, что мы сравниваем десятичные числа.
```javascript
await from('operation.order')
  .where('total <= @maxTotal')
  .parameter('maxTotal', 1000, 7)
  .query();
```

query()

## Границы запроса к регистру
Методы **beforeMoment**, **upToMoment**, **fromMoment** и **afterMoment** ограничивают выборку по дате или моменту операции. Они позволяют получать записи для расчёта остатков до или после операции, на начало или конец периода, а также оборотов за период.

Каждый вызов добавляет отдельную границу; ранее заданные границы сохраняются и применяются совместно. Условие **where**, параметры и фильтры запроса при этом не меняются. BaSYS.FX передаёт границы серверу в поле `boundaries`; для их применения необходима версия сервера BaSYS с поддержкой этого поля. Сервер без такой поддержки может проигнорировать границы.

### Параметры границ
Все четыре метода принимают одинаковые параметры:

- value: Date \| Moment — корректная дата или момент операции, созданный функцией [moment](#moment). Строка даты сама по себе не принимается: используйте `new Date(...)`.
- options *(необязательный)*: BoundaryOptions — объект с дополнительными параметрами границы.

**BoundaryOptions** — объект с полями:

- excludeOwn *(необязательный)*: boolean — исключать собственные записи операции. `true` и `false` передаются серверу без изменения; если параметр не указан, передаётся `null`, и значение по умолчанию выбирает сервер.
- column *(необязательный)*: string — имя другой колонки даты, по которой нужно задать границу вместо периода регистра. Допускается только вместе с `Date`; передача `column` вместе с моментом операции вызывает ошибку. Наличие и тип колонки проверяются сервером.

Дата границы передаётся в локальном времени в формате `YYYY-MM-DDTHH:mm:ss`, без часового пояса и миллисекунд. Для границы по дате поля `metaObject` и `number` равны `null`; для момента они берутся из операции. Граница по дате относится ко всей указанной секунде: **upToMoment** и **fromMoment** включают её, **beforeMoment** исключает её, а **afterMoment** начинает выборку со следующей секунды.

В следующих примерах предполагается, что `records.stock` — регистр записей с колонками `product` и `quantity`, а операция `operation.supply` создаёт записи в этом регистре. В примерах со ссылкой на `$h` код выполняется в форме этой операции.

### **beforeMoment**
Задаёт верхнюю границу выборки: строго до указанной даты или момента операции, без включения границы.

#### Синтаксис
```javascript
beforeMoment(value, options)
```

#### Параметры
value, options — см. [Параметры границ](#параметры-границ).

#### Возвращаемое значение
QueryBuilder.

#### Пример
Расчёт остатков товаров до текущей операции с явным исключением её собственных записей.
```javascript
var balances = await from('records.stock')
  .select(['product', 'Sum(quantity) as quantity'])
  .groupBy('product')
  .beforeMoment(moment($h, 'operation.supply'), { excludeOwn: true })
  .query();

return balances;
```

### **upToMoment**
Задаёт верхнюю границу выборки: до указанной даты или момента операции включительно.

#### Синтаксис
```javascript
upToMoment(value, options)
```

#### Параметры
value, options — см. [Параметры границ](#параметры-границ).

#### Возвращаемое значение
QueryBuilder.

#### Пример
Расчёт остатков товаров на конец ноября 2026 года.
```javascript
var period = new Date(2026, 10, 10);
var balances = await from('records.stock')
  .select(['product', 'Sum(quantity) as quantity'])
  .groupBy('product')
  .upToMoment(period.endMonth())
  .query();

return balances;
```

### **fromMoment**
Задаёт нижнюю границу выборки: начиная с указанной даты или момента операции включительно.

#### Синтаксис
```javascript
fromMoment(value, options)
```

#### Параметры
value, options — см. [Параметры границ](#параметры-границ).

#### Возвращаемое значение
QueryBuilder.

#### Примеры
Расчёт оборотов за ноябрь 2026 года. Нижняя и верхняя границы применяются совместно.
```javascript
var period = new Date(2026, 10, 10);
var turnover = await from('records.stock')
  .select(['product', 'Sum(quantity) as quantity'])
  .groupBy('product')
  .fromMoment(period.beginMonth())
  .upToMoment(period.endMonth())
  .query();

return turnover;
```

Границу по дате можно задать по другой колонке. В этом примере в регистре дополнительно предусмотрена колонка `delivery_date` типа «Дата и время».
```javascript
var deliveries = await from('records.stock')
  .fromMoment(new Date(2026, 10, 1), { column: 'delivery_date' })
  .query();

return deliveries;
```

### **afterMoment**
Задаёт нижнюю границу выборки: строго после указанной даты или момента операции, без включения границы.

#### Синтаксис
```javascript
afterMoment(value, options)
```

#### Параметры
value, options — см. [Параметры границ](#параметры-границ).

#### Возвращаемое значение
QueryBuilder.

#### Пример
Получение записей регистра после текущей операции с явным исключением её собственных записей.
```javascript
var laterRecords = await from('records.stock')
  .afterMoment(moment($h, 'operation.supply'), { excludeOwn: true })
  .query();

return laterRecords;
```

## Примеры

### Пример 1

Получение курса валюты из журнала currency_rates.

```javascript
(await from("register.currency_rates")
  .where("currency = @currency")
  .parameter("currency", $h.currency)
  .orderBy("period desc")
  .query()
).rows[0].rate
```

### Пример 2

Получение валюты кассы из справочника cash_box

```javascript
(await from('catalog.cash_box')
 .where('id = @id')
 .parameter('id', $h.cash_box)
 .query()
)
.rows[0].currency;
```

### Пример 3. Информация о прикрепленных файлах.

Если для объекта метаданных настроено использование прикреплённых файлов, информацию о них можно получить запросом к «виртуальной» таблице по следующему шаблону:  
`<kindName>.<objectName>.attached_files`.

В примере ниже при установке параметра **id** явно задано значение [`System.Data.DbType`](https://learn.microsoft.com/en-us/dotnet/api/system.data.dbtype?view=net-9.0) — `11` (это `DbType.Int32`), соответствующее целочисленному типу `int`.

```javascript
var filesData = await from("operation.тарифы_дорожные.attached_files")
  .select(['uid', 'filename'])
  .where("objectuid = @id")
  // 11 - System.DbType.Int32
  .parameter("id", $h.number, 11)
  .query();

return filesData;
```

### Пример 4. Запрос к табличной части.

Если `DataObject` содержит табличные части (*DetailsTables*), к ним можно обратиться, выполнив запрос к таблице вида:  
`<kindName>.<objectName>.<detailsTableName>`.

В примере ниже извлекаются все строки табличной части **время** у объекта вида **operation** с именем **ведомость**. Возвращаются только строки того объекта, у которого идентификатор равен `3`. При установке параметра **id** явно задано значение [`System.Data.DbType`](https://learn.microsoft.com/en-us/dotnet/api/system.data.dbtype?view=net-9.0) — `11` (это `DbType.Int32`), соответствующее целочисленному типу `int`.

```javascript
var tableTime = await from("operation.ведомость.время")
  .where("object_uid = @id")
  .parameter("id", 3, 11)
  .query();

return tableTime;
```
