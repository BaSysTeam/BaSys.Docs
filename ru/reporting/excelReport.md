# Отчёт на базе Excel

## Назначение

**Отчёт Excel** — вид метаданных платформы **BaSYS**, предназначенный для построения отчётов по заранее подготовленному макету в формате `.xlsx`. Макет разрабатывается в Microsoft Excel или совместимом редакторе и содержит как статическое оформление (шапки, заголовки, подписи, объединённые ячейки, форматирование), так и специальные маркеры, в которые при формировании отчёта подставляются данные из источников.

Сферы применения:

- **Регламентированная отчётность** — формы, в которых каждая ячейка является отдельным расчётом (бухгалтерская и налоговая отчётность, отраслевые формы), а оформление макета строго определено.
- **Печатные формы документов** — счета, накладные, акты, договоры, заявления, в которых требуется точное соответствие установленному образцу.
- **Сложно отформатированные сводные отчёты** — отчёты с многоуровневыми шапками, объединёнными ячейками, нестандартной разбивкой страниц, фирменной стилистикой.

Отчёт Excel рекомендуется использовать тогда, когда определяющую роль играет специфическое форматирование макета или требование точно воспроизвести заранее заданную форму. Если та же задача может быть решена через [Панель данных](dataView.md), предпочтение следует отдавать ей по соображениям производительности и простоты сопровождения: формирование файла Excel — относительно ресурсоёмкая операция (разбор шаблона, вычисление формул, сериализация).

## Архитектура и принцип работы

Формирование отчёта проходит через следующий конвейер:

1. **Загрузка метаданных.** По имени отчёта извлекаются настройки (`ExcelReportSettings`) и бинарный шаблон `.xlsx`, сохранённый в БД вместе с метаобъектом.
2. **Разбор фильтров.** Пользовательские значения фильтров приводятся к типам, согласованным с настройками в [построителе запросов](../calculations/queryBuilder.md), и передаются в источники данных через зарезервированное имя `_filters`.
3. **Последовательное вычисление источников данных.** Каждый источник представляет собой выражение на языке BaSYS (см. [библиотеку функций](../calculations/index.md)). Источники вычисляются по порядку; результат каждого помещается в контекст под именем источника и доступен последующим источникам через `_data.<имя>`.
4. **Наполнение шаблона.** Шаблон вместе со словарём данных передаётся в шаблонизатор `ExcelTemplateFiller`, построенный на библиотеке [ClosedXML.Report](https://github.com/closedxml/closedxml.report). Шаблонизатор обходит маркеры в книге, подставляет значения, разворачивает именованные диапазоны для коллекций, вычисляет формулы итогов.
5. **Сохранение результата.** Сформированная книга сериализуется в массив байтов, помещается в файловый кэш сервера и возвращается клиенту в виде идентификатора файла.
6. **Предпросмотр и выгрузка.** На клиенте файл загружается по идентификатору, разбирается собственным парсером XLSX и отображается в компоненте `BsExcelViewer`. Параллельно доступна выгрузка оригинального файла `.xlsx` для открытия в Excel.

## Состав настроек

Метаобъект **Отчёт Excel** хранит общие свойства (имя, заголовок, примечание, активность, версия), бинарный шаблон, список источников данных и список фильтров.

| Свойство      | Назначение                                                                                                       |
| :------------ | :--------------------------------------------------------------------------------------------------------------- |
| `Name`        | Системное имя отчёта. Используется в URL формы, при поиске метаданных и в API.                                   |
| `Title`       | Отображаемое название отчёта (заголовок формы).                                                                  |
| `Memo`        | Произвольное примечание для разработчика.                                                                        |
| `IsActive`    | Признак активности. Неактивные отчёты не отображаются в навигации пользователя.                                  |
| `Шаблон`      | Файл `.xlsx`, загружаемый отдельно. До загрузки шаблона построение отчёта невозможно.                            |
| `DataSources` | Упорядоченный список источников данных (см. ниже).                                                               |
| `Filters`     | Список настраиваемых фильтров (см. [Настраиваемые фильтры](filters.md)).                                         |

## Источники данных

Источник данных — именованное выражение, возвращающее значение или коллекцию значений, доступную в шаблоне под этим именем. Источники вычисляются строго в порядке их объявления, поэтому каждый последующий источник может опираться на результат предыдущего.

| Поле         | Назначение                                                                                          |
| :----------- | :-------------------------------------------------------------------------------------------------- |
| `Name`       | Имя источника. Под этим именем результат становится доступен в шаблоне и в последующих источниках.  |
| `Expression` | Выражение на языке BaSYS (`.bjs`-скрипт), возвращающее результат через `return`.                    |
| `Memo`       | Произвольное описание.                                                                              |

В выражении источника доступны следующие зарезервированные имена:

- `_filters` — массив активных значений фильтров; передаётся в [построитель запросов](../calculations/queryBuilder.md) методом `withFilters(_filters)`.
- `_data` — словарь результатов уже вычисленных источников. Доступ — `_data.<имяИсточника>`.
- `_parameters` — словарь параметров вызова (используется в более общих сценариях вычислителя).

### Пример: основной источник и итоги

Основной источник `rows` извлекает строки таблицы записей `КТУ сотрудников` за указанный период с фильтром по сотрудникам. Источник `totals` использует уже вычисленный `rows` для расчёта итогов.

```javascript
// Источник rows
var tableResult = await from('records.кту_сотрудников')
  .select(['period', 'проект_заказ as project', 'сотрудники as person', 'месяц as month', 'часы as hours'])
  .getDisplays()
  .orderBy('period desc')
  .withFilters(_filters)
  .top(100)
  .query();

return tableResult;
```

```javascript
// Источник totals
var hoursTotal = _data.rows.sum('hours');
var result = {
  hours: hoursTotal,
};

return result;
```

В шаблоне эти источники будут доступны под именами `rows` (как именованный диапазон с коллекцией строк) и `totals` (как объект, поля которого выводятся через точечную нотацию).

### Возвращаемые типы данных

Шаблонизатор корректно обрабатывает следующие типы данных:

| Тип результата                  | Доступ в шаблоне                                       | Особенности                                                                                                                  |
| :------------------------------ | :----------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------- |
| Простое значение                | `{{name}}`                                             | Строки, числа, даты, логические значения.                                                                                    |
| Объект (`Dictionary`/`Expando`) | `{{name.property}}`                                    | Значение преобразуется в полноценный CLR-тип: `ClosedXML.Report` использует рефлексию и не поддерживает динамические объекты. |
| Коллекция типизированных объектов | `{{item.Property}}` внутри именованного диапазона     | В макете создаётся именованный диапазон с тем же именем, что и источник.                                                     |
| `DataTable`                     | `{{item["ColumnName"]}}` или `{{item[index]}}`         | Передаётся как `DataRowCollection`. Также требует именованный диапазон.                                                      |

> **Замечание.** Если источник возвращает словарь (`Dictionary<string, object?>`) или `ExpandoObject`, на сервере он на лету конвертируется в полноценный CLR-тип через `System.Reflection.Emit`. Сгенерированные типы кэшируются по сигнатуре имён и типов свойств.

## Макет (шаблон Excel)

Шаблон представляет собой книгу `.xlsx`, в которой статическое содержимое (заголовки, подписи, оформление) сосуществует с маркерами шаблонизатора. При построении отчёта маркеры заменяются на данные, а оформление сохраняется как есть.

### Маркеры значений

Простые значения подставляются по имени источника:

```
{{period}}
{{totals.hours}}
```

Точечная нотация работает для свойств объектов (включая словари и `ExpandoObject`, преобразованные в типизированные объекты).

### Вывод коллекций

Для вывода табличных данных используются именованные диапазоны Excel. Имя диапазона должно совпадать с именем источника, возвращающего коллекцию. Внутри диапазона доступно зарезервированное имя `item`, через которое читаются поля текущего элемента:

- для коллекции типизированных объектов — `{{item.Property}}`;
- для `DataTable` — `{{item["ColumnName"]}}` или `{{item[<индекс колонки>]}}`.

При формировании отчёта область диапазона размножается по числу элементов коллекции.

> **Не выделяйте ячейки именованного диапазона до конца строки «про запас»** — это приводит к существенному падению производительности при размножении области (`ClosedXML.Report` обрабатывает каждую ячейку диапазона). Включайте в диапазон только реально используемые ячейки.

### Дополнительные возможности шаблонизатора

`ClosedXML.Report` поддерживает развитый язык разметки макетов: вложенные диапазоны, группировки, сортировки, агрегатные функции, условные блоки и пр. Описание полного синтаксиса и подборка примеров приведены в официальной документации:

- [ClosedXML.Report — синтаксис разметки](https://closedxml.io/ClosedXML.Report/docs/en/Markup.html);
- [Готовые примеры макетов](https://closedxml.io/ClosedXML.Report/docs/en/Examples.html).

### Итоги в макете

Библиотека предоставляет встроенный механизм для написания формул итогов (например, `<<sum>>`, `<<count>>`). При построении отчёта на их месте формируются стандартные формулы Excel вида `=SUM(...)`. Эти формулы корректно вычисляются только после открытия файла в Excel — их кэшированные значения не пересчитываются на сервере, поэтому **в предпросмотре отчёта итоги, вычисленные таким способом, не отображаются**.

Если требуется, чтобы итоги были видны в системе без выгрузки файла, рассчитывайте их на стороне источников данных и подставляйте в шаблон как обычные значения (см. пример с источником `totals` выше).

## Фильтры

Отчёт Excel поддерживает механизм настраиваемых фильтров, интегрированный с [построителем запросов](../calculations/queryBuilder.md) BaSYS. Для каждого фильтра задаются:

- системное имя и заголовок;
- тип данных и тип элемента ввода;
- предустановленный оператор сравнения и список доступных операторов;
- признак обязательности — без значения такого фильтра отчёт не построится;
- место отображения: боковая панель (Sidebar) или строка над командной панелью (Header).

Активные значения фильтров передаются в выражения источников через `_filters`. Подробное описание настройки и использования фильтров приведено в статье [Настраиваемые фильтры](filters.md).

## Построение отчёта в интерфейсе

Форма отчёта состоит из заголовка, командной панели, опциональной строки фильтров и области предпросмотра.

| Команда       | Описание                                                                                                                          |
| :------------ | :-------------------------------------------------------------------------------------------------------------------------------- |
| Сформировать  | Запускает построение отчёта на сервере. Перед запуском проверяется заполнение обязательных фильтров.                              |
| Excel         | Скачивает оригинальный файл `.xlsx` из последнего сформированного отчёта.                                                         |
| Фильтры       | Открывает боковую панель фильтров (если есть фильтры с типом отображения Sidebar).                                                 |
| Действия      | Свернуть/развернуть все группы строк и колонок; открыть журнал построения.                                                        |

Журнал построения отображает диагностические сообщения (трассировку источников данных, время построения, ошибки выражений и т.д.). Уровень детализации задаётся настройками клиента и передаётся на сервер вместе с запросом.

## Просмотр в системе. Возможности и ограничения

После построения отчёта файл `.xlsx` отображается в собственном компоненте просмотра `BsExcelViewer`. Компонент реализован на стороне клиента и разбирает книгу средствами библиотечного парсера, что позволяет показать отчёт без необходимости устанавливать или встраивать Microsoft Excel.

**Поддерживаемое оформление и функциональность:**

- шрифты (семейство, размер, цвет, начертание, подчёркивание);
- цвета заливки ячеек;
- границы ячеек (тип, цвет, толщина);
- горизонтальное и вертикальное выравнивание, перенос текста;
- числовые форматы (включая денежные, процентные и форматы с разделителями групп);
- форматирование дат;
- объединённые ячейки;
- закреплённые области (freeze panes);
- группировка строк и столбцов с возможностью сворачивания/разворачивания;
- виртуализация рендеринга — отображаются только ячейки в видимой области, что позволяет работать с большими отчётами.

**Не поддерживается в предпросмотре:**

- сводные таблицы;
- диаграммы и графики;
- условное форматирование;
- изображения;
- переключение между листами книги — в предпросмотре отображается только первый лист (при выгрузке файла все листы сохраняются);
- вычисление формул — отображаются кэшированные значения, сохранённые при формировании файла; формулы, у которых на момент сохранения отсутствует кэш (в частности, итоги, вставленные средствами `ClosedXML.Report`), показываются пустыми.

При необходимости получить полнофункциональное представление отчёта с пересчётом формул, переключением листов, диаграммами и условным форматированием — выгрузите файл по кнопке **Excel** и откройте его в Microsoft Excel либо в совместимом редакторе.

## Рекомендации по производительности

- **Предпочитайте Панель данных, если задача сводится к табличному отчёту или дашборду.** Формирование Excel-файла существенно тяжелее, чем построение Панели данных.
- **Минимизируйте размер именованных диапазонов в макете.** В диапазон должны попадать только ячейки, реально содержащие маркеры или элементы оформления. Ячейки, выделенные «про запас» до конца строки или столбца, обрабатываются построчно и серьёзно замедляют построение.
- **Считайте итоги в источниках данных, а не в шаблоне.** Помимо корректного отображения в предпросмотре, это снижает объём работы для шаблонизатора и Excel.
- **Ограничивайте объём извлекаемых данных** методами `top(N)`, фильтрами и предварительными агрегациями на уровне БД.
- **Избегайте множественного дублирования источников.** Если несколько частей отчёта используют одни и те же данные, опирайтесь в них на ранее вычисленный источник через `_data.<имя>`.
