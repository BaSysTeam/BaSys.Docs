# Настройка печатной формы

Печатные формы настраиваются в конструкторе, на отдельной закладке метаобъекта. У одного метаобъекта может быть произвольное количество печатных форм; каждая из них хранит общие свойства, вид макета, файл макета и список источников данных.

## Когда печатная форма доступна

Печатные формы можно создавать только для тех видов метаданных, у которых в настройках вида установлен флаг `UsePrintForms` (поле `UsePrintForms` в `MetaObjectKindSettings`). По умолчанию этот флаг включён для документов; для других видов метаданных (справочники, регистры и т. п.) он включается явно в настройках вида.

Если флаг снят, печатные формы для объектов соответствующего вида не строятся и не отображаются на форме объекта.

## Чем печатная форма отличается от Отчёта Excel

| Характеристика                | Печатная форма                                                          | Отчёт Excel                                                  |
| :---------------------------- | :---------------------------------------------------------------------- | :----------------------------------------------------------- |
| Привязка                      | К конкретному метаобъекту и его экземпляру                              | Самостоятельный вид метаданных, не привязан к объекту        |
| Точка вызова                  | Команда **Печать** на форме объекта                                     | Отдельная форма отчёта в навигации                           |
| Предпросмотр в системе        | Не поддерживается                                                       | Поддерживается в компоненте `BsExcelViewer`                  |
| Настраиваемые фильтры         | Не поддерживаются                                                       | Поддерживаются (см. [Настраиваемые фильтры](../filters.md))  |
| Источники данных              | Поддерживаются                                                          | Поддерживаются                                               |
| Автозагрузка данных объекта   | Поддерживается (флаг `AutoRetrieveData`)                                | Неприменимо                                                  |
| Вид макета                    | `.xlsx` (ClosedXML.Report) или `.pdf`                                   | Только `.xlsx`, ClosedXML.Report                             |

## Вид макета

Вид макета (`TemplateKind`) определяет формат файла макета, способ его разметки и формат результата печати:

| Вид макета | Файл макета | Разметка                                                                        | Результат печати                          |
| :--------- | :---------- | :------------------------------------------------------------------------------ | :---------------------------------------- |
| **Excel**  | `.xlsx`     | Маркеры и именованные диапазоны [ClosedXML.Report](https://github.com/closedxml/closedxml.report) | `.xlsx`, скачивается файлом              |
| **PDF**    | `.pdf`      | Поля PDF-формы либо текстовые метки `{{путь}}`                                  | `.pdf`, открывается в новой вкладке       |

Вид макета задаётся при создании печатной формы и в дальнейшем не изменяется: в карточке печатной формы поле доступно только для чтения, а попытка изменить его через API отклоняется. Чтобы перевести печатную форму на другой вид макета, создайте новую печатную форму. Одна печатная форма — один вид макета и один файл макета.

Для вида макета PDF дополнительно задаётся **вид разметки** (`PdfMarkupKind`) — «Поля PDF-формы» (`FormFields`) или «Текстовые метки `{{…}}`» (`TextLabels`). Значение по умолчанию — `FormFields`, рекомендуемый вид разметки; менять его можно в любой момент, но оно должно соответствовать тому, как размечен загруженный файл. Для вида макета Excel настройка не отображается и не используется. Подробнее — в статье [Макет на базе PDF](pdfTemplate.md).

## Состав настроек

| Свойство            | Назначение                                                                                                                                          |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Name`              | Системное имя печатной формы. Используется в API и при вызове команды печати.                                                                        |
| `Title`             | Отображаемое название (заголовок пункта в меню печати на форме объекта). Используется также в имени файла результата.                                |
| `Memo`              | Произвольное примечание для разработчика.                                                                                                           |
| `IsActive`          | Признак активности. Неактивные печатные формы не отображаются в меню печати.                                                                         |
| `MetaObjectUid`     | UID метаобъекта, к которому принадлежит печатная форма.                                                                                              |
| `TemplateKind`      | Вид макета: `Excel` или `Pdf`. Задаётся при создании и не изменяется.                                                                                |
| `PdfMarkupKind`     | Вид разметки PDF-макета: `FormFields` (по умолчанию) или `TextLabels`. Имеет смысл только при `TemplateKind = Pdf`.                                   |
| `Шаблон`            | Файл макета (`.xlsx` или `.pdf` — в зависимости от вида), загружаемый отдельно. До загрузки макета построение печатной формы невозможно.             |
| `AutoRetrieveData`  | Признак **Автозагрузка данных**. Если установлен, данные объекта (шапка и табличные части) попадают в контекст автоматически.                        |
| `TextTemplate`      | Резерв для видов макета, использующих текстовое представление; для Excel- и PDF-макетов не используется.                                             |
| `DataSources`       | Упорядоченный список источников данных (см. [Извлечение данных](dataRetrieval.md)).                                                                  |

## Загрузка макета

Файл макета загружается в карточке печатной формы и хранится в БД вместе с метаобъектом. При загрузке проверяются:

- **расширение** — должно соответствовать виду макета (`.xlsx` для Excel, `.pdf` для PDF); файл другого формата отклоняется с сообщением об ожидаемом расширении;
- **сигнатура файла** — содержимое действительно является книгой Excel или документом PDF;
- **размер** — не более 20 МБ;
- **для PDF** — документ должен открываться и не быть зашифрован (защищённый паролем макет отклоняется).

Разметка макета при загрузке не проверяется: ошибки разметки диагностируются при построении печатной формы (см. [Диагностика сборки](pdfTemplate.md#диагностика-сборки) для PDF-макетов).

При экспорте метаданных макет выгружается отдельным файлом рядом с описанием печатной формы — `...print_form.<имя>.template.xlsx` или `...print_form.<имя>.template.pdf`. При импорте расширение файла сверяется с видом макета, указанным в настройках.

## Как строится печатная форма

Построение выполняет сервис `PrintFormBuilder`. Подготовка данных одинакова для всех видов макета, форматом определяются только разбор макета и подстановка значений:

1. **Загрузка настроек и макета.** По UID печатной формы извлекаются настройки (`PrintFormSettings`) и бинарный файл макета. Если макет не загружен — построение завершается ошибкой.
2. **Автозагрузка данных объекта** (при `AutoRetrieveData = true`). Сервис по первичному ключу читает шапку объекта и все табличные части с разворачиванием отображаемых значений ссылок.
3. **Последовательное вычисление источников данных.** Результат каждого источника помещается в контекст под его именем и доступен последующим источникам через `_data`.
4. **Параметры объекта.** В контекст параметров (`_parameters`) передаются `kind_name`, `object_name`, `object_uid` и значение первичного ключа под его системным именем.
5. **Наполнение макета.** Контекст данных вместе с файлом макета передаётся наполнителю, выбранному по виду макета: `ExcelTemplateFiller` для `.xlsx`, `PdfTemplateFiller` для `.pdf`.
6. **Возврат результата.** Готовый файл помещается в файловый кэш сервера и возвращается клиенту в виде идентификатора вместе с именем файла и его MIME-типом.

Шаги 1–4 подробно описаны в статье [Извлечение данных](dataRetrieval.md), шаг 5 — в статьях [Макет на базе Excel](excelTemplate.md) и [Макет на базе PDF](pdfTemplate.md).

## Команда печати на форме объекта

Если для текущего вида метаданных установлен флаг `UsePrintForms` и для объекта существует хотя бы одна активная печатная форма с загруженным макетом, на форме объекта появляется команда **Печать**. По её нажатию открывается выпадающее меню со списком доступных печатных форм (отображается `Title` из настроек).

При выборе пункта меню клиент отправляет на сервер POST-запрос вида:

```
POST /api/dataObjects/print/{kind}/{name}/{uid}
{
  "formName": "<имя печатной формы>",
  "logLevel": "<уровень детализации>"
}
```

Сервер строит печатную форму, сохраняет файл во временный файловый кэш и возвращает идентификатор файла, имя файла и его MIME-тип. Диагностические сообщения сборки возвращаются вместе с ответом и попадают в журнал построения.

Команда печати работает одинаково в автоматической и в программируемой форме объекта.

## Получение результата

Способ доставки результата зависит от вида макета:

- **Excel-макет** — файл `.xlsx` скачивается на диск пользователя под именем `<Заголовок>_<дата и время>.xlsx`;
- **PDF-макет** — файл `.pdf` открывается в новой вкладке браузера во встроенном просмотрщике, откуда его можно сразу отправить на печать или сохранить. Если открыть вкладку не удалось (браузер заблокировал всплывающее окно), файл скачивается.

Предпросмотр внутри системы не поддерживается ни для одного вида макета: печатные формы предназначены для печати и отправки, а не для интерактивного анализа. Если требуется именно интерактивный просмотр результата в системе — используйте [Отчёт Excel](../excelReport.md) или [Панель данных](../dataView.md).

Ссылка на результат в кэше сервера действует ограниченное время (порядка 10 минут), поэтому повторное открытие или обновление вкладки в этот период отдаёт тот же файл, а по истечении срока печатную форму нужно построить заново.

## Рекомендации по эксплуатации

- **Используйте автозагрузку данных, где это возможно.** Это сокращает объём кода в источниках, упрощает сопровождение и снижает количество запросов к БД.
- **Ограничивайте объём извлекаемых данных** в источниках: на печать обычно выводится один объект, поэтому массовые выборки в источниках, как правило, признак ошибки. Используйте параметры `object_uid` / `<pk>` для запроса именно текущего объекта.
- **Деактивируйте устаревшие печатные формы** через флаг `IsActive` — это убирает их из меню печати, но сохраняет настройки и макет в БД.
- **Проверяйте журнал построения** после доработки макета: предупреждения об обрезке значений и неразрешённых путях к данным видны только там.
