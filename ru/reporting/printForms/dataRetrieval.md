# Извлечение данных

Данные для печатной формы извлекаются одинаково для любого вида макета: и Excel-, и PDF-макет наполняются из одного и того же **контекста данных** — набора именованных значений, которые сервер собирает перед подстановкой в макет. Разметка макета обращается к этим именам, поэтому смена вида макета не требует переделки источников данных.

Контекст наполняется из двух источников:

- **автозагрузка данных объекта** — шапка и табличные части текущего объекта, читаются платформой;
- **источники данных** — выражения на языке BaSYS, вычисляемые по порядку.

## Автозагрузка данных объекта

Если в настройках печатной формы установлен флаг **Автозагрузка данных** (`AutoRetrieveData`), для большинства типовых документов источники писать не нужно: сервер по первичному ключу читает текущий объект и наполняет контекст.

| Имя в контексте            | Содержание                                                                                                                            |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------ |
| `header`                   | Шапка объекта (`DataObject.Header`) с разрешёнными отображаемыми значениями ссылочных полей.                                           |
| `<имя_табличной_части>`    | Каждая табличная часть метаобъекта попадает в контекст под собственным именем как `DataTable` с разрешёнными отображаемыми значениями. |

Для ссылочных полей в контекст попадает отображаемое представление ссылки, поэтому в макете не требуется дополнительный запрос за наименованием контрагента, номенклатуры и т. п.

Как обратиться к этим данным в макете:

- в Excel-макете — `{{header.number}}`, `{{item["quantity"]}}` внутри именованного диапазона (см. [Макет на базе Excel](excelTemplate.md));
- в PDF-макете — метка `{{header.number}}` или поле с именем `header.number`, колонки внутри полосы — `item.quantity` (см. [Макет на базе PDF](pdfTemplate.md)).

## Источники данных

Если автозагрузки недостаточно (например, требуется подтянуть данные из связанных объектов, посчитать итоги по сложной формуле, обратиться к произвольным таблицам БД), используются **источники данных** — те же, что и в [Отчёте Excel](../excelReport.md).

| Поле         | Назначение                                                                                          |
| :----------- | :-------------------------------------------------------------------------------------------------- |
| `Name`       | Имя источника. Под этим именем результат становится доступен в макете и в последующих источниках.   |
| `Expression` | Выражение на языке BaSYS (`.bjs`-скрипт), возвращающее результат через `return`.                     |
| `Memo`       | Произвольное описание.                                                                              |

Источники вычисляются строго в порядке объявления, поэтому каждый последующий источник может опираться на результат предыдущего.

В выражениях источников доступны следующие зарезервированные имена:

- `_parameters` — словарь параметров вызова. Для печатной формы сервер автоматически добавляет:
  - `kind_name` — имя вида метаданных;
  - `object_name` — имя метаобъекта;
  - `object_uid` — значение первичного ключа объекта в типе колонки PK;
  - `<имя_первичного_ключа>` — то же значение под системным именем PK (например, `id`).
- `_data` — словарь уже наполненных данных контекста. При включённой автозагрузке здесь сразу доступны `_data.header` и `_data.<имя_табличной_части>`; кроме того, в `_data` попадают результаты ранее вычисленных источников.
- `_filters` — для совместимости с библиотекой выражений; для печатной формы фильтры не используются, передаётся пустая коллекция.

Полное описание языка выражений — в разделах [Вычисления](../../calculations/index.md) и [Построитель запросов](../../calculations/queryBuilder.md).

### Пример: вытягивание связанных данных по объекту

Пусть для документа «Реализация товаров» автозагрузка включена, но в печатной форме требуется вывести реквизиты контрагента, отсутствующие в шапке документа напрямую.

```javascript
var contractorUid = _data.header.contractor;

var rows = await from('catalogs.контрагенты')
  .select(['inn', 'kpp', 'address', 'phone'])
  .where('uid = @uid')
  .parameter('uid', contractorUid)
  .query();

return rows.first();
```

Назвав источник `contractor_details`, в макете можно использовать путь `contractor_details.inn`, `contractor_details.address` и т. п.

### Возвращаемые типы данных

| Тип результата                     | Обращение в макете                                     | Особенности                                                                                                                  |
| :--------------------------------- | :----------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------- |
| Простое значение                   | `name`                                                 | Строки, числа, даты, логические значения.                                                                                    |
| Объект (`Dictionary`/`Expando`)    | `name.property`                                        | Значение преобразуется в полноценный CLR-тип: `ClosedXML.Report` использует рефлексию и не поддерживает динамические объекты. |
| Коллекция типизированных объектов  | `item.Property` внутри области вывода коллекции        | В Excel-макете — именованный диапазон, в PDF-макете — полоса с именем источника.                                              |
| `DataTable`                        | `item["ColumnName"]` (Excel) или `item.ColumnName` (PDF) | Передаётся как `DataRowCollection`. Также требует области вывода коллекции.                                                  |

> **Замечание.** Если источник возвращает словарь (`Dictionary<string, object?>`) или `ExpandoObject`, на сервере он на лету конвертируется в полноценный CLR-тип через `System.Reflection.Emit`. Сгенерированные типы кэшируются по сигнатуре имён и типов свойств.

## Рекомендации

- **Опирайтесь на ранее вычисленные источники через `_data`**, чтобы избежать дублирования запросов, если одни и те же данные нужны в нескольких частях макета.
- **Считайте итоги в источниках данных.** Для PDF-макета это единственный способ: формул в результате нет. Для Excel-макета это гарантирует, что итоги будут видны и в просмотрщиках, не пересчитывающих формулы.
- **Не запрашивайте больше, чем нужно для одного объекта.** Используйте параметры `object_uid` / `<pk>` и ограничивайте выборки.
