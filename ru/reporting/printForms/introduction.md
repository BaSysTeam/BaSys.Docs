# Печатные формы. Введение

**Печатная форма** — элемент настройки метаобъекта в платформе **BaSYS**, предназначенный для вывода данных конкретного объекта (документа, записи справочника и т. п.) в готовый к печати файл по заранее подготовленному макету. Печатная форма не является самостоятельным видом метаданных: как и [форма](../../userInterface/index.md), она всегда принадлежит конкретному метаобъекту, у одного метаобъекта может быть несколько печатных форм. В отличие от [Отчёта Excel](../excelReport.md), печатная форма формируется в контексте конкретного экземпляра объекта — по его первичному ключу — и вызывается командой **Печать** на форме объекта.

Типичные сценарии применения:

- счета, накладные, акты, договоры, заявления и другие документы, выводимые по строго заданному образцу;
- сопроводительные печатные формы к справочникам (карточка контрагента, карточка номенклатуры и т. п.);
- унифицированные документы, для которых требуется выгрузка одного экземпляра «как есть», без агрегации по выборке.

Поддерживаются два вида макета: **Excel** (файл `.xlsx`) и **PDF** (файл `.pdf`). Вид макета задаётся при создании печатной формы и определяет только то, как размечается макет и в каком формате получается результат. Настройка самой печатной формы — общие свойства, загрузка файла макета, состав данных — от вида макета не зависит.

Подробнее о свойствах, загрузке макета и вызове печати — в статье [Настройка печатной формы](printFormSettings.md).

## Извлечение данных

Данные для печатной формы собираются одинаково для всех видов макета. Основной способ — **автозагрузка данных**: сервер по первичному ключу читает шапку объекта и все его табличные части, поэтому для типовых документов писать код не требуется. Если нужны данные из связанных объектов или расчётные значения, добавляются **источники данных** — выражения на языке BaSYS с использованием [построителя запросов](../../calculations/queryBuilder.md) и [библиотеки функций](../../calculations/index.md).

Подробнее — в статье [Извлечение данных](dataRetrieval.md).

## Макет на базе Excel

Макет представляет собой книгу `.xlsx`, размеченную маркерами библиотеки [ClosedXML.Report](https://github.com/closedxml/closedxml.report): простые маркеры значений `{{...}}`, именованные диапазоны для табличных частей, встроенные формулы итогов. Результат — файл `.xlsx`, который скачивается на диск пользователя и открывается во внешнем редакторе.

Подробнее — в статье [Макет на базе Excel](excelTemplate.md).

## Макет на базе PDF

Макет представляет собой готовый документ `.pdf`, места для значений размечаются одним из двух способов: **полями PDF-формы**, имена которых являются путями к данным, или **текстовыми метками** `{{путь}}` в содержимом страницы. Табличные части выводятся полосами с повтором строк и переносом на новые страницы. Результат — файл `.pdf`, который открывается в новой вкладке браузера во встроенном просмотрщике; готовая к печати геометрия документа не зависит от того, установлен ли у получателя Excel.

Подробнее — в статье [Макет на базе PDF](pdfTemplate.md).

## Какой вид макета выбрать

Рекомендуемый вариант — **PDF-макет с разметкой полями**: результат представляет собой законченный документ, имена полей видны и правятся в редакторе PDF, а в результате печати не остаётся ни полей ввода, ни текста меток.

Продуктивный путь получения такого макета — **конвертация существующего Excel-макета**, а не рисование PDF с нуля: платформа переносит в PDF геометрию, сетку, статичный текст, объединённые ячейки и картинки, превращает маркеры в поля, а именованные диапазоны — в полосы; автору остаётся доводка в редакторе.

Excel-макет остаётся предпочтительным, когда:

- получателю нужен именно редактируемый файл `.xlsx`;
- итоги считаются формулами Excel средствами `ClosedXML.Report`;
- макет уже существует, а требований к точному виду результата нет.

Разметка PDF текстовыми метками применяется, когда редактор не позволяет создавать поля формы: она проще в подготовке, но текст меток остаётся в содержимом результата, а фон под меткой должен быть однотонным.
