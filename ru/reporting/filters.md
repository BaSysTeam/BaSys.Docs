# Настраиваемые фильтры

Фильтры позволяют пользователю задавать условия отбора перед построением отчёта: выбрать проект, сотрудников, период или диапазон сумм. Один механизм используется в [Панелях данных](dataView.md) и [отчётах на базе Excel](excelReport.md).

Прикладной разработчик описывает фильтры на вкладке **Фильтры** метаобъекта отчёта и использует их в выражениях источников данных. Фильтр может задавать условие запроса или управлять логикой расчёта — например, выбирать разрез группировки. Само добавление фильтра в метаданные не меняет результат отчёта: источник данных должен применить его через `withFilters()` или обработать значение в скрипте.

## Настройка в конструкторе

1. Откройте метаобъект Панели данных или отчёта Excel и перейдите на вкладку **Фильтры**.
2. Добавьте фильтр, задайте его заголовок и имя.
3. Выберите тип данных и подходящий элемент управления.
4. При необходимости задайте путь к полю, по которому выполняется отбор.
5. Выберите место отображения, сравнение по умолчанию, доступные сравнения и признак обязательности.
6. Подключите фильтр в выражении источника данных и сохраните метаобъект.

### Свойства фильтра

Настройки одного фильтра описываются моделью `FilterSettingsItem`. В выгрузке метаданных они находятся в массиве `filters` отчёта.

| Свойство | Назначение |
| --- | --- |
| **Заголовок** (`title`) | Подпись фильтра в интерфейсе, например «Проект» |
| **Имя** (`name`) | Идентификатор фильтра в выражениях, например `project`. Имена фильтров одного отчёта должны быть уникальными |
| **Путь к данным** (`dataPath`) | Имя поля исходной таблицы, по которому строится условие запроса. Если не заполнено, используется `name` |
| **Тип данных** (`dataTypeUid`) | Тип вводимого значения: строка, число, логический, дата и время или ссылка на метаобъект |
| **Количество знаков** (`numberDigits`) | Максимальное количество знаков после запятой при вводе десятичного числа |
| **Элемент управления** (`controlKindUid`) | Компонент ввода значения. Список компонентов зависит от типа данных |
| **Источник элементов** (`itemsSource`) | Выражение, возвращающее допустимые значения ссылочного фильтра. Пустое выражение означает стандартный список выбранного типа данных |
| **Место отображения** (`renderPlace`) | Боковая панель (`Sidebar`, `0`) или шапка отчёта (`Header`, `1`) |
| **Сравнение по умолчанию** (`defaultComparisonKind`) | Вид сравнения при начальной настройке фильтра |
| **Доступные сравнения** (`availableComparisonKinds`) | Виды сравнения, которые разрешено выбирать пользователю |
| **Оператор соединения** (`joinOperator`) | Как условие соединяется с другими: **И** (`And`, `0`) или **ИЛИ** (`Or`, `1`). Обычно используется **И** |
| **Обязательный** (`required`) | Фильтр всегда активен; без заполненного значения построение отчёта не запускается |
| `uid` | Уникальный идентификатор фильтра. Используется для сопоставления настроек и пользовательских значений |

**Имя** и **Путь к данным** решают разные задачи. Например, фильтр с именем `report_period` может отбирать записи по полю `period`: для этого задайте `dataPath = "period"`. В скриптах к нему обращаются по имени `report_period`, а условие запроса применяется к `period`.

В `dataPath` указывайте поле исходной таблицы запроса. Псевдоним из `select()` не заменяет имя этого поля: при `select(['сотрудники as person'])` фильтр должен отбирать по `сотрудники`, а не по `person`.

### Типы данных и элементы управления

| Тип данных | Элемент управления | Значения фильтра |
| --- | --- | --- |
| Строка | Текстовое поле или многострочный ввод | Строка |
| Целое число | Ввод целого числа | Число |
| Десятичное число | Ввод числа | Число с точностью ввода `numberDigits` |
| Логический | Флажок или переключатель | `true` / `false` |
| Дата и время (`DateTime`) | Ввод даты или даты и времени | Одна дата; для «Между» — две даты |
| Дата и время (`DateTime`) | Выбор периода (`BaSYS.PeriodSelector`, компонент `BsPeriodSelector`) | Начало и конец периода |
| Ссылочный тип | Выбор ссылки | Идентификатор одной записи |
| Ссылочный тип | Множественный выбор | Массив идентификаторов в первом значении фильтра |

У ссылочного фильтра тип данных определяет, из какого справочника или перечисления выбираются значения. Например, для фильтра «Проект» из решения Construction используется тип `catalog.project`, для «Шифр РД» — `catalog.rd_code`.

### Виды сравнения

| Сравнение | Значение `ComparisonKind` | Условие |
| --- | --- | --- |
| Равно (`Equal`) | `0` | Поле равно значению |
| Не равно (`NotEqual`) | `1` | Поле не равно значению |
| Больше (`Greater`) | `2` | Поле больше значения |
| Больше или равно (`GreaterOrEqual`) | `3` | Поле больше или равно значению |
| Меньше (`Less`) | `4` | Поле меньше значения |
| Меньше или равно (`LessOrEqual`) | `5` | Поле меньше или равно значению |
| Между (`Between`) | `6` | Поле находится между двумя границами, включая границы |

Для ссылочных типов в конструкторе доступны **Равно** и **Не равно**. При выборе «Между» обычный компонент ввода показывает второе поле; `BsPeriodSelector` сам вводит обе границы.

Включайте сравнение по умолчанию в список доступных сравнений. Если в списке больше одного варианта, в боковой панели появляется переключатель сравнения. В шапке отчёта этот переключатель не отображается.

В существующих выгрузках встречается `availableComparisonKinds: []`. Такой фильтр работает с `defaultComparisonKind`, но не предлагает пользователю сменить сравнение. Для нового фильтра с фиксированным сравнением задавайте список из одного элемента, например `[0]` для равенства или `[6]` для периода.

## Работа пользователя с фильтрами

Фильтры с местом отображения **Шапка** доступны непосредственно на экране отчёта. Фильтры с местом отображения **Боковая панель** открываются кнопкой **Фильтры**. Обычно в шапку выносят часто используемые условия — проект и период, а в боковую панель помещают дополнительные отборы.

У необязательного фильтра рядом с заголовком есть флажок активности. Изменение значения автоматически включает такой фильтр. Если снять флажок, условие перестаёт применяться, хотя введённое значение может оставаться в поле. У обязательного фильтра флажка активности нет.

Для логического фильтра различайте активность условия и само значение. Активный фильтр со значением `false` может означать отбор записей, у которых поле равно `false`; выключенный фильтр означает отсутствие этого условия.

После выбора значений нажмите кнопку построения отчёта. Изменение фильтра само по себе не перестраивает данные отчёта. Перед построением платформа ждёт обновления зависимых списков и проверяет заполнение обязательных фильтров. Пустой множественный выбор также считается незаполненным.

Значения фильтров, их активность и разрешённые настройки сравнения сохраняются отдельно для каждого пользователя после успешного построения. При следующем открытии отчёта они восстанавливаются. Пункт **Стандартные настройки** в меню действий возвращает начальные настройки. Подробнее — [Пользовательские настройки форм](../userInterface/userFormPreferences.md).

## Использование в источнике данных отчёта

В выражениях источников данных значения доступны через `_filters`. Это объект, в котором ключ — имя фильтра. Для перебора можно использовать `Object.values(_filters)`.

| Обращение | Значение |
| --- | --- |
| `_filters.project` | Объект фильтра с именем `project`, если он передан в источник |
| `_filters.project.values[0]` | Первое значение: одиночное значение или список выбранных записей |
| `_filters.period.values[1]` | Второе значение: верхняя граница периода или диапазона |
| `filter.isActive` | Признак активности |
| `filter.comparisonKind` | Текущее сравнение |
| `filter.dataPath` | Поле для условия запроса; при пустом пути используется `filter.name` |
| `filter.joinOperator` | Оператор соединения условия |

В Excel-отчёте передаются активные фильтры. В Панели данных объект может содержать и неактивные фильтры, поэтому при ручной обработке проверяйте `isActive` и учитывайте возможность отсутствия фильтра.

### Применение через `withFilters()`

Метод [построителя запросов](../calculations/queryBuilder.md) `withFilters()` добавляет фильтры к запросу:

```js
return await from('records.кту_сотрудников')
  .select(['period', 'сотрудники as person', 'часы as hours'])
  .withFilters(_filters)
  .query();
```

Если настроены фильтры `period` и `сотрудники`, они применяются к одноимённым полям регистра. Неактивные фильтры не создают условий. Для обычного сравнения нужно первое значение; для `Between` — обе границы. При отсутствии нужных значений условие не добавляется.

Фильтры применяются только к тому запросу, в котором вызван `withFilters()`. Если источник выполняет несколько запросов, подключите подходящие фильтры в каждом. Если следующий источник вычисляет итоги по `_data.rows`, он использует уже отобранные строки и повторный отбор может не требоваться.

### Параметры расчёта и множественный выбор

Не каждый фильтр соответствует колонке таблицы. В Панели данных `data_view.rd_volume_balance` («Остатки объёмов РД») решения Construction используются такие настройки:

| Имя | Заголовок | Ввод | Назначение |
| --- | --- | --- | --- |
| `project` | Проект | Одиночная ссылка, обязательный | Отбор движений выбранного проекта |
| `level` | Разрез | Одиночная ссылка на `enum.work_entry_slice`, обязательный | Выбор уровня группировки |
| `rd_code` | Шифр РД | Множественный выбор | Отбор по списку шифров |
| `item_group_2` | Номенклатурная группа (Ⅱ) | Множественный выбор | Отбор по группам номенклатуры |
| `only_balance` | Только с остатком | Переключатель | Дополнительный отбор рассчитанных строк |

Все эти фильтры в выгрузке размещены в шапке. Источник передаёт в `withFilters()` только фильтр `project`. Остальные значения обрабатывает скрипт: `level` определяет колонки группировки, список шифров участвует в условии `in`, группа номенклатуры и переключатель используются при обработке таблицы результата.

Текущая реализация `withFilters()` строит скалярные сравнения и `BETWEEN`. **Множественный выбор не преобразуется автоматически в `IN`**. Для него сформируйте условие и передайте массив параметром. Ниже — сокращённый пример по мотивам источника Construction:

```js
var filters = Object.values(_filters);
var projectFilters = filters.filter(f => f.name === 'project');
var codeFilter = filters.find(f => f.name === 'rd_code' && f.isActive);
var rawCodes = codeFilter && codeFilter.values
  ? codeFilter.values[0]
  : null;

// В источнике отчёта список может прийти как массив или как текст JSON.
var codes = rawCodes == null || rawCodes === ''
  ? []
  : (typeof rawCodes === 'string' ? JSON.parse(rawCodes) : rawCodes);
codes = [].concat(codes).map(Number);

var query = from('records.rd_quantity')
  .select(['rd_code', 'quantity'])
  .withFilters(projectFilters);

if (codes.length > 0) {
  query = query
    .where('rd_code in @codes')
    .parameter('codes', codes);
}

return await query.query();
```

Здесь идентификаторы шифров — целые числа, поэтому используется `map(Number)`. Для справочника со строковым ключом или GUID такое преобразование не нужно. При обработке «Не равно» для списка используйте `not in`, учитывая `comparisonKind` выбранного фильтра.

Не передавайте параметры расчёта в запрос как отборы по колонкам, которых нет в исходной таблице. Можно выбрать нужные фильтры через `Object.values(_filters).filter(...)`, как выше, или исключить остальные по имени вторым аргументом:

```js
query.withFilters(_filters, ['level', 'rd_code', 'item_group_2', 'only_balance']);
```

## Зависимые списки: источник элементов

**Источник элементов** (`itemsSource`) ограничивает список значений ссылочного фильтра с учётом других фильтров отчёта. Например, после выбора проекта пользователю можно предложить только его шифры РД.

Это отдельное выражение в свойствах фильтра. Оно определяет, **что можно выбрать**, а выражение источника данных отчёта определяет, **какие записи попадут в результат**. Отбор данных через `withFilters()` или ручное условие нужен и при использовании зависимого списка.

Поле **Источник элементов** доступно для ссылочных типов и находится после выбора элемента управления. Выражение можно ввести непосредственно в поле или открыть редактор кнопкой с лупой. При смене типа данных на примитивный выражение очищается. Пустое выражение оставляет стандартный список выбранного типа.

### Контекст выражения

Источник элементов вычисляется асинхронно на клиенте и возвращает массив объектов `{ value, text }` либо `DataTable` с колонками `value` и `text`. `value` — идентификатор записи, `text` — её представление. В скрипте из нескольких операторов явно возвращайте результат через `return`.

| Имя в выражении | Содержимое |
| --- | --- |
| `$h` | Первые значения всех фильтров по их именам: `$h.project`, `$h.rd_code` |
| `filters` | Массив копий фильтров с полями `uid`, `name`, `title`, `isActive`, `required`, `comparisonKind`, `values` |
| `from`, `DbType` | Построитель запросов и типы параметров |
| Функции BaSYS | Функции [библиотеки вычислений](../calculations/index.md), например `isEmpty`, `isNotEmpty`, `createTable`, `format` |
| `$m` | Функции [общих модулей](../calculations/sharedModules.md) |
| `$r`, `$t` | Контекст строки и табличных частей отсутствует: `$r` равен `null`, `$t` — `undefined` |

В `$h` одиночный выбор даёт идентификатор, множественный — массив идентификаторов, период — только первую границу. Неактивный необязательный фильтр даёт `null`, даже если его прежнее значение остаётся в поле. Обязательный фильтр считается активным всегда.

Ключ `$h` — именно `name`, а не заголовок или `dataPath`. Вид сравнения в `$h` не учитывается: при «Не равно» выражение получает выбранное значение. Чтобы прочитать сравнение или вторую границу, найдите фильтр в массиве `filters`:

```js
var period = filters.find(f => f.name === 'period');
var finish = period && (period.isActive || period.required)
  ? period.values[1]
  : null;
```

Контекст включает фильтры и шапки, и боковой панели. Изменение копий `$h` или `filters` внутри выражения не изменяет пользовательский выбор. Контекст источника элементов (`$h`, `filters`) и контекст источника данных отчёта (`_filters`) используются в разных выражениях.

### Пример: шифры выбранного проекта

Возьмём фильтры `project` и `rd_code` из `data_view.rd_volume_balance`. У `project` оставьте одиночный выбор ссылки, у `rd_code` — множественный выбор. В свойство **Источник элементов** фильтра `rd_code` добавьте:

```js
var project = $h.project;
var query = from('catalog.rd_code')
  .select(['id as value', 'title as text']);

if (isNotEmpty(project)) {
  query = query
    .where('project = @project')
    .parameter('project', project, DbType.Int32);
}

return await query.query();
```

В используемой выгрузке Construction ключ `catalog.project` имеет тип целого числа, поэтому здесь задан `DbType.Int32`. Для проекта с GUID-ключом используйте `DbType.Guid`. UID типа данных в метаданных всегда является GUID, но это не означает, что идентификаторы записей тоже имеют тип GUID.

Без выбранного проекта выражение возвращает весь доступный список шифров, с проектом — только его шифры. Если выбор без проекта нужно запретить, в начале выражения верните `[]` при пустом `$h.project`.

В исходной выгрузке у этих фильтров `itemsSource` пустой. Пример показывает, как дополнить существующую настройку зависимым списком. У зависимого фильтра можно выбрать и одиночный компонент: выражение останется тем же.

### Пример: шифры нескольких проектов

Если у фильтра `project` выбран **Множественный выбор**, `$h.project` содержит массив. Используйте условие `in`:

```js
var projects = $h.project;
var query = from('catalog.rd_code')
  .select(['id as value', 'title as text']);

if (projects && projects.length > 0) {
  query = query
    .where('project in @projects')
    .parameter('projects', projects);
}

return await query.query();
```

Массив передаётся без явного `DbType`. При пустом выборе этот скрипт также возвращает весь список; при необходимости замените это поведение возвратом `[]`.

### Обновление списков и ошибки

При изменении значения, активности или сравнения любого фильтра источники элементов пересчитываются автоматически. После успешного вычисления значения, отсутствующие в новом списке, удаляются из выбора:

- при одиночном выборе недопустимое значение заменяется на `null`;
- при множественном выборе удаляются только недопустимые идентификаторы; если ничего не осталось, значение становится `[]`.

Если очистка изменила другой фильтр, обновление продолжается по цепочке зависимостей. Механизм работает и при закрытой боковой панели. Перед построением отчёт ждёт завершения всей цепочки и затем проверяет обязательные фильтры.

При открытии отчёта сначала восстанавливаются пользовательские настройки, затем вычисляются списки. Согласованные значения сохраняются, недопустимые удаляются. Действие **Стандартные настройки** также запускает пересчёт.

Если выражение или запрос завершились ошибкой, список становится пустым, но текущее выбранное значение сохраняется. Это отличается от успешного возврата `[]`, который очищает выбор. Сообщение с заголовком фильтра записывается в **Журнал** отчёта. В Панели данных журнал очищается перед построением, поэтому ошибку списка следует посмотреть до нажатия кнопки построения; в Excel-отчёте журнал перед построением не очищается.

Если запрос повторяется в нескольких отчётах, вынесите его в общий модуль. Значения фильтров передавайте аргументами: функция модуля не видит `$h` вызывающего выражения. Например:

```js
return await $m.rd_common.loadRdCodes($h.project);
```

Такой вызов требует заранее созданной асинхронной функции `loadRdCodes` в модуле `rd_common`.

## Фильтр по периоду через `BsPeriodSelector`

Частый сценарий — отчёт по движениям регистра за месяц, квартал или произвольный диапазон дат. Для него удобно использовать один фильтр с компонентом [BsPeriodSelector](../userInterface/bsPeriodSelector.md): компонент выбирает начало и конец периода и позволяет переключать периодичность.

### Настройка фильтра

В отчёте Excel `excel_report.кту_сотрудников` («КТУ Сотрудников») решения Elevator фильтр настроен так:

| Свойство | Значение |
| --- | --- |
| Имя | `period` |
| Заголовок | Период |
| Путь к данным | Пустой: используется поле `period` |
| Тип данных | Дата и время (`DateTime`) |
| Элемент управления | Выбор периода (`BaSYS.PeriodSelector`, компонент `BsPeriodSelector`) |
| Сравнение по умолчанию | Между (`Between`, `6`) |
| Место отображения | Шапка (`Header`, `1`) |
| Оператор соединения | И (`And`, `0`) |
| Обязательный | Да |

Фрагмент исходных метаданных:

```json
{
  "uid": "2ebb273e-8b10-5250-2210-1a2d90509e30",
  "name": "period",
  "dataPath": "",
  "title": "Период",
  "dataTypeUid": "9001eafb-efb1-442f-b288-723bb8002b12",
  "numberDigits": 0,
  "defaultComparisonKind": 6,
  "renderPlace": 1,
  "controlKindUid": "97cb84b8-b357-4e14-8036-28ebc3be59b8",
  "joinOperator": 0,
  "required": true,
  "availableComparisonKinds": [],
  "itemsSource": ""
}
```

Для нового фильтра укажите `availableComparisonKinds: [6]`. Выбор компонента периода сам по себе не устанавливает сравнение `Between`: его нужно задать в настройках. Если поле даты называется иначе, например `date`, заполните `dataPath = "date"`.

### Подключение к запросу

Источник `rows` в этом отчёте использует фильтры следующим образом:

```js
var tableResult = await from('records.кту_сотрудников')
  .select(['period', 'проект_заказ as project', 'сотрудники as person',
           'месяц as month', 'часы as hours'])
  .getDisplays()
  .orderBy('period desc')
  .withFilters(_filters)
  .top(100)
  .query();

return tableResult;
```

Компонент записывает начало в `values[0]`, конец — в `values[1]`. При `Between` запрос получает условие вида `period BETWEEN @начало AND @конец`. Обе границы включаются в отбор. Ограничение `.top(100)` взято из примера отчёта и независимо от фильтра ограничивает результат первыми 100 строками.

В том же отчёте есть необязательный фильтр `сотрудники` с одиночным выбором ссылки в боковой панели. Благодаря `withFilters(_filters)` он применяется вместе с периодом, когда пользователь его включает.

### Выбор периода в интерфейсе

Компонент предлагает шесть вариантов: **День**, **Месяц**, **Квартал**, **Год**, **Произвольный**, **Без ограничения**.

- Карандаш открывает список периодичностей.
- Нажатие на подпись периода открывает календарь для выбранной периодичности.
- Стрелки переключают соседние дни, месяцы, кварталы или годы.
- В режиме **Произвольный** пользователь вводит две даты; стрелки отключены.
- В режиме **Без ограничения** обе границы равны `null`, стрелки отключены, а список периодичностей открывается по нажатию на подпись.

При первом открытии без заданных дат компонент по умолчанию выбирает текущий год. Для дня, месяца, квартала, года и произвольного диапазона начало устанавливается на `00:00:00.000`, конец — на `23:59:59.999` последнего дня. Поэтому отбор включает записи за весь последний день периода.

У обязательного фильтра вариант **Без ограничения** оставляет значение пустым и не позволяет построить отчёт. Если отчёт должен допускать отсутствие ограничения по дате, сделайте период необязательным. В режиме **Произвольный** заполните обе границы: при отсутствии одной из них `withFilters()` не добавляет условие `BETWEEN`.

В стандартном фильтре отчёта компоненту передаются только границы периода. Свойства `periodKind`, `allowedPeriodKinds` и `lockPeriodKind` не настраиваются через `FilterSettingsItem`. Если требуется разрешить только месяцы или зафиксировать периодичность, такие свойства задаются при использовании `BsPeriodSelector` в [программируемом компоненте](../userInterface/programmableComponents.md); примеры приведены в [описании компонента](../userInterface/bsPeriodSelector.md).

## Проверка настройки

| Ситуация | Что проверить |
| --- | --- |
| Значение фильтра меняется, а результат остаётся прежним | Источник применяет фильтр, а отчёт построен заново после изменения значения |
| Запрос сообщает об отсутствующей колонке | `dataPath` или `name` соответствует полю исходной таблицы; параметры расчёта исключены из `withFilters()` |
| Множественный выбор не даёт нужного отбора | Массив обработан явно через `in` / `not in`, а не передан как скалярное равенство |
| Зависимый список не учитывает проект | В `itemsSource` используется `$h.<имя фильтра>`, тип параметра соответствует ключу справочника |
| После смены проекта очистился шифр РД | Прежний шифр отсутствует в новом списке; при обязательном фильтре нужно выбрать допустимое значение |
| Период не ограничивает данные | Заданы `DateTime`, `Between` и обе границы; фильтр подключён к запросу |
| Обязательный период не позволяет построить отчёт | Не выбран режим «Без ограничения», дата начала заполнена |
| Источник элементов вернул пустой список после ошибки | Откройте журнал отчёта и проверьте сообщение с заголовком фильтра |
