# Печатные формы

## Назначение

**Печатная форма** — элемент настройки метаобъекта в платформе **BaSYS**, предназначенный для вывода данных конкретного объекта (документа, записи справочника и т. п.) в готовый к печати файл по заранее подготовленному макету. Печатная форма не является самостоятельным видом метаданных: как и [форма](../userInterface/index.md), она всегда принадлежит конкретному метаобъекту, у одного метаобъекта может быть несколько печатных форм. В отличие от [Отчёта Excel](excelReport.md), печатная форма формируется в контексте конкретного экземпляра объекта — по его первичному ключу.

Типичные сценарии применения:

- счета, накладные, акты, договоры, заявления и другие документы, выводимые по строго заданному образцу;
- сопроводительные печатные формы к справочникам (карточка контрагента, карточка номенклатуры и т. п.);
- унифицированные документы, для которых требуется выгрузка одного экземпляра «как есть», без агрегации по выборке.

В настоящий момент поддерживается единственный тип шаблона — **Excel** (`PrintTemplateKinds.Excel = 0`). Архитектурно структура допускает добавление других типов шаблонов (Word, текстовые, HTML) без изменения модели метаданных, но реализованы только Excel-печатные формы на базе библиотеки [ClosedXML.Report](https://github.com/closedxml/closedxml.report).

## Когда печатная форма доступна

Печатные формы можно создавать только для тех видов метаданных, у которых в настройках вида установлен флаг `UsePrintForms` (поле `UsePrintForms` в `MetaObjectKindSettings`). По умолчанию этот флаг включён для документов; для других видов метаданных (справочники, регистры и т. п.) он включается явно в настройках вида.

Если флаг снят, печатные формы для объектов соответствующего вида не строятся и не отображаются на форме объекта.

## Чем печатная форма отличается от Отчёта Excel

| Характеристика                | Печатная форма                                                          | Отчёт Excel                                                  |
| :---------------------------- | :---------------------------------------------------------------------- | :----------------------------------------------------------- |
| Привязка                      | К конкретному метаобъекту и его экземпляру                              | Самостоятельный вид метаданных, не привязан к объекту        |
| Точка вызова                  | Команда **Печать** на форме объекта                                     | Отдельная форма отчёта в навигации                           |
| Предпросмотр в системе        | Не поддерживается, файл сразу скачивается                               | Поддерживается в компоненте `BsExcelViewer`                  |
| Настраиваемые фильтры         | Не поддерживаются                                                       | Поддерживаются (см. [Настраиваемые фильтры](filters.md))     |
| Источники данных              | Поддерживаются                                                          | Поддерживаются                                               |
| Автозагрузка данных объекта   | Поддерживается (флаг `AutoRetrieveData`)                                | Неприменимо                                                  |
| Шаблон                        | `.xlsx`, ClosedXML.Report                                               | `.xlsx`, ClosedXML.Report                                    |

Технически способ работы печатной формы тот же, что и у Отчёта Excel: данные собираются в словарь, после чего передаются в шаблонизатор `ClosedXML.Report`, который размечает книгу `.xlsx`. Преимуществом данного подхода является поддержка выражений для подсчёта итогов средствами `ClosedXML.Report`.

## Архитектура и принцип работы

Построение печатной формы выполняет сервис `ExcelPrintFormBuilder`. Конвейер построения:

1. **Загрузка настроек и шаблона.** По UID печатной формы извлекаются настройки (`PrintFormSettings`) и бинарный шаблон `.xlsx`, сохранённый в БД вместе с метаобъектом. Если шаблон не загружен — построение завершается ошибкой.
2. **Автозагрузка данных объекта (при `AutoRetrieveData = true`).** Сервис по первичному ключу объекта читает его шапку и все табличные части (с разворачиванием отображаемых значений ссылок). Шапка помещается в контекст под именем `header`, каждая табличная часть — под собственным именем (имя табличной части в метаданных).
3. **Последовательное вычисление источников данных.** Каждый источник представляет собой выражение на языке BaSYS (см. [библиотеку функций](../calculations/index.md)). Источники вычисляются по порядку; результат каждого помещается в контекст под именем источника и доступен последующим источникам через `_data.<имя>`. Все ранее наполненные данные (`header`, табличные части) также доступны через `_data`.
4. **Параметры объекта.** В контексте параметров (`_parameters`) сервис автоматически передаёт `kind_name`, `object_name`, `object_uid`, а также значение первичного ключа под его системным именем (например, `id`). Это позволяет источникам данных формировать запросы по текущему объекту, не запрашивая UID отдельно.
5. **Наполнение шаблона.** Шаблон вместе со словарём данных передаётся в шаблонизатор `ExcelTemplateFiller`, построенный на библиотеке [ClosedXML.Report](https://github.com/closedxml/closedxml.report). Шаблонизатор обходит маркеры в книге, подставляет значения, разворачивает именованные диапазоны для коллекций, вычисляет формулы итогов.
6. **Возврат результата.** Сформированная книга сериализуется в массив байтов, помещается в файловый кэш сервера и возвращается клиенту в виде идентификатора файла. На клиенте файл сразу скачивается — режим предпросмотра не предусмотрен.

## Состав настроек

Настройки печатной формы (`PrintFormSettings`) хранят общие свойства, бинарный шаблон и список источников данных. Настройки относятся к метаобъекту через поле `MetaObjectUid`; у одного метаобъекта может быть произвольное количество печатных форм.

| Свойство            | Назначение                                                                                                                                                                                          |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Name`              | Системное имя печатной формы. Используется в API и при вызове команды печати.                                                                                                                       |
| `Title`             | Отображаемое название (заголовок пункта в меню печати на форме объекта).                                                                                                                            |
| `Memo`              | Произвольное примечание для разработчика.                                                                                                                                                           |
| `IsActive`          | Признак активности. Неактивные печатные формы не отображаются в меню печати.                                                                                                                        |
| `MetaObjectUid`     | UID метаобъекта, к которому принадлежит печатная форма.                                                                                                                                             |
| `TemplateKind`      | Тип шаблона. В настоящее время — только `Excel`.                                                                                                                                                    |
| `Шаблон`            | Файл `.xlsx`, загружаемый отдельно. До загрузки шаблона построение печатной формы невозможно.                                                                                                        |
| `AutoRetrieveData`  | Признак **Автозагрузка данных**. Если установлен, данные объекта (шапка и табличные части) попадают в контекст автоматически — описывать источники не обязательно.                                  |
| `TextTemplate`      | Резерв для типов шаблонов, использующих текстовое представление (на текущем этапе не используется для Excel-форм).                                                                                  |
| `DataSources`       | Упорядоченный список источников данных (см. ниже).                                                                                                                                                  |

## Автозагрузка данных объекта

Если в настройках печатной формы установлен флаг **Автозагрузка данных** (`AutoRetrieveData`), для большинства типовых документов источники писать не нужно: сервер сам читает текущий объект и наполняет контекст.

Имена в контексте:

| Имя в шаблоне                            | Содержание                                                                                                                                          |
| :--------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| `header`                                 | Шапка объекта (`DataObject.Header`) с разрешёнными отображаемыми значениями ссылочных полей.                                                        |
| `<имя_табличной_части>`                  | Каждая табличная часть метаобъекта попадает в контекст под собственным именем как `DataTable` с разрешёнными отображаемыми значениями.              |

### Маркеры для шапки

Шапка передаётся в шаблонизатор как объект, поэтому к её полям обращаются через точечную нотацию:

```
{{header.number}}
{{header.date}}
{{header.contractor}}
```

Для ссылочных полей (например, `contractor`) подставляется отображаемое представление ссылки.

### Маркеры для табличных частей

Каждая табличная часть передаётся как `DataTable`, поэтому к её колонкам обращаются по имени колонки в квадратных скобках. Вокруг строк используется именованный диапазон Excel, имя которого совпадает с именем табличной части:

```
{{item["nomenclature"]}}
{{item["quantity"]}}
{{item["sum"]}}
```

При формировании печатной формы область диапазона размножается по числу строк табличной части. Подробности разметки именованных диапазонов — в разделе [Отчёт на базе Excel → Вывод коллекций](excelReport.md#вывод-коллекций).

## Источники данных

Если автозагрузки недостаточно (например, требуется подтянуть данные из связанных объектов, посчитать итоги по сложной формуле, обратиться к произвольным таблицам БД), используются **источники данных** — те же, что и в Отчёте Excel.

| Поле         | Назначение                                                                                          |
| :----------- | :-------------------------------------------------------------------------------------------------- |
| `Name`       | Имя источника. Под этим именем результат становится доступен в шаблоне и в последующих источниках.  |
| `Expression` | Выражение на языке BaSYS (`.bjs`-скрипт), возвращающее результат через `return`.                    |
| `Memo`       | Произвольное описание.                                                                              |

В выражениях источников доступны следующие зарезервированные имена:

- `_parameters` — словарь параметров вызова. Для печатной формы сервер автоматически добавляет:
  - `kind_name` — имя вида метаданных;
  - `object_name` — имя метаобъекта;
  - `object_uid` — значение первичного ключа объекта в типе колонки PK;
  - `<имя_первичного_ключа>` — то же значение под системным именем PK (например, `id`).
- `_data` — словарь уже наполненных данных контекста. При включённой автозагрузке здесь сразу доступны `_data.header` и `_data.<имя_табличной_части>`; кроме того, в `_data` попадают результаты ранее вычисленных источников.
- `_filters` — для совместимости с библиотекой выражений; для печатной формы фильтры не используются, передаётся пустая коллекция.

### Пример: вытягивание связанных данных по объекту

Пусть для документа «Реализация товаров» автозагрузка включена, но в печатной форме требуется вывести реквизиты контрагента, отсутствующие в шапке документа напрямую.

```javascript
var contractorUid = _data.header.contractor;

var rows = await from('catalogs.контрагенты')
  .select(['inn', 'kpp', 'address', 'phone'])
  .where('uid = @uid')
  .parameter('uid', contractorUid)
  .query();

return rows.first();
```

Назвав источник `contractor_details`, в шаблоне можно использовать маркеры `{{contractor_details.inn}}`, `{{contractor_details.address}}` и т. п.

### Возвращаемые типы данных

Шаблонизатор поддерживает те же типы данных, что и для Отчёта Excel:

| Тип результата                     | Доступ в шаблоне                                       | Особенности                                                                                                                  |
| :--------------------------------- | :----------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------- |
| Простое значение                   | `{{name}}`                                             | Строки, числа, даты, логические значения.                                                                                    |
| Объект (`Dictionary`/`Expando`)    | `{{name.property}}`                                    | Значение преобразуется в полноценный CLR-тип: `ClosedXML.Report` использует рефлексию и не поддерживает динамические объекты. |
| Коллекция типизированных объектов  | `{{item.Property}}` внутри именованного диапазона      | В макете создаётся именованный диапазон с тем же именем, что и источник.                                                     |
| `DataTable`                        | `{{item["ColumnName"]}}` или `{{item[index]}}`         | Передаётся как `DataRowCollection`. Также требует именованный диапазон.                                                      |

> **Замечание.** Если источник возвращает словарь (`Dictionary<string, object?>`) или `ExpandoObject`, на сервере он на лету конвертируется в полноценный CLR-тип через `System.Reflection.Emit`. Сгенерированные типы кэшируются по сигнатуре имён и типов свойств.

## Макет (шаблон Excel)

Шаблон представляет собой книгу `.xlsx`, в которой статическое оформление (шапки, подписи, объединённые ячейки, фирменные стили) сосуществует с маркерами шаблонизатора. При построении печатной формы маркеры заменяются на данные, а оформление сохраняется как есть.

Все возможности разметки — простые маркеры значений (`{{...}}`), именованные диапазоны для коллекций, формулы итогов (`<<sum>>`, `<<count>>`), вложенные диапазоны, условные блоки — полностью совпадают с возможностями Отчёта Excel. Подробное описание разметки и примеры — в разделах:

- [Отчёт на базе Excel → Макет (шаблон Excel)](excelReport.md#макет-шаблон-excel);
- [ClosedXML.Report — синтаксис разметки](https://closedxml.io/ClosedXML.Report/docs/en/Markup.html);
- [Готовые примеры макетов](https://closedxml.io/ClosedXML.Report/docs/en/Examples.html).

> **Не выделяйте ячейки именованного диапазона до конца строки «про запас»** — это приводит к существенному падению производительности при размножении области (`ClosedXML.Report` обрабатывает каждую ячейку диапазона). Включайте в диапазон только реально используемые ячейки.

### Особенности итогов в шаблоне

Если в шаблоне используются стандартные конструкции итогов `ClosedXML.Report` (`<<sum>>`, `<<count>>` и т. п.), они превращаются при построении в обычные формулы Excel вида `=SUM(...)`. Печатная форма не имеет режима предпросмотра в системе, поэтому, в отличие от Отчёта Excel, ограничение «итоги не отображаются в предпросмотре» здесь несущественно: файл всегда открывается во внешнем редакторе, где формулы пересчитываются автоматически.

Тем не менее, если печатная форма должна корректно отображать итоговые значения и в случаях, когда получатель открывает файл в просмотрщиках, не пересчитывающих формулы, итоги имеет смысл рассчитывать на стороне источников данных и подставлять в шаблон как обычные значения.

## Команда печати на форме объекта

Если для текущего вида метаданных установлен флаг `UsePrintForms` и для объекта существует хотя бы одна активная печатная форма с загруженным шаблоном, на форме объекта появляется команда **Печать**. По её нажатию открывается выпадающее меню со списком доступных печатных форм (отображается `Title` из настроек печатной формы).

При выборе пункта меню клиент отправляет на сервер POST-запрос вида:

```
POST /api/dataObjects/print/{kind}/{name}/{uid}
{
  "formName": "<имя печатной формы>",
  "logLevel": "<уровень детализации>"
}
```

Сервер строит печатную форму, сохраняет файл во временный файловый кэш и возвращает идентификатор файла. Клиент тут же запрашивает файл по идентификатору и инициирует его скачивание под именем, полученным от сервера.

## Просмотр и доставка результата

В отличие от Отчёта Excel, для печатной формы **не поддерживается просмотр в системе**: сформированный файл сразу скачивается на диск пользователя. Это связано с типовым сценарием — печатные формы предназначены для отправки/печати, а не для интерактивного анализа, и в большинстве случаев пользователь открывает файл во внешнем редакторе или сразу отправляет на печать.

Если требуется именно интерактивный просмотр результата в системе — следует использовать [Отчёт Excel](excelReport.md) или [Панель данных](dataView.md).

## Рекомендации по производительности и эксплуатации

- **Используйте автозагрузку данных, где это возможно.** Это сокращает объём кода в источниках, упрощает сопровождение и снижает количество запросов к БД.
- **Минимизируйте размер именованных диапазонов в макете.** В диапазон должны попадать только ячейки, реально содержащие маркеры или элементы оформления. Ячейки, выделенные «про запас» до конца строки или столбца, обрабатываются построчно и серьёзно замедляют построение.
- **Считайте итоги в источниках данных, а не средствами шаблона**, если печатная форма может открываться в просмотрщиках без пересчёта формул (предпросмотры в почтовых клиентах, мобильные просмотрщики и т. п.).
- **Ограничивайте объём извлекаемых данных** в источниках: на печать обычно выводится один объект, поэтому массовые выборки в источниках, как правило, признак ошибки. Используйте параметры `object_uid` / `<pk>` для запроса именно текущего объекта.
- **Опирайтесь на ранее вычисленные источники через `_data`**, чтобы избежать дублирования запросов, если одни и те же данные нужны в нескольких частях шаблона.
- **Деактивируйте устаревшие печатные формы** через флаг `IsActive` — это убирает их из меню печати, но сохраняет настройки и шаблон в БД.
