# Публичное API

Публичное API BaSYS — это набор REST-эндпоинтов для чтения метаданных базы (тенанта) сторонними приложениями и интеграциями. Все эндпоинты доступны под общим префиксом `/api/public/v1/` и защищены JWT-аутентификацией.

На текущий момент публичное API предоставляет доступ к метаданным в режиме чтения:

- **типы данных** — перечень доступных в платформе типов данных;
- **виды метаобъектов** — настройки видов метаобъектов (справочники, документы, регистры и т. п.);
- **метаобъекты** — конкретные метаобъекты выбранного вида и их детальные настройки.

## Базовый адрес и версионирование

Все запросы выполняются к хосту BaSYS по пути с префиксом версии:

```
https://<host>/api/public/v1/...
```

| Часть пути | Описание                                                           |
|------------|--------------------------------------------------------------------|
| `<host>`   | Адрес и порт хоста BaSYS (например, `localhost:44365`).            |
| `v1`       | Версия публичного API. При несовместимых изменениях вводится новая версия. |

> В примерах значения в угловых скобках — это плейсхолдеры, которые нужно подставить под своё окружение: `<host>` — адрес хоста BaSYS, `<access-токен>` — access-токен из ответа авторизации, `<kind>` — имя вида метаобъекта, `<uid>` — идентификатор. Реальные хосты, логины и пароли в примерах не приводятся.

## Аутентификация

Все эндпоинты публичного API требуют JWT-аутентификации по схеме `Bearer`. Перед обращением к API нужно получить access-токен, а затем передавать его в каждом запросе в заголовке `Authorization`:

```
Authorization: Bearer <access-токен>
```

Имя базы данных (тенанта) в запросах к API повторно указывать не нужно: оно берётся из claim `DbName` внутри access-токена, поэтому запрос автоматически выполняется в той базе, для которой был выпущен токен.

Полное описание получения и обновления токенов см. в разделе [Авторизация](auth.md). Если токен отсутствует, недействителен или истёк, эндпоинт возвращает `401 Unauthorized`.

## Формат ответа

Полезные данные всех эндпоинтов возвращаются в едином конверте `ResultWrapper`. Это позволяет обрабатывать ответы единообразно: сами данные находятся в поле `data`, а статус выполнения операции — в поле `status`.

```json
{
  "status": 0,
  "message": "OK",
  "technicalInfo": "",
  "data": { },
  "isOK": true,
  "presentation": "0 : OK"
}
```

| Поле            | Тип     | Описание                                                                                          |
|-----------------|---------|---------------------------------------------------------------------------------------------------|
| `status`        | int     | Прикладной код статуса (**не** HTTP-код). `0` — операция выполнена без ошибок, иное значение — ошибка. |
| `message`       | string  | Сообщение для пользователя. При успехе — `"OK"`, при ошибке — её описание.                         |
| `technicalInfo` | string  | Дополнительная техническая информация (например, стек вызова). Не предназначена для показа пользователю. |
| `data`          | object  | Полезные данные ответа. Структура зависит от конкретного эндпоинта.                                |
| `isOK`          | bool    | Признак отсутствия ошибок (`status == 0`).                                                         |
| `presentation`  | string  | Строковое представление статуса и сообщения для логирования.                                      |

> Важно различать HTTP-код и поле `status`. Запрос, прошедший аутентификацию, как правило возвращает HTTP `200 OK`, даже если при обработке возникла прикладная ошибка. В этом случае сам факт ошибки отражается в полях `status` (≠ 0) и `message`. Поэтому после успешного HTTP-ответа всегда проверяйте поле `status` (или `isOK`).

## Эндпоинты

### Типы данных

Возвращает полный список типов данных, доступных в базе: как примитивные типы (строка, число, дата и т. п.), так и ссылочные типы, связанные с видами метаобъектов.

```
GET /api/public/v1/metadata/data-types
```

Поле `data` содержит массив элементов со следующей структурой:

| Поле            | Тип     | Описание                                                                              |
|-----------------|---------|---------------------------------------------------------------------------------------|
| `uid`           | guid    | Уникальный идентификатор типа данных.                                                 |
| `kind`          | string  | Вид типа данных.                                                                      |
| `name`          | string  | Имя типа данных.                                                                      |
| `title`         | string  | Отображаемое название типа данных.                                                    |
| `isPrimitive`   | bool    | Признак примитивного типа. `true` — примитивный тип, `false` — ссылочный.             |
| `dbType`        | int     | Тип данных на уровне СУБД (`System.Data.DbType`), представленный числовым кодом.       |
| `objectKindUid` | guid?   | Идентификатор вида метаобъекта для ссылочных типов. Для примитивных типов — `null`.   |
| `typeName`      | string? | Полное имя CLR-типа для примитивных типов (например, `System.String`). Для ссылочных типов — `null`. |

Пример запроса:

```bash
curl https://<host>/api/public/v1/metadata/data-types \
  -H "Authorization: Bearer <access-токен>" \
  -H "Accept: application/json"
```

Пример ответа:

```json
{
  "status": 0,
  "message": "OK",
  "technicalInfo": "",
  "data": [
    {
      "uid": "a4f5d2c1-1111-4a3b-8c2d-000000000001",
      "kind": "Primitive",
      "name": "String",
      "title": "Строка",
      "isPrimitive": true,
      "dbType": 16,
      "objectKindUid": null,
      "typeName": "System.String"
    },
    {
      "uid": "a4f5d2c1-1111-4a3b-8c2d-000000000002",
      "kind": "Primitive",
      "name": "Int",
      "title": "Целое число",
      "isPrimitive": true,
      "dbType": 11,
      "objectKindUid": null,
      "typeName": "System.Int32"
    },
    {
      "uid": "14a60875-e241-4e99-b32d-d45b2726d18b",
      "kind": "Object",
      "name": "operation",
      "title": "Операция",
      "isPrimitive": false,
      "dbType": 11,
      "objectKindUid": "14a60875-e241-4e99-b32d-d45b2726d18b",
      "typeName": null
    }
  ],
  "isOK": true,
  "presentation": "0 : OK"
}
```

### Виды метаобъектов

Виды метаобъектов задают категории объектов метаданных (например, справочники, документы, регистры).

#### Список видов метаобъектов

Возвращает коллекцию всех видов метаобъектов базы.

```
GET /api/public/v1/metadata/meta-object-kinds
```

Поле `data` содержит массив элементов со следующей структурой:

| Поле          | Тип    | Описание                                                              |
|---------------|--------|-----------------------------------------------------------------------|
| `uid`         | guid   | Уникальный идентификатор вида метаобъекта.                            |
| `title`       | string | Отображаемое название вида.                                           |
| `name`        | string | Системное имя вида (используется в маршрутах как `<kind>`).           |
| `prefix`      | string | Префикс вида, применяемый при формировании имён таблиц и кодов.       |
| `storeData`   | bool   | Признак того, что данные вида хранятся в собственных таблицах.        |
| `isReference` | bool   | Признак ссылочного вида (на объекты вида можно ссылаться из других объектов). |
| `isStandard`  | bool   | Признак стандартного (встроенного) вида платформы.                    |
| `memo`        | string | Произвольное текстовое примечание.                                    |

Пример запроса:

```bash
curl https://<host>/api/public/v1/metadata/meta-object-kinds \
  -H "Authorization: Bearer <access-токен>" \
  -H "Accept: application/json"
```

Пример ответа:

```json
{
  "status": 0,
  "message": "OK",
  "technicalInfo": "",
  "data": [
    {
      "uid": "14a60875-e241-4e99-b32d-d45b2726d18b",
      "title": "Операции",
      "name": "operation",
      "prefix": "op",
      "storeData": true,
      "isReference": true,
      "isStandard": false,
      "memo": ""
    }
  ],
  "isOK": true,
  "presentation": "0 : OK"
}
```

#### Настройки вида метаобъекта по идентификатору

Возвращает подробные настройки конкретного вида метаобъекта.

```
GET /api/public/v1/metadata/meta-object-kinds/{uid}
```

| Параметр | Расположение | Описание                                            |
|----------|--------------|-----------------------------------------------------|
| `uid`    | маршрут      | Уникальный идентификатор вида метаобъекта (GUID).   |

Поле `data` содержит объект настроек вида. Основные поля:

| Поле                 | Тип     | Описание                                                              |
|----------------------|---------|-----------------------------------------------------------------------|
| `uid`                | guid    | Идентификатор вида метаобъекта.                                       |
| `title`              | string  | Отображаемое название вида.                                           |
| `name`               | string  | Системное имя вида.                                                   |
| `prefix`             | string  | Префикс вида.                                                         |
| `storeData`          | bool    | Признак хранения данных вида.                                         |
| `isReference`        | bool    | Признак ссылочного вида.                                              |
| `allowAttachedFiles` | bool    | Разрешено ли прикреплять файлы к объектам вида.                       |
| `canCreateRecords`   | bool    | Может ли вид формировать записи в регистрах.                          |
| `useDetailsTables`   | bool    | Используются ли табличные части.                                      |
| `useForms`           | bool    | Используются ли формы.                                               |
| `usePrintForms`      | bool    | Используются ли печатные формы.                                       |
| `saveHistory`        | bool    | Сохраняется ли история изменений.                                    |
| `isStandard`         | bool    | Признак стандартного вида платформы.                                  |
| `version`            | long    | Версия настроек.                                                      |
| `memo`               | string  | Текстовое примечание.                                                 |
| `iconClass`          | string  | CSS-класс иконки вида.                                                |
| `orderByExpression`  | string  | Выражение сортировки по умолчанию.                                    |
| `displayExpression`  | string  | Выражение формирования отображаемого представления объектов.          |
| `standardColumns`    | array   | Стандартные колонки вида.                                             |
| `availableRights`    | array   | Идентификаторы доступных прав.                                        |

Пример запроса:

```bash
curl https://<host>/api/public/v1/metadata/meta-object-kinds/<uid> \
  -H "Authorization: Bearer <access-токен>" \
  -H "Accept: application/json"
```

Пример ответа (часть полей опущена):

```json
{
  "status": 0,
  "message": "OK",
  "technicalInfo": "",
  "data": {
    "uid": "14a60875-e241-4e99-b32d-d45b2726d18b",
    "title": "Операции",
    "name": "operation",
    "prefix": "op",
    "storeData": true,
    "isReference": true,
    "allowAttachedFiles": false,
    "canCreateRecords": true,
    "useDetailsTables": true,
    "useForms": true,
    "usePrintForms": false,
    "saveHistory": false,
    "isStandard": false,
    "version": 1,
    "memo": "",
    "iconClass": "pi pi-cog",
    "orderByExpression": "",
    "displayExpression": "",
    "standardColumns": [],
    "availableRights": []

  "isOK": true,
  "presentation": "0 : OK"

```

### Метаобъекты

Метаобъекты — это конкретные объекты метаданных определённого вида (например, конкретный справочник или документ).

#### Список метаобъектов вида

Возвращает список метаобъектов указанного вида.

```
GET /api/public/v1/metadata/meta-objects/{kind}
```

| Параметр | Расположение | Описание                                                        |
|----------|--------------|-----------------------------------------------------------------|
| `kind`   | маршрут      | Системное имя вида метаобъекта (поле `name` из видов метаобъектов). |

Поле `data` содержит объект со структурой списка:

| Поле               | Тип    | Описание                                              |
|--------------------|--------|-------------------------------------------------------|
| `metaObjectKindUid`| guid   | Идентификатор вида метаобъекта.                       |
| `storeData`        | bool   | Признак хранения данных вида.                         |
| `saveHistory`      | bool   | Признак сохранения истории изменений.                 |
| `title`            | string | Отображаемое название вида.                           |
| `items`            | array  | Массив метаобъектов вида.                             |

Каждый элемент массива `items` имеет структуру:

| Поле       | Тип    | Описание                                       |
|------------|--------|------------------------------------------------|
| `uid`      | guid   | Идентификатор метаобъекта.                     |
| `kindUid`  | guid   | Идентификатор вида, к которому относится объект.|
| `title`    | string | Отображаемое название метаобъекта.             |
| `name`     | string | Системное имя метаобъекта.                     |
| `memo`     | string | Текстовое примечание.                          |
| `isActive` | bool   | Признак активности метаобъекта.                |
| `version`  | long   | Версия метаобъекта.                            |

Пример запроса:

```bash
curl https://<host>/api/public/v1/metadata/meta-objects/<kind> \
  -H "Authorization: Bearer <access-токен>" \
  -H "Accept: application/json"
```

Пример ответа:

```json
{
  "status": 0,
  "message": "OK",
  "technicalInfo": "",
  "data": {
    "metaObjectKindUid": "14a60875-e241-4e99-b32d-d45b2726d18b",
    "storeData": true,
    "saveHistory": false,
    "title": "Операции",
    "items": [
      {
        "uid": "a30177b3-bf29-4e3d-9215-9a1a5e2fcfdb",
        "kindUid": "14a60875-e241-4e99-b32d-d45b2726d18b",
        "title": "Приходная операция",
        "name": "incoming",
        "memo": "",
        "isActive": true,
        "version": 3
      }
    ]
  },
  "isOK": true,
  "presentation": "0 : OK"
}
```

Поле `data` содержит объект настроек метаобъекта. Основные поля:

| Поле                  | Тип    | Описание                                                      |

| `name`                | string | Системное имя метаобъекта.                                   |
| `title`               | string | Отображаемое название метаобъекта.                           |

| `displayExpression`   | string | Выражение формирования отображаемого представления.          |

| `itemFormUid`         | string | Идентификатор формы элемента.                                |

## Обработка ошибок

Публичное API использует комбинацию HTTP-кодов и прикладного поля `status`:

| Уровень     | Признак                  | Как обрабатывать                                                                 |
|-------------|--------------------------|----------------------------------------------------------------------------------|
| HTTP `401`  | Unauthorized             | Токен отсутствует, недействителен или истёк. Обновите access-токен через refresh и повторите запрос (см. [Авторизация](auth.md)). |
| HTTP `200` + `status = 0`  | Успех     | Данные находятся в поле `data`.                                                  |
| HTTP `200` + `status ≠ 0`  | Прикладная ошибка | Запрос обработан, но операция завершилась ошибкой. Причина — в поле `message`, технические детали — в `technicalInfo`. Например, не найден вид метаобъекта или метаобъект по указанному имени/идентификатору. |

> Рекомендация: после успешного HTTP-ответа всегда проверяйте поле `status` (или `isOK`) и только затем используйте `data`.
