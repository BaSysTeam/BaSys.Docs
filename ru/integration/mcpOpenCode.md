# Подключение MCP-сервера BaSYS к OpenCode

Эта статья демонстрирует, как подключить встроенный [MCP-сервер BaSYS](mcp.md) к [OpenCode](https://opencode.ai) — терминальному ИИ-агенту, — чтобы он мог читать метаданные базы и импортировать их обратно прямо из проекта.

OpenCode обнаруживает MCP-серверы по файлу конфигурации `opencode.json`. Однако MCP-сервер BaSYS защищён JWT-аутентификацией (см. [Авторизация](auth.md)): каждый запрос требует заголовка `Authorization: Bearer <access-токен>`, а сам токен короткоживущий (по умолчанию 1 час) и периодически обновляется. Статичный заголовок в конфигурации для этого не подходит — он «протухнет» вместе с токеном.

Чтобы решить эту задачу, между OpenCode и BaSYS ставится небольшой локальный **прокси** (Node.js-скрипт). OpenCode запускает его как локальный (stdio) MCP-сервер; при старте прокси получает access-токен, обновляет его перед истечением и при ответе `401`, а сами MCP-вызовы транслирует на HTTP-эндпоинт `/mcp` BaSYS.

```
OpenCode  ──stdio (JSON-RPC)──►  mcp-proxy.js  ──HTTPS + Bearer──►  BaSYS /mcp
```

Готовый прокси и шаблоны настроек уже опубликованы в репозитории [BaSYS.AI.KIT](https://github.com/BaSysTeam/BaSYS.AI.KIT) — писать скрипт вручную не нужно. Достаточно скопировать каталог `.opencode` в свой проект и заполнить учётные данные.

## Готовый набор файлов

Все нужные файлы лежат в каталоге [`dist/.opencode`](https://github.com/BaSysTeam/BaSYS.AI.KIT/tree/main/dist/.opencode) репозитория BaSYS.AI.KIT и размещаются в каталоге `.opencode` в корне вашего проекта:

| Файл                              | Назначение                                                                 |
|-----------------------------------|----------------------------------------------------------------------------|
| [`opencode.json`](https://github.com/BaSysTeam/BaSYS.AI.KIT/blob/main/dist/.opencode/opencode.json)          | Регистрация MCP-сервера в OpenCode (запуск прокси).                        |
| [`mcp-proxy.js`](https://github.com/BaSysTeam/BaSYS.AI.KIT/blob/main/dist/.opencode/mcp-proxy.js)            | Прокси stdio→HTTPS: авторизация, обновление токена и проброс запросов.     |
| [`basys-credentials.example.json`](https://github.com/BaSysTeam/BaSYS.AI.KIT/blob/main/dist/.opencode/basys-credentials.example.json) | Образец файла учётных данных (без реальных секретов).               |
| `basys-credentials.json`          | Ваши учётные данные подключения к BaSYS. **Не коммитится** в репозиторий (его создаёте вы). |
| [`.gitignore`](https://github.com/BaSysTeam/BaSYS.AI.KIT/blob/main/dist/.opencode/.gitignore)              | Уже исключает `basys-credentials.json` из системы контроля версий.        |

> Помимо файлов для MCP, в `dist/.opencode` репозитория есть подготовленный каталог `skills` — навыки для ИИ-агента BaSYS. Он не обязателен для работы MCP, но его можно скопировать в проект вместе с остальными файлами.

> Для работы прокси требуется установленный [Node.js](https://nodejs.org) (LTS-версия). Проверить наличие можно командой `node --version`.

## Шаг 1. Скопируйте файлы в проект

Получите содержимое каталога `dist/.opencode` из репозитория любым удобным способом и положите его в каталог `.opencode` в корне вашего проекта. Например, склонируйте репозиторий и скопируйте каталог:

```bash
git clone https://github.com/BaSysTeam/BaSYS.AI.KIT.git
cp -r BaSYS.AI.KIT/dist/.opencode ./.opencode
```

Либо скачайте файлы по отдельности со страницы [`dist/.opencode`](https://github.com/BaSysTeam/BaSYS.AI.KIT/tree/main/dist/.opencode) и поместите их в каталог `.opencode` своего проекта.

Минимально необходимый набор для подключения MCP: `opencode.json`, `mcp-proxy.js`, `basys-credentials.example.json` и `.gitignore`.

## Шаг 2. Заполните учётные данные

Прокси умеет получать учётные данные двумя способами — из файла или из переменных окружения. Достаточно настроить любой из них.

### Вариант A. Файл учётных данных

Скопируйте образец `basys-credentials.example.json` в файл `basys-credentials.json` и подставьте значения своего окружения вместо плейсхолдеров:

```json
{
  "url"     : "https://<host>:<port>",
  "dbName"  : "<dbName>",
  "login"   : "<login>",
  "password": "<password>"
}
```

| Поле       | Описание                                                                 |
|------------|--------------------------------------------------------------------------|
| `url`      | Базовый адрес хоста BaSYS (схема и хост, при необходимости порт). Порт указывается, только если хост слушает нестандартный порт, например локальный dev-хост `https://localhost:44365`; для публичных адресов он обычно не нужен — `https://test.thebasys.com`. Без завершающего слеша и без пути. |
| `dbName`   | Имя базы данных (тенанта), к которой подключается агент.                  |
| `login`    | Логин пользователя (email).                                              |
| `password` | Пароль пользователя.                                                     |

Файл `basys-credentials.json` содержит секреты и **не должен попадать** в систему контроля версий. В наборе из репозитория уже есть `.opencode/.gitignore`, который его исключает:

```gitignore
basys-credentials.json
```

### Вариант Б. Переменные окружения

Если файл учётных данных не создан, прокси читает значения из переменных окружения. Задайте их перед запуском OpenCode:

| Переменная       | Соответствует полю |
|------------------|--------------------|
| `BASYS_URL`      | `url`              |
| `BASYS_DB_NAME`  | `dbName`           |
| `BASYS_LOGIN`    | `login`            |
| `BASYS_PASSWORD` | `password`         |

Прокси сначала ищет `basys-credentials.json`, и только если файла нет — берёт переменные окружения. Этот вариант удобен в CI и других окружениях, где секреты задаются через переменные, а не файлы.

> Прокси отправляет логин и пароль на эндпоинт авторизации только при получении нового токена и далее работает по короткоживущему access-токену. Подробнее о схеме аутентификации см. [Авторизация](auth.md).

## Шаг 3. Как зарегистрирован сервер в OpenCode

Регистрацию выполнять вручную не нужно — файл `.opencode/opencode.json` из набора уже указывает OpenCode запускать прокси как локальный (stdio) MCP-сервер:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "basys-mcp": {
      "type": "local",
      "command": ["node", ".opencode/mcp-proxy.js"],
      "enabled": true
    }
  }
}
```

| Поле        | Описание                                                                 |
|-------------|--------------------------------------------------------------------------|
| `basys-mcp` | Имя сервера, под которым он отображается в OpenCode (можно изменить).     |
| `type`      | Тип сервера — `local`: OpenCode запускает процесс и общается с ним по stdio. |
| `command`   | Команда запуска: исполняемый файл `node` и путь к скрипту прокси относительно корня проекта. |
| `enabled`   | Признак активности сервера. Чтобы временно отключить его, задайте `false`. |

## Шаг 4. Проверка подключения

1. Перезапустите OpenCode (или откройте проект заново), чтобы он перечитал `opencode.json`.
2. Убедитесь, что сервер `basys-mcp` запустился и его инструменты доступны агенту. Список подключённых MCP-серверов можно посмотреть командой `/mcp` в интерфейсе OpenCode.
3. Среди инструментов должны появиться `validate_metadata` и `import_metadata`, а среди ресурсов — `data_types`, `meta_object_kinds` и `meta_object_kind_by_uid` (см. описание в статье [MCP-сервер](mcp.md)).
4. Попросите агента, например, «выведи список видов метаобъектов» — он обратится к ресурсу MCP и вернёт данные из вашей базы.

Если сервер не запустился, диагностические сообщения прокси (с префиксом `[basys-mcp-proxy]`) выводятся в `stderr` и видны в журнале OpenCode.

## Как работает прокси

Исходный код прокси находится в файле [`mcp-proxy.js`](https://github.com/BaSysTeam/BaSYS.AI.KIT/blob/main/dist/.opencode/mcp-proxy.js). Скрипт не содержит секретов — все учётные данные он читает из `basys-credentials.json` либо из переменных окружения. Логика работы:

- **Запуск.** При старте прокси читает учётные данные и сразу запрашивает access-токен, чтобы не задерживать первый запрос агента.
- **Проброс вызовов.** Каждое JSON-RPC сообщение от OpenCode (одна строка из stdin) транслируется `POST`-запросом на `<url>/mcp` с заголовком `Authorization: Bearer <access-токен>` и `Accept: application/json, text/event-stream`. Ответ (обычный JSON или поток SSE) разбирается и возвращается в stdout.
- **Обновление токена.** Перед каждым вызовом прокси проверяет срок жизни токена и обновляет его за 60 секунд до истечения. Если сервер всё же вернул `401`, прокси сбрасывает токен, получает новый и **один раз** повторяет запрос.

Прокси использует упрощённую модель: он получает новый токен по логину и паролю и не задействует refresh-токен. Это допустимо для локального инструмента разработчика; в более строгих сценариях логику можно расширить обменом refresh-токена (см. [Авторизация](auth.md)).

> В прокси параметр `rejectUnauthorized: false` отключает проверку TLS-сертификата и нужен только для работы с локальным dev-хостом, использующим самоподписанный сертификат. На стенде с доверенным сертификатом этот параметр следует убрать.

## Безопасность

- **Не коммитьте `basys-credentials.json`.** Файл содержит логин и пароль — держите его вне системы контроля версий (за это уже отвечает `.opencode/.gitignore`), а в репозитории оставляйте только образец `basys-credentials.example.json` с плейсхолдерами.
- **Используйте HTTPS.** На рабочих стендах подключайтесь по HTTPS к доверенному сертификату и убирайте из прокси `rejectUnauthorized: false`.
- **Ограничивайте права пользователя.** Для подключения используйте учётную запись с минимально необходимыми правами на работу с метаданными базы.

## Возможные проблемы

| Симптом                                              | Причина и решение                                                                 |
|------------------------------------------------------|-----------------------------------------------------------------------------------|
| Сервер не появился в списке MCP в OpenCode           | Проверьте, что установлен Node.js (`node --version`) и путь в `command` указан верно. |
| `Credentials file not found`                         | Не создан `.opencode/basys-credentials.json` и не заданы переменные окружения. Скопируйте образец и заполните значения либо задайте `BASYS_*`. |
| `Authentication failed (401)`                        | Неверные `login`/`password` или `dbName`. Проверьте учётные данные (см. [Авторизация](auth.md)). |
| Ошибки TLS / сертификата                             | Самоподписанный сертификат dev-хоста. Для локальной разработки в прокси оставлен `rejectUnauthorized: false`. |
| Агент не видит инструменты или ресурсы               | Перезапустите OpenCode, чтобы он перечитал `opencode.json`, и проверьте журнал MCP. |
