# Пользовательские настройки форм

Пользовательские настройки форм — это личное состояние экрана конкретного пользователя, которое платформа запоминает и восстанавливает при следующем открытии того же экрана тем же пользователем. Фильтры списка, сортировка, размер страницы, значения фильтров отчёта — всё это сохраняется автоматически, без действий со стороны пользователя.

Механизм не следует путать с двумя другими сущностями:

- **Настройки метаданных** (конструктор форм, настройки объекта метаданных) — это конфигурация приложения. Она общая для всех пользователей, входит в выгрузку метаданных и переносится между контурами. Пользовательские настройки форм не входят в выгрузку и не переносятся.
- **Бизнес-данные** — хранятся в объектах метаданных. Пользовательские настройки форм не предназначены для хранения идентификаторов документов, сумм, статусов и любых других данных предметной области.

Запись всегда принадлежит одному пользователю. Идентификатор пользователя подставляет сервер; прочитать или перезаписать настройки другого пользователя невозможно.

## Как это работает

Одна запись адресуется тремя составляющими:

- **вид цели** — класс экрана (список объектов, Excel-отчёт, панель данных, программируемая форма и т. д.);
- **идентификатор цели** — стабильный uid объекта метаданных, отчёта, представления или формы;
- **подключ** — уточнение внутри одного экрана (например, имя вложенной таблицы). У основной записи экрана подключ пустой.

Адресация идёт по идентификаторам, а не по отображаемым именам, поэтому переименование объекта, колонки или фильтра не приводит к потере сохранённых настроек.

Восстановление выполняется **поэлементно**. Если колонка удалена из формы, фильтр удалён из отчёта или у поля изменился тип данных, платформа отбрасывает только этот элемент, а остальную часть настроек применяет. Целиком запись отбрасывается лишь в двух случаях: содержимое не удалось разобрать или запись создана более новой версией клиентского приложения.

Механизм спроектирован так, чтобы не мешать работе. Недоступный сервер, испорченная запись, ошибка применения — любой сбой означает, что экран открывается на значениях по умолчанию. Экран остаётся полностью работоспособным.

## Где механизм работает

| Экран | Что запоминается | Когда сохраняется |
| --- | --- | --- |
| Список объектов метаданных (автоматическая форма) | Фильтры колонок, поле и направление сортировки, размер страницы | Автоматически, через 1 секунду после изменения, а также при закрытии экрана |
| Список объектов метаданных (форма конструктора) | То же, плюс отдельно состояние каждой вложенной таблицы | Автоматически, аналогично автоматической форме |
| [Отчёт на бланке Excel](../reporting/excelReport.md) | Значения фильтров | После успешного построения отчёта |
| [Панель данных](../reporting/dataView.md) | Значения фильтров | После успешного построения |
| Список метаобъектов в конструкторе | Фильтры и сортировка (отдельная запись на каждый вид метаданных) | Автоматически |
| Списки пользователей, групп пользователей и RLS-разделителей в администрировании | Фильтры | Автоматически |
| Программируемая форма | Произвольные данные, которые определяет прикладной разработчик | Только по явному вызову из скрипта формы |

Список объектов метаданных адресуется идентификатором самого объекта, а не формы. Поэтому если для объекта настроена форма списка в конструкторе и она затем заменена на автоматическую (или наоборот), сохранённые настройки не теряются: применяется та их часть, которая подходит новой форме.

Вложенные таблицы формы списка, собранной в конструкторе, хранятся отдельными записями — по одной на каждую таблицу. Состояние основного списка и состояние вложенных таблиц независимы.

## Что нужно учитывать

**Отчёты сохраняют фильтры только по факту построения.** Это осознанное поведение, и у него три следствия:

- изменение фильтров без нажатия кнопки построения не сохраняется;
- неуспешное построение (ошибка запроса, пустой обязательный параметр) не сохраняется;
- сохраняется набор фильтров на момент построения, а не последний введённый.

**Не запоминаются:**

- порядок, ширина и видимость колонок списков;
- номер текущей страницы и выделенная строка;
- состав выводимых полей отчёта и уровень протоколирования — это параметры запуска, а не настройки экрана.

## Сброс к значениям по умолчанию

Во всех перечисленных выше платформенных экранах в меню действий есть пункт **Стандартные настройки**. Он удаляет сохранённую запись и немедленно приводит экран к значениям по умолчанию, без перезагрузки страницы.

Диалога подтверждения нет: действие неразрушительно, а результат мгновенно воспроизводится заново. Успешный сброс подтверждается сообщением «Восстановлены стандартные настройки». Сообщение выводится и в том случае, когда сохранённой записи не было — экран в любом случае приведён к значениям по умолчанию.

После сброса автосохранение остаётся включённым: следующее же изменение фильтра создаст запись заново. Это ожидаемое поведение.

В формах списка, собранных в конструкторе, пункт меню добавляет разработчик формы — командой `standard.reset_preferences` в обработчике `@Click` (см. раздел «Команды» в статье [Конструктор форм](formConstructor.md)):

```json
{
  "id": "pv-split-button-item-reset-preferences",
  "componentName": "pv-split-button-item",
  "properties": [
    { "name": "label", "value": "Стандартные настройки" },
    { "name": "icon", "value": "pi pi-cog" },
    { "name": "@Click", "value": "standard.reset_preferences" }
  ]
}
```

> Команда сбрасывает настройки основного списка формы. Настройки вложенных таблиц при этом сохраняются — их нужно сбрасывать по отдельности, если такая необходимость возникает.

В программируемых формах платформа никаких пунктов меню не добавляет и сообщений не показывает: интерфейс сброса пишет прикладной разработчик (см. ниже).

## Границы механизма

- **Размер одной записи — не более 64 КБ.** Проверка выполняется и на клиенте, и на сервере. Превышение означает, что запись не сохранена; экран продолжает работать. Запас здесь большой: снимок фильтров и сортировки списка занимает сотни байт, набор фильтров отчёта — единицы килобайт. Упереться в лимит можно практически только одним способом — положив в запись данные вместо состояния экрана (результат запроса, таблицу, содержимое файла).
- **Формат хранилища версионируется.** Если запись создана более новой версией клиентского приложения, она не применяется, а автосохранение для этого экрана отключается до его закрытия. Так исключается ситуация, когда старая вкладка затирает настройки, записанные новой версией.
- **Параллельные вкладки:** побеждает последняя запись. Разрешения конфликтов в интерфейсе нет — настройки формы не являются бизнес-данными.
- **Диагностика:** неявные операции молчат, явные сообщают о результате. Сбой чтения и сбой автосохранения пользователю не показываются и пишутся в журнал событий. Сбой сброса показывается сообщением об ошибке, поскольку пользователь нажал кнопку и ждёт результата.
- Настройки удаляются вместе с объектом метаданных, представлением, отчётом или формой, к которым относятся.
- Именованные наборы настроек (пресеты), общие и ролевые настройки, а также сброс всех настроек пользователя одним действием не поддерживаются.

## Использование в программируемых формах

Программируемая форма получает собственное пространство хранения и работает с ним напрямую: платформа не знает, что в данных формы считать изменением, поэтому автосохранения здесь нет. **Не вызвали функцию сохранения — ничего не сохранилось.**

### Доступные функции

В [скрипт-контекст](programmableComponents.md#скрипт-контекст-глобальные-функции) программируемой формы внедряются три асинхронные функции. Они доступны по имени, без импорта и без объявления в `inject`:

```ts
loadFormPreferences(subKey?: string): Promise<Record<string, unknown> | null>
saveFormPreferences(payload: Record<string, unknown>, subKey?: string): Promise<boolean>
resetFormPreferences(subKey?: string): Promise<boolean>
```

| Функция | Возвращает | Примечание |
| --- | --- | --- |
| `loadFormPreferences` | Сохранённый объект или `null` | `null` означает и «записи ещё нет», и «прочитать не удалось». Реакция в обоих случаях одна: работать на значениях по умолчанию. |
| `saveFormPreferences` | `true` при успехе, `false` при отказе | Запись выполняется сразу, без задержки. Отказ — это превышение лимита 64 КБ или недоступность сервера. |
| `resetFormPreferences` | `true` при успехе, `false` при отказе | Удаляет запись. Значения полей формы функция не меняет — их сбрасывает скрипт. |

Цель записи подставляет платформа: вид цели «программируемая форма» плюс идентификатор текущей формы. Обратиться к настройкам другого экрана, другой формы или другого пользователя через эти функции невозможно.

Функции доступны во всех трёх режимах открытия программируемой формы: как форма объекта, как форма списка объектов и как модальный диалог, открытый через `openDialog`.

Ошибки не показываются пользователю автоматически. Если сообщение нужно — выводит его скрипт формы.

### Полный пример

Ниже — форма, запоминающая выбранные пользователем проект и сотрудника. Загрузка выполняется в `mounted`, сохранение и очистка — по кнопкам, сообщения о результате выводит сама форма.

```html
<script>
export default {
  props: ['title'],
  data() {
    return {
      isWaiting: false,
      projectId: null,
      employeeId: null,
      projectDataType: 'a9c75bdf-d854-4f05-9a6a-1db90d2ae59b',
      employeeDataType: 'c47d3835-48d8-427f-be89-e84c082575ef',
    };
  },
  async mounted() {
    this.isWaiting = true;
    const saved = await loadFormPreferences();
    this.isWaiting = false;

    if (saved && saved.version === 1) {
      this.projectId = saved.projectId ?? this.projectId;
      this.employeeId = saved.employeeId ?? this.employeeId;
    }
  },
  methods: {
    async onSaveClick() {
      this.isWaiting = true;
      const ok = await saveFormPreferences({
        version: 1,
        projectId: this.projectId,
        employeeId: this.employeeId,
      });
      this.isWaiting = false;

      if (!ok) {
        this.$toast.add({
          severity: 'error',
          summary: 'Не удалось сохранить пользовательские настройки',
        });
        return;
      }

      this.$toast.add({
        severity: 'success',
        summary: 'Пользовательские настройки сохранены',
      });
    },
    async onResetClick() {
      this.isWaiting = true;
      const ok = await resetFormPreferences();
      this.isWaiting = false;

      if (!ok) {
        this.$toast.add({
          severity: 'error',
          summary: 'Не удалось очистить пользовательские настройки',
        });
        return;
      }

      this.projectId = null;
      this.employeeId = null;
    },
  },
}
</script>

<template>
<div class="grid">
  <div class="col">
    <BsViewTitle :title="title" :isWaiting="isWaiting"></BsViewTitle>
  </div>
</div>

<div class="grid">
  <div class="col">
    <Button label="Сохранить пользовательские настройки"
      size="small"
      severity="success"
      icon="pi pi-save"
      outlined
      @click="onSaveClick"></Button>
    <Button label="Очистить пользовательские настройки"
      class="ml-1"
      size="small"
      severity="secondary"
      icon="pi pi-filter-slash"
      outlined
      @click="onResetClick"></Button>
  </div>
</div>

<div class="grid align-items-center">
  <div class="col-12 md:col-3">
    <label for="project">Проект/Заказ</label>
  </div>
  <div class="col-12 md:col-9">
    <BsObjectReferenceSelect
      id="project"
      :data-type="projectDataType"
      v-model="projectId"
      :showClear="true"
      class="w-full"></BsObjectReferenceSelect>
  </div>
</div>

<div class="grid align-items-center">
  <div class="col-12 md:col-3">
    <label for="employee">Сотрудник</label>
  </div>
  <div class="col-12 md:col-9">
    <BsObjectReferenceSelect
      id="employee"
      :data-type="employeeDataType"
      v-model="employeeId"
      :showClear="true"
      class="w-full"></BsObjectReferenceSelect>
  </div>
</div>
</template>
```

Сохранение не обязано быть привязано к кнопке. Его можно вызывать из `watch`, из обработчика закрытия диалога или перед выполнением длительной операции — платформа не накладывает ограничений на момент вызова. Стоит лишь учитывать, что каждый вызов — это обращение к серверу, поэтому сохранять на каждое нажатие клавиши в текстовом поле не следует.

### Подключ `subKey`

`subKey` — необязательный параметр каждой из трёх функций, а не свойство формы. Он позволяет одной форме держать несколько независимых записей:

```js
const listState = await loadFormPreferences('list');
const chartState = await loadFormPreferences('chart');
```

Вызов без параметра равносилен пустому подключу — это основная запись формы. Записи с разными подключами полностью независимы: `loadFormPreferences('v2')` не увидит данные, сохранённые вызовом `saveFormPreferences(payload)`. Если подключ в форме меняется, предусмотрите чтение старого ключа или примите потерю ранее сохранённых настроек.

### Версионирование данных формы

Платформа не разбирает содержимое сохранённого объекта и не версионирует его. Версионирование формата хранилища, упомянутое в разделе «Границы механизма», к полям внутри объекта отношения не имеет.

Несовместимое изменение структуры обрабатывает сама форма — полем версии внутри объекта:

```js
const saved = await loadFormPreferences();

if (saved) {
  if (saved.version === 2) {
    this.applyV2(saved);
  } else if (saved.version === 1) {
    this.applyV1(saved);
  }
}
```

Без такой проверки форма новой версии применит данные, записанные старой, и может получить неожиданные значения. Проверка версии — самый простой способ этого избежать: неизвестная версия просто игнорируется, и форма открывается на значениях по умолчанию.

### Рекомендации

- Сохраняйте только то, что пользователь выбрал сам: значения фильтров, выбранную вкладку, режим отображения, свёрнутость групп.
- Не сохраняйте загруженные данные: результаты запросов, таблицы, содержимое файлов, изображения. Это и превышение лимита 64 КБ, и устаревающие данные.
- Не сохраняйте бизнес-данные и ссылки на них как источник истины — для этого существуют объекты метаданных.
- Всегда кладите в объект поле версии и проверяйте его при загрузке.
- Считайте, что загрузка может вернуть `null` в любой момент: форма обязана корректно открываться на значениях по умолчанию.
- Не блокируйте отрисовку формы ожиданием загрузки настроек — используйте индикатор ожидания, как в примере выше.
- Если форме нужна кнопка сброса, добавьте её сами и не забудьте после `resetFormPreferences` вернуть поля формы к значениям по умолчанию.
