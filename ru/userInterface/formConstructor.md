# Конструктор форм

В **BaSYS** доступен визуальный конструктор форм. Принцип работы конструктора следующий: пользователь в визуальном редакторе добавляет компоненты, задаёт им свойства, привязки данных и обработчики событий. Полученная структура формы сохраняется в JSON и при открытии формы рендерится при помощи [Render-функции Vue.js](https://vuejs.org/guide/extras/render-function.html).

Конструктор предназначен для случаев, когда автоматических форм недостаточно, но и полноценный программируемый компонент избыточен. Технически он представляет собой декларативное описание дерева Vue-компонентов, поэтому большинство возможностей **Vue 3** и **PrimeVue 3** (двусторонние привязки, условный рендеринг, события, именованные слоты) доступны прямо из визуального редактора без написания шаблонов.

## Принцип работы

Каждая форма-конструктор хранится в метаданных как объект `ConstructorFormSettings`. Его центральное поле — `Root`, корневой `FormElement`. `FormElement` — узел дерева, описывающий один элемент верстки и содержащий:

- `id` — идентификатор элемента в пределах формы (используется для выделения, перемещения, привязки к свойству `ref` и т. д.);
- `componentName` — имя компонента (см. перечень ниже, например `bs-form`, `bs-row`, `bs-col`, `pv-button`, `bs-form-field`);
- `dataUid` — UID связанного поля метаданных (заполняется для полей шапки и колонок таблиц);
- `cssClass` и `style` — CSS-класс и inline-стиль;
- `properties` — список пар «имя свойства — значение» (props, события, привязки);
- `items` — дочерние элементы.

При открытии формы клиентское приложение получает дерево `Root` и рекурсивно строит виртуальное DOM-дерево функцией `renderComponentTree`. Для каждого узла:

1. По `componentName` выбирается реализация из реестра `componentRegistry`. Узлы-обёртки `bs-form`, `bs-row`, `bs-col` рендерятся как обычные `<div>`.
2. Формируется объект `props` Vue-компонента. В него попадают `id`, `class`, `style` и все элементы `properties`, кроме служебных (`v-if`, `vModel`, `v-bind`, привязки `:foo`, события `@event`).
3. Раскрываются привязки (двусторонние, односторонние, событийные) — см. раздел [Привязки данных и события](#привязки-данных-и-события).
4. Рекурсивно рендерятся `items`. Если у дочерних элементов задано свойство `slot`, они группируются по слотам и передаются как named slots (это используется, например, в `pv-toolbar`).
5. Полученный VNode возвращается родителю.

В режиме визуального редактора используется отдельный обход `renderConstructorComponentTree` — он не выполняет привязки, добавляет служебные классы (`bs-constructor-row`, `bs-constructor-col`, `bs-selected`) и подменяет таблицы их «конструкторскими» версиями (`bs-details-table-constructor`, `bs-table-view-constructor`), которые умеют редактировать набор колонок и реагировать на клики мышью.

Такое разделение позволяет редактировать форму и сразу видеть её предварительный результат, не дублируя описание компонентов.

## Структура верстки

Верстка основана на CSS-фреймворке [PrimeFlex](https://primeflex.org/). Используется 12-колоночная сетка, задаваемая данным фреймворком. Для размещения компонентов сначала необходимо задать [сетку](https://primeflex.org/gridsystem) из строк (row) и колонок (column) PrimeFlex. И в созданной сетке размещать доступные компоненты.

В терминах конструктора используется фиксированная иерархия обёрток:

| Обёртка | Назначение | Допустимые потомки |
| --- | --- | --- |
| `bs-form` | Корневой контейнер формы (всегда `Root`). Рендерится как `<div>`. | `bs-row` |
| `bs-row` | Строка PrimeFlex-сетки (рекомендуется CSS-класс `grid`). | `bs-col` |
| `bs-col` | Колонка PrimeFlex-сетки (CSS-классы `col`, `col-2`, `col-6` и т. д.). | Любые компоненты из реестра |

Допустимость перемещения элементов между обёртками контролируется методом `move` класса `ConstructorFormSettings` — например, колонку нельзя перемещать в произвольное место, а строка может быть размещена внутри `bs-form` или внутри сворачиваемой группы `bs-collapsible-group`.

Внутри одной колонки можно размещать как простые компоненты (кнопки, поля ввода, текст), так и составные — группы кнопок (`pv-button-group`), поле формы с подписью (`bs-form-field`), сворачиваемые группы (`bs-collapsible-group`), вкладки (`pv-tab-view`/`pv-tab-panel`), таблицы и т. п.

## Доступные компоненты

В конструкторе доступно использование компонентов из библиотеки [PrimeVue 3](https://v3.primevue.org/) и собственных компонентов **BaSYS**. Помимо собственных свойств компонента компоненту могут быть заданы `cssClass` и `style`. Это сильно расширяет возможности кастомизации. При кастомизации преимущество следует отдавать свойствам компонента, затем CSS-классам [PrimeFlex](https://primeflex.org/) и в последнюю очередь стилям.

Полный перечень компонентов задаётся реестром `componentRegistry` и перечислением `ConstructorComponents`. Подробное описание каждого компонента (props, события, слоты) приводится в отдельных статьях.

### Пример кастомизации компонента

В качестве примера рассмотрим кастомизацию кнопки `pv-button`. Для изменения цвета лучше отдавать предпочтение свойству компонента `severity` (`primary`, `secondary`, `success`, `info`, `warning`, `danger`). Если нужно задать левый отступ, то можно применить класс `ml-1`. Inline-стиль уместен только тогда, когда нужное свойство нельзя выразить ни props, ни классами PrimeFlex/PrimeVue — например, чтобы зафиксировать минимальную ширину кнопки в пикселях независимо от темы:

```json
{
  "ComponentName": "pv-button",
  "CssClass": "ml-1",
  "Style": "min-width: 180px;",
  "Properties": [
    { "Name": "label", "Value": "Сохранить" },
    { "Name": "icon", "Value": "pi pi-save" },
    { "Name": "severity", "Value": "primary" },
    { "Name": "size", "Value": "small" },
    { "Name": "outlined", "Value": "outlined" },
    { "Name": "@Click", "Value": "standard.save" }
  ]
}
```

## Привязки данных и события

Состояние формы доступно компонентам как реактивный объект `formState`. Конструктор поддерживает несколько видов свойств, имитирующих синтаксис Vue.

### Сокращения путей

В выражениях привязок можно использовать следующие сокращения:

| Сокращение | Раскрывается в | Смысл |
| --- | --- | --- |
| `$h.<имя>` | `data.header.<имя>` | Поле шапки документа/справочника. |
| `$t.<имя>` | `data.tables.<имя>` | Табличная часть с указанным именем. |
| `$r.<имя>` | `data.currentRow.<имя>` | Поле текущей строки таблицы. |

### Виды свойств

| Вид | Синтаксис в `Name` | Описание |
| --- | --- | --- |
| Обычный prop | `propName` | Передаётся в компонент как есть. |
| Двусторонняя привязка | `vModel` | Значение свойства — выражение пути (например, `$h.date`). Конструктор сам подписывает `onUpdate:modelValue`. |
| Привязка одиночного prop | `:propName` или `v-bind:propName` | Значение трактуется как JS-выражение в контексте `formState`. Поддерживаются обращения к полям, литералы шаблонных строк и вызовы `formatter.*` (например, `` `${data.header.number} от ${formatter.formatDateTime(data.header.date)}` ``). |
| Привязка всего объекта props | `v-bind` или `:` | Значение — путь к объекту, поля которого мержатся в props компонента. |
| Условный рендеринг | `v-if` (`vIf`) | Выражение, вычисляется в контексте `formState`. Если результат ложный, компонент и его поддерево не рендерятся. |
| Обработчик события | `@EventName` | Значение — имя команды (см. ниже). Конструктор регистрирует соответствующий `on<EventName>`. |
| Слот | `slot` | Имя слота родительского компонента, в который рендерится текущий элемент. |

### Команды

В обработчиках событий и в пунктах `pv-split-button-item` указывается имя команды формата `группа.имя[:параметр]`. Имена резолвятся через объект `handlers`, передаваемый рендереру. Часть команд — стандартные (`standard.save`, `standard.save_close`, `standard.return`, `standard.add`, `standard.edit`, `standard.delete`, `standard.refresh`, `standard.clear_filters`, `standard.export_excel`, `standard.print`, `standard.open_records`, `standard.open_files`, `standard.create_from`, `standard.create_records`, `standard.delete_records`, `standard.row_select`, `standard.row_dbl_click`, `standard.table_add` и др.) — реализованы платформой. Остальные команды разработчик задаёт на стороне объекта метаданных (см. поле `Commands` в настройках объекта и команды формата `custom_save`, `approve_start` и т. п.).

Параметр после двоеточия (например, `standard.refresh:list` или `standard.table_add:монтаж_площадка`) обычно указывает таблицу или режим, к которым применяется команда.

### Скрипт инициализации

В `ConstructorFormSettings.onInitializedScript` можно задать JavaScript-код, который выполняется один раз после загрузки формы. Он используется, например, для предзаполнения данных, подписки на изменения или открытия диалогов в зависимости от контекста.

## Быстрое создание формы списка и формы редактирования

При решении практических задач наиболее часто приходится создавать формы списка и формы редактирования. Эти формы можно создать последовательно добавляя необходимые элементы. Однако в **BaSYS** предусмотрен более быстрый вариант создания данных форм при помощи специализированных помощников. Принцип работы помощников следующий: помощники анализируют структуру метаданных и создают список или форму редактирования согласно этой структуре. Созданные формы не будут идеальны, но дорабатывать созданные автоматом формы существенно проще, чем разрабатывать с нуля.

Серверная часть помощников расположена в `BaSys.Constructor/FormBuilders`:

- `ListFormBuilder` — собирает форму списка. В неё включается заголовок (`bs-view-title`), стандартная группа кнопок «Добавить/Редактировать/Удалить» (`pv-button-group`), дополнительные кнопки («Копировать», «Записи», `pv-split-button` «Действия» с пунктами «Обновить», «Очистить фильтры», «Excel» и при необходимости «Создать/Удалить записи»), разделитель и таблица `bs-table-view` с колонками, построенными `TableViewBuilder` по выбранным полям объекта.
- `EditFormBuilder` — собирает форму редактирования. В неё включается строка заголовка, строка кнопок (`Вернуться`, `Сохранить&Закрыть`, `Сохранить`, при необходимости «Создать на основании», «Записи», «Файлы», `pv-split-button` «Печать» и `pv-split-button` «Действия» с пунктами «Журнал расчётов», «Пересчитать», «Создать/Удалить записи», «Excel» и командами объекта), разделитель, поля шапки (в виде сетки колонок или внутри сворачиваемой группы) и при наличии табличных частей — вкладки `pv-tab-view`/`pv-tab-panel` с таблицей `bs-details-table` и собственной панелью команд для каждой табличной части.

Для формы редактирования предусмотрены несколько настроек, объединённых в `EditFormConstructorRequest`:

| Свойство | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `HeaderColumnsCount` | `3` | Количество колонок при размещении полей шапки в сетке. |
| `UseCollapsibleGroup` | `true` | Размещать поля шапки внутри сворачиваемой группы (`bs-collapsible-group`). |
| `Header.Columns` | — | Какие поля шапки включить в форму. |
| `DetailTables` | — | Какие табличные части и их колонки включить в форму, а также какие команды объекта добавить в панель действий. |

Тип элемента ввода для каждого поля определяется автоматически по типу данных (см. `EditFormBuilder.AddFormField` и `DetailsTableBuilder`): bool → `pv-checkbox` или `pv-input-switch`, число → `pv-input-number`, дата → `pv-calendar`, строка → `pv-input-text`, объектная ссылка → `bs-object-reference-select`. Виртуальные поля получают свойство `disabled`, обязательные — `required`. Для каждого поля автоматически проставляется `vModel` вида `$h.<имя>` (для шапки) либо `$r.<имя>` (для строк таблицы), что синхронизирует значение поля с моделью формы.
