# Пользовательский интерфейс

Система **BaSYS** поддерживает следующие способов создания пользовательских интерфейсов:

- **Автоматические формы** — формы, автоматически генерируемые на основе метаданных.  
  Позволяют работать с данными без программирования. Используют фреймворк [Vue.js 3](https://vuejs.org/) и 
библиотеку компонентов [PrimeVue 3](https://v3.primevue.org/setup/).

- **Программируемые компоненты** — интерфейсы, разрабатываемые вручную с использованием **Vue.js 3** и **PrimeVue 3**.  
  Предназначены для случаев, когда требуется более гибкая логика или нестандартное поведение.

- **Конструктор форм** *(в разработке)* — визуальный редактор для создания пользовательских интерфейсов без написания кода.  
  Позволяет создавать формы и компоненты в интерактивном режиме.

- **UI-плагины** *(в разработке)* — отдельные frontend-приложения, интегрируемые в систему BaSYS.  
  Плагины могут быть реализованы на любом фреймворке. При регистрации плагину выделяется собственный сегмент URL, 
по которому он доступен в системе.

- **Внешние приложения** *(в разработке)* — автономные frontend-приложения, созданные с использованием любых технологий.  
  Взаимодействуют с BaSYS через внешнее API.


## Рекомендации по созданию пользовательских интерфейсов

Разработка пользовательских интерфейсов, особенно сложных, требует значительных усилий. 
Интерфейс — это та часть системы, к которой пользователи предъявляют наибольшие требования.
Другими словами, при разработке интерфейсов легко «утонуть» в деталях и потратить чрезмерно много времени 
в ущерб другим задачам.

Исходя из нашего опыта, мы рекомендуем придерживаться следующих принципов при разработке пользовательских интерфейсов:

- **Максимально используйте автоматические формы**.  
  Они позволяют быстро создавать интерфейсы для работы с данными и не требуют программирования.  
  Во многих случаях автоматических форм достаточно для решения пользовательских задач.

- **Если автоматические формы не подходят, используйте конструктор форм**.  
  Он позволяет эффективно создавать более сложные интерфейсы без программирования.

- **Программируемые компоненты используйте только при необходимости**.  
  Такие компоненты требуют больше усилий на разработку и поддержку по сравнению с автоматическими формами и формами, 
созданными в конструкторе. Используйте их только тогда, когда другие подходы не позволяют реализовать требуемую функциональность.

Применяя принцип Парето к данной задаче, мы рекомендуем следующее распределение подходов к созданию интерфейсов:

- **Около 70% интерфейсов** следует реализовывать с использованием **автоматических форм**.
- **Примерно 15%** — с помощью **конструктора форм**.
- **Не более 5%** — с применением **программируемых компонентов**.

Такой подход позволяет достигать оптимального соотношения между скоростью разработки, 
удобством сопровождения и гибкостью решений.

> ⚠️ **Важно**: Полное построение интерфейса с использованием только программируемых компонентов — крайне неудачное решение. 
> Если автоматические формы и конструктор форм не удовлетворяют требованиям, и требуется создание уникального интерфейса, рекомендуется переходить к **UI-плагинам** или **внешним приложениям**.

UI-плагины и внешние приложения разрабатываются в полноценных IDE и обеспечивают максимальную гибкость при создании интерфейсов. 
Если необходимо реализовать действительно сложные пользовательские сценарии, предпочтение следует отдавать этим технологиям.

Идеально, если решение о подходе к реализации интерфейсов и выборе инструментов принимается на этапе проектирования системы.
