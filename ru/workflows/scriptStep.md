# Скрипт (JavaScript)

Шаг **Скрипт** (`java_script`) выполняет JavaScript-код в контексте запущенного процесса. Его используют в тех случаях, когда требуется описать прикладную логику, которую невозможно выразить другими стандартными шагами: рассчитать значения, подготовить таблицу для последующей загрузки данных, объединить результаты нескольких шагов, выполнить запрос к данным или сформировать объект для дальнейшей обработки.

В JSON-описании процесса код шага задаётся в параметре `Expression`. В экспортированных процессах значение `Expression` указывает на `.bjs`-файл, в котором хранится текст скрипта, например `workflow.create_task.step.data.bjs`.

## Контекст выполнения

Внутри скрипта доступны служебные объекты:

- `_parameters` — параметры процесса, переданные при запуске workflow.
- `_data` — результаты уже выполненных шагов процесса. Ключом выступает техническое имя шага (`Name`).

К параметрам и данным шагов можно обращаться через точечную нотацию:

```javascript
var documentNumber = _parameters.number;
var previousRows = _data.load_data.rows;
```

Если имя параметра или шага не является корректным JavaScript-идентификатором, используйте квадратные скобки:

```javascript
var value = _parameters['parameter-name'];
var stepData = _data['load data'];
```

Результаты предыдущих шагов передаются в скрипт как данные для чтения и преобразования. Изменение объекта из `_data` не переписывает результат исходного шага. Если преобразованные данные должны быть доступны дальше по процессу, их необходимо вернуть из текущего скрипта.

## Результат шага

Значение, возвращённое скриптом, сохраняется как результат текущего шага и становится доступно последующим шагам через `_data.<имя_шага>`.

Рекомендуется завершать скрипт явным `return`, чтобы результат был очевиден при чтении процесса:

```javascript
var tableData = createTable([
  'author number',
  'responsible number',
  'status',
  'topic',
  'date'
]);

tableData.addRow([
  _parameters.author,
  _parameters.responsible,
  _parameters.status,
  _parameters.topic,
  (new Date()).toLocalISO()
]);

return tableData;
```

Если результат шага используется, например, в загрузчике данных, в настройках следующего шага обычно указывается имя текущего шага как источник данных.

## Синхронные и асинхронные скрипты

Шаг поддерживает два режима выполнения:

- Если код не содержит `await`, скрипт выполняется встроенным V8-движком ClearScript. Этот режим подходит для синхронных вычислений и преобразования уже доступных данных.
- Если код содержит `await`, скрипт выполняется через Node.js. Этот режим используется для асинхронных операций, прежде всего для запросов к данным через построитель запросов BaSYS.

Пример асинхронного запроса:

```javascript
var resultTable = await from('operation.проект_договора')
  .select(['number', 'date', 'представление as display', 'статус as status'])
  .getDisplays()
  .where('number = @number')
  .parameter('number', _parameters.number)
  .query();

return resultTable;
```

Пример с группировкой и агрегацией:

```javascript
var tableResult = await from('operation.task')
  .select(['status', 'Count(*) as count'])
  .groupBy('status, status_display')
  .having('Count(*) > 10')
  .getDisplays()
  .query();

return tableResult;
```

Результат одного запроса можно использовать как параметр для другого:

```javascript
var tasksArray = (await from('register.task_message')
  .where('has_read = false').query()).toArray('task');

var tasks = await from('operation.task')
  .select(['number', 'date', 'topic', 'status'])
  .where('number in @numbers')
  .parameter('numbers', tasksArray)
  .query();

return tasks;
```

Для передачи значений в условия запроса следует использовать `.parameter(...)`, а не подставлять значения в строку вручную. Это упрощает экранирование, делает выражение устойчивее к ошибкам формата и сохраняет единый стиль построителя запросов.

## BaSYS.Fx

В скрипте доступны функции библиотеки **BaSYS.Fx**. Они добавляются в глобальный контекст выполнения, поэтому их можно вызывать напрямую.

### createTable

Создаёт табличный результат для последующих шагов. Принимает массив описаний колонок в одном из двух форматов:

```javascript
// Строковый формат: 'имя тип' (тип можно опустить)
var table = createTable(['author number', 'responsible number', 'status', 'topic', 'date']);

// Объектный формат
var table = createTable([
  {name: 'period'},
  {name: 'document', dataType: 'number'},
  {name: 'status'}
]);
```

### Методы табличных данных

Результат `createTable(...)` и данные, полученные из запросов, являются экземплярами класса `DataTable`. Полное описание доступных методов (`addRow`, `filter`, `leftJoin`, `groupBy`, `clone` и др.) приведено в статье [Работа с табличными данными](../calculations/dataTable.md).

### Построитель запросов

`from(expression)` — создаёт построитель запросов к данным BaSYS. Доступен только в асинхронных скриптах (выполняемых через Node.js). Полное описание методов цепочки (`select`, `where`, `parameter`, `orderBy`, `top`, `groupBy`, `getDisplays`, `query` и др.) приведено в статье [Построение и выполнение запросов](../calculations/queryBuilder.md).

Пример обработки результата предыдущего шага:

```javascript
var messages = _data.persons
  .leftJoin(_data.document, (personRow, documentRow) => true)
  .filter(row => row.status == 'у_директора' && row.email);

return messages;
```

## Ограничения

Процессы и их шаги выполняются на сервере. Поэтому в скриптах не следует использовать функции и объекты браузерного интерфейса, такие как `alert()`, `window` или `document`: у серверного процесса нет пользовательского окна и DOM.

Скрипт должен выполнять ограниченную прикладную операцию и возвращать результат для следующих шагов. Длительные вычисления, бесконечные циклы и неявные внешние зависимости усложняют диагностику процесса и могут негативно повлиять на выполнение других серверных задач.
