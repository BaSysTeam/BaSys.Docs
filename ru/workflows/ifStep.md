# Условие (If)

Шаг **Условие** (`if`) вычисляет JavaScript-выражение и направляет выполнение процесса по одной из двух ветвей в зависимости от результата. Это основной механизм ветвления: с его помощью можно пропустить шаги, которые не нужны при определённых входных данных, или выбрать между альтернативными сценариями обработки.

## Как работает шаг

1. Выражение из параметра `Condition` вычисляется встроенным движком ClearScript (V8).
2. Если результат — логическое значение `true`, выполнение переходит к шагу, указанному в `TrueStepUid`.
3. Если результат — `false`, выполнение переходит к шагу, указанному в `FalseStepUid`.
4. Если соответствующий параметр (`TrueStepUid` или `FalseStepUid`) не задан, ветвь считается пустой и выполнение продолжается в обычном порядке.
5. Если результат выражения не является булевым значением, он интерпретируется как `false`, а в лог записывается ошибка.

## Контекст выражения

Внутри выражения доступны те же объекты, что и в шаге «Скрипт»:

- `_parameters` — параметры процесса, переданные при запуске workflow.
- `_data` — результаты уже выполненных шагов. Ключом выступает техническое имя шага (`Name`).

Примеры обращений:

```javascript
_parameters.sendMail == true
```

```javascript
_data.messages != null
```

```javascript
_data.load_data.rows.length > 0
```

## Настройки

### Condition

Строка с JavaScript-выражением, которое должно вернуть `true` или `false`. Выражение вычисляется синхронно движком ClearScript. Поддерживаются стандартные операторы сравнения (`==`, `!=`, `>`, `<`, `>=`, `<=`), логические операторы (`&&`, `||`, `!`) и обращение к параметрам и данным шагов.

### TrueStepUid

`Guid` шага, к которому перейдёт выполнение, если условие истинно. Значение — `Uid` целевого шага в описании процесса. Если параметр не задан (пустая строка или `null`), ветвь `true` не выполняет перехода.

### FalseStepUid

`Guid` шага, к которому перейдёт выполнение, если условие ложно. Если параметр не задан, ветвь `false` не выполняет перехода.

## Результат шага

Шаг не сохраняет данных в `_data`. Его единственная задача — направить поток выполнения.

## Пример: условная отправка писем

В процессе согласования документа после подготовки списка адресатов нужно отправить уведомления, только если список не пуст. Шаг If проверяет наличие данных и при выполнении условия передаёт управление шагу отправки почты:

```json
{
  "Condition": "_data.messages != null",
  "TrueStepUid": "f5644333-9480-ff9c-ef02-1ef071d5c426",
  "FalseStepUid": "",
  "KindName": "if",
  "Title": "Check mail",
  "Name": "check_mail",
  "IsActive": true
}
```

Здесь `TrueStepUid` указывает на шаг отправки письма. `FalseStepUid` не задан — если список адресатов пуст, процесс продолжится без отправки.

## Пример: выбор между двумя сценариями

Если при истинном и ложном результате нужно выполнить разные действия, укажите оба перехода:

```json
{
  "Condition": "_parameters.approved == true",
  "TrueStepUid": "aaa11111-1111-1111-1111-111111111111",
  "FalseStepUid": "bbb22222-2222-2222-2222-222222222222",
  "KindName": "if",
  "Title": "Check approval",
  "Name": "check_approval",
  "IsActive": true
}
```

При `approved == true` выполнение перейдёт к шагу подтверждения, при `false` — к шагу отклонения.

## Ограничения

- Выражение вычисляется синхронно. Асинхронные вызовы (`await`, запросы к данным) внутри условия не поддерживаются. Если условие зависит от результата запроса, выполните запрос в предшествующем шаге «Скрипт» и проверяйте его результат через `_data`.
- Выражение должно возвращать булево значение. Результаты других типов (`number`, `string`, `object`) трактуются как `false`.
