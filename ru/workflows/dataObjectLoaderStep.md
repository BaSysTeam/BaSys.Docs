# Загрузка объекта данных

Шаг **Загрузка объекта данных** (`data_object_loader`) создаёт или обновляет объекты данных в базе на основе результатов предыдущих шагов процесса. Шаг принимает коллекцию входных элементов, выполняет маппинг полей по заданным правилам и сохраняет результат в указанный мета-объект. Поддерживается загрузка как полей шапки, так и табличных частей объекта.

## Настройки

### MetaObjectKindUid

Идентификатор типа мета-объекта (вида), в который загружаются данные. Примеры видов: `operation`, `catalog`, `register`.

### MetaObjectUid

Идентификатор конкретного мета-объекта внутри указанного вида. Определяет целевую таблицу, в которую будут записаны объекты данных.

### SourcePath

Имя шага-источника данных. Шаг берёт результат указанного шага из контекста процесса (`_data`) и использует его как входную коллекцию. Каждый элемент коллекции обрабатывается отдельно: для него выполняется маппинг полей и операция сохранения.

Как правило, источником является шаг «Скрипт», который подготавливает данные с помощью `createTable` или возвращает результат запроса.

### SaveRegime

Режим сохранения объекта. Определяет, какие операции допустимы при загрузке:

| Значение | Режим          | Поведение                                                                                       |
|----------|----------------|-------------------------------------------------------------------------------------------------|
| 0        | CreateUpdate   | Если объект найден по `SearchBy` — обновляет его; если не найден — создаёт новый                |
| 1        | Create         | Только создание. Если объект уже существует, шаг фиксирует ошибку и пропускает элемент          |
| 2        | Update         | Только обновление. Если объект не найден по `SearchBy`, шаг фиксирует ошибку и пропускает элемент |

### SearchBy

Имя поля (или нескольких полей через запятую), по которому выполняется поиск существующего объекта в базе. Используется при режимах `Update` и `CreateUpdate` для определения, существует ли объект.

Значение для поиска берётся из результата маппинга: если в `HeaderMapping` есть строка с совпадающим `DestinationFieldName`, используется уже сопоставленное значение; иначе значение ищется напрямую во входном элементе.

Если параметр пуст, поиск не выполняется и шаг всегда создаёт новый объект (независимо от `SaveRegime`).

Пример с одним полем:

```
number
```

Пример с несколькими полями:

```
number, date
```

### Condition

JavaScript-выражение, которое вычисляется для каждого входного элемента. Если выражение возвращает `false`, элемент пропускается и не загружается. Если параметр пуст, все элементы обрабатываются без ограничений.

В выражении доступны:

- `item` — текущий обрабатываемый элемент входных данных.
- `_data` — результаты предыдущих шагов.
- `_parameters` — параметры процесса.

Пример:

```javascript
item.quantity > 0
```

### CreateRecords

Флаг, включающий создания записей, если создание записей поддерживается видом метаданных. По умолчанию — `false`.

### HeaderMapping

Коллекция правил маппинга полей шапки объекта данных. Каждая строка описывает, как значение из входного элемента преобразуется в значение поля целевого объекта.

Параметры строки маппинга:

| Параметр               | Описание                                                                                                                                                |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| `SourceFieldName`      | Имя поля во входном элементе, откуда берётся значение. Если пусто, поле заполняется значением `DefaultValue`                                           |
| `DestinationFieldName` | Имя поля в целевом объекте данных, куда записывается результат                                                                                          |
| `DefaultValue`         | Значение по умолчанию. Применяется, если `SourceFieldName` не задано или исходное значение пустое                                                       |
| `DataTypeUid`          | Идентификатор типа данных поля. Определяет, как значение будет разобрано и сохранено                                                                    |
| `SearchBy`             | Имя поля для поиска связанного объекта. Применяется для ссылочных (непримитивных) типов данных — шаг ищет объект по указанному полю и подставляет его первичный ключ |

#### Маппинг примитивных полей

Если тип данных поля примитивный (строка, число, дата, логическое значение) или `SearchBy` не задан, значение из входного элемента просто приводится к целевому типу и записывается в поле объекта.

Пример: загрузка текстового поля `topic` из входного элемента в поле `topic` объекта.

```json
{
  "SourceFieldName": "topic",
  "DestinationFieldName": "topic",
  "DefaultValue": "",
  "SearchBy": "",
  "DataTypeUid": "0234c067-7868-46b2-ba8e-e22fae5255cb"
}
```

#### Маппинг ссылочных полей

Если тип данных поля является ссылкой на другой объект (например, справочник или операцию) и задан `SearchBy`, шаг выполняет дополнительный запрос: ищет в связанном мета-объекте запись, у которой значение поля `SearchBy` совпадает с исходным значением, и подставляет первичный ключ найденной записи.

Пример: входное значение поля `status` содержит название статуса (`"name"`). Шаг ищет запись в справочнике статусов, у которой `name` равен переданному значению, и записывает в поле `status` целевого объекта первичный ключ найденного статуса.

```json
{
  "SourceFieldName": "status",
  "DestinationFieldName": "status",
  "DefaultValue": "",
  "SearchBy": "name",
  "DataTypeUid": "049e5e0f-eb73-4a21-ae91-91505d1ee048"
}
```

#### Поля со значением по умолчанию

Если `SourceFieldName` пуст, поле заполняется значением `DefaultValue`. Это удобно для установки фиксированных значений, не зависящих от входных данных.

```json
{
  "SourceFieldName": "",
  "DestinationFieldName": "is_deleted",
  "DefaultValue": "false",
  "SearchBy": "",
  "DataTypeUid": "4bff64cf-eb01-4933-9f3d-b902336751f4"
}
```

### TableMapping

Коллекция настроек загрузки табличных частей объекта данных. Каждый элемент описывает маппинг одной табличной части.

Параметры элемента:

| Параметр     | Описание                                                                                                        |
|--------------|-----------------------------------------------------------------------------------------------------------------|
| `TableUid`   | Идентификатор табличной части мета-объекта, в которую загружаются строки                                        |
| `SourcePath`  | JavaScript-выражение, которое возвращает коллекцию строк для табличной части. В выражении доступен объект `item` — текущий обрабатываемый элемент шапки |
| `Mapping`    | Коллекция правил маппинга полей строки табличной части (аналогична `HeaderMapping`)                              |

Выражение `SourcePath` вычисляется в контексте текущего элемента. Часто используется для фильтрации общей таблицы по идентификатору родительского элемента:

```
_data.table_data.filter(x=>x.operation_id == item.id)
```

## Результат шага

После выполнения шаг сохраняет список обработанных объектов, который доступен последующим шагам через `_data.<имя_шага>`. Каждый элемент результата содержит информацию о созданном или обновлённом объекте: вид, мета-объект, первичный ключ и представление.

Информация о созданных объектах также добавляется в общий список `CreatedObjects` процесса.

## Обработка ошибок

Шаг фиксирует ошибку в логе процесса в следующих случаях:

- Контекст данных процесса недоступен.
- Шаг-источник (`SourcePath`) не найден — процесс завершается со статусом `Terminated`.
- Входная коллекция пуста.
- Мета-объект или его вид не найдены по указанным идентификаторам.
- Не найден объект для обновления (режим `Update`).
- Объект уже существует (режим `Create`).
- Не найдено значение для ключа поиска (`SearchBy`).
- Не найдено исходное поле во входном элементе.
- Не найден связанный объект при маппинге ссылочного поля.

Ошибки обработки отдельного элемента не прерывают обработку остальных элементов коллекции. Процесс переходит в статус `Terminated` только при критических ошибках (например, отсутствие источника данных).

## Пример: создание задачи

Процесс состоит из двух шагов: скрипт формирует данные, загрузчик создаёт объект.

Скрипт `data`:

```javascript
var today = (new Date()).toLocalISO();
var tableData = createTable(['author number',
                             'responsible number',
                             'status',
                             'topic',
                             'date'])
  .addRow([_parameters.author,
           _parameters.responsible,
           _parameters.status,
           _parameters.topic,
           today]);

return tableData;
```

Шаг загрузки:

```json

  "SaveRegime": 1,

  "Condition": "",
  "HeaderMapping": [
    {
      "SourceFieldName": "date",
```

## Пример: обновление статуса

```json
{
  "MetaObjectKindUid": "14a60875-e241-4e99-b32d-d45b2726d18b",
  "MetaObjectUid": "a30177b3-bf29-4e3d-9215-9a1a5e2fcfdb",
  "SaveRegime": 2,
  "SearchBy": "number",
  "SourcePath": "data",
  "Condition": "",
  "HeaderMapping": [
    {
      "SourceFieldName": "status",
      "DestinationFieldName": "status",
      "DefaultValue": "",
      "SearchBy": "name",
      "DataTypeUid": "049e5e0f-eb73-4a21-ae91-91505d1ee048"
    }
  ],
  "TableMapping": [],
  "KindName": "data_object_loader",
  "Title": "Set status",
  "Name": "set_status",
  "IsActive": true
}
```

`SaveRegime = 2` (Update) — шаг ищет существующий объект по полю `number` и обновляет только поле `status`.

Данные шапки загружаются из шага `header_data`. Табличная часть заполняется строками из шага `table_data`, отфильтрованными по `operation_id` текущего элемента шапки. Маппинг полей табличной части работает по тем же правилам, что и маппинг полей шапки.
