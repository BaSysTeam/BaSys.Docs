# Итератор (Iterator)

Шаг **Итератор** (`iterator`) организует циклическое выполнение группы шагов для каждого элемента коллекции. Он работает совместно с шагом **Остановка итератора** (`iterator_stop`), который обозначает конец тела цикла. Все шаги, расположенные между `iterator` и `iterator_stop`, выполняются на каждой итерации.

## Как работает шаг

1. Шаг `iterator` получает коллекцию по пути `SourcePath` — это техническое имя (`Name`) предшествующего шага, результат которого содержит массив или таблицу.
2. Коллекция преобразуется в список объектов. Поддерживаются: `DataTable`, `List<IDictionary<string, object>>`, `List<ExpandoObject>`, `List<dynamic>`, `IEnumerable<object>`, одиночный `ExpandoObject`, `KeyValuePair<string, object>`.
3. Текущий элемент коллекции записывается в данные процесса под именем, указанным в `ItemName`. Этот объект доступен в последующих шагах через `_data.<ItemName>` или через шаблоны подстановки `{{<ItemName>.<field>}}`.
4. Выполняются все шаги тела цикла (между `iterator` и `iterator_stop`).
5. Шаг `iterator_stop` увеличивает индекс. Если в коллекции есть следующий элемент, управление возвращается к первому шагу тела цикла. Если коллекция исчерпана — цикл завершается и выполнение продолжается после `iterator_stop`.

## Границы цикла

Границу цикла необходимо указать явно, добавив шаг `iterator_stop` в конце тела цикла. Система автоматически находит парный `iterator` для каждого `iterator_stop`, двигаясь по цепочке `PreviousStepUid` назад. Это позволяет использовать вложенные итераторы — каждый `iterator_stop` сопоставляется с ближайшим незакрытым `iterator`.

Если шаг `iterator_stop` не указан, цикл не будет повторяться — шаги тела выполнятся только для первого элемента.

## Настройки шага Iterator

### SourcePath

Техническое имя (`Name`) шага, результат которого содержит коллекцию для перебора. Обычно это шаг «Скрипт», возвращающий массив объектов, или шаг «Загрузка объекта данных».

### ItemName

Имя переменной, под которым текущий элемент коллекции будет доступен в контексте процесса. Значение перезаписывается на каждой итерации. К полям элемента можно обращаться:

- В шаблонах: `{{item.field_name}}`
- В скриптах: `_data.item.field_name`

где `item` — значение `ItemName`.

## Настройки шага Iterator Stop

Шаг `iterator_stop` не имеет собственных настраиваемых параметров. Все необходимые значения (`IteratorName`, `ItemName`, `HasExit`) определяются автоматически при построении процесса на основе парного шага `iterator`.

## Результат шага

Шаг `iterator` не сохраняет собственных данных в `_data`. Его задача — инициализировать состояние цикла и записать первый элемент коллекции под именем `ItemName`.

Шаг `iterator_stop` также не сохраняет данных — он управляет переходом к следующей итерации или выходом из цикла.

## Обработка ошибок

- Если коллекция по пути `SourcePath` не найдена — процесс завершается с ошибкой (`Terminated`), в лог записывается сообщение `Cannot find step: <SourcePath>`.
- Если состояние итератора не найдено при выполнении `iterator_stop` — цикл прерывается, в лог записывается ошибка.
- Если коллекция пуста (`null`) — цикл прерывается без выполнения тела.

## Пример: рассылка писем по списку

Процесс подготавливает список задач в скрипте, затем для каждого элемента отправляет письмо:

```json
[
  {
    "expression": "workflow.tasks_mail_send.step.tasks.bjs",
    "kindName": "java_script",
    "title": "Tasks",
    "name": "tasks",
    "isActive": true
  },
  {
    "sourcePath": "tasks",
    "itemName": "item",
    "kindName": "iterator",
    "title": "Iterator",
    "name": "iterator",
    "isActive": true
  },
  {
    "host": "smtp.example.com",
    "from": "noreply@example.com",
    "to": "{{item.user_name}}",
    "subject": "Задачи в системе",
    "body": "{{item.messages}}",
    "kindName": "smtp_send",
    "title": "Mail send",
    "name": "mail_send",
    "isActive": true
  },
  {
    "kindName": "iterator_stop",
    "title": "Iterator stop",
    "name": "iterator_stop",
    "isActive": true
  }
]
```

Здесь шаг `tasks` формирует массив объектов с полями `user_name` и `messages`. Итератор проходит по каждому элементу, записывая его в `item`. Шаг отправки письма использует поля текущего элемента через шаблоны `{{item.user_name}}` и `{{item.messages}}`. Шаг `iterator_stop` замыкает тело цикла.

## Пример: итератор с условием внутри тела

Внутри тела цикла можно использовать любые шаги, включая условия:

```json
[
  {
    "sourcePath": "messages",
    "itemName": "item",
    "kindName": "iterator",
    "title": "Iterator",
    "name": "iterator",
    "isActive": true
  },
  {
    "condition": "_data.messages != null",
    "trueStepUid": "...",
    "falseStepUid": "",
    "kindName": "if",
    "title": "Check mail",
    "name": "check_mail",
    "isActive": true
  },
  {
    "kindName": "smtp_send",
    "title": "Mail send",
    "name": "mail_send",
    "isActive": true
  },
  {
    "kindName": "iterator_stop",
    "title": "Iterator stop",
    "name": "iterator_stop",
    "isActive": true
  }
]
```

## Ограничения

- Коллекция целиком загружается в память перед началом итерации. Для очень больших наборов данных рекомендуется ограничивать выборку на этапе подготовки.
- Итератор не поддерживает прерывание цикла по условию (аналог `break`). Для пропуска элементов используйте шаг «Условие» внутри тела цикла.
- Вложенные итераторы поддерживаются, но каждый вложенный итератор должен иметь свой парный `iterator_stop`.
