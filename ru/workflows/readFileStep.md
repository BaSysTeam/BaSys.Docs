# Чтение файла

Шаг **Чтение файла** (`read_file`) загружает файл из файлового хранилища BaSYS и сохраняет его содержимое для последующих шагов процесса. Файл идентифицируется по UID, который может быть задан напрямую или вычислен выражением на основе данных предыдущих шагов. Результат доступен в двух форматах: бинарном (массив байтов) и текстовом (строка UTF-8).

Типичный сценарий использования — чтение загруженного пользователем файла (например, Excel-документа) перед его обработкой шагом маппинга или скриптом.

## Настройки

### Regime

Режим работы шага. Определяет источник файла:

| Значение | Режим        | Описание                                                                 |
|----------|--------------|--------------------------------------------------------------------------|
| 1        | AttachedFile | Прикреплённый файл — UID файла задаётся выражением                      |

Значение по умолчанию — `AttachedFile` (1).

В режиме `AttachedFile` шаг использует параметр `AttachedFileUidExpression` для получения идентификатора файла. В режиме `Interactive` файл передаётся процессу в момент запуска.

### OutputFormat

Формат выходных данных шага:

| Значение | Формат | Описание                                              |
|----------|--------|-------------------------------------------------------|
| 0        | Binary | Содержимое файла сохраняется как массив байтов        |
| 1        | Text   | Содержимое файла декодируется из UTF-8 в строку       |

Значение по умолчанию — `Binary` (0).

Формат `Binary` используется, когда файл передаётся дальше по процессу без текстовой интерпретации — например, для обработки Excel-файлов шагом маппинга. Формат `Text` применяется, когда содержимое файла нужно разобрать как текст (CSV, JSON, XML и т.д.) в последующем скрипте.

### AttachedFileUidExpression

Выражение, возвращающее UID файла в файловом хранилище. Может принимать одну из двух форм:

1. **Строковый GUID** — статический идентификатор файла, например `"3fa85f64-5717-4562-b3fc-2c963f66afa6"`.
2. **JavaScript-выражение** — динамическое вычисление UID на основе данных процесса. Выражение выполняется движком ClearScript и имеет доступ к параметрам процесса и результатам предыдущих шагов.

Шаг сначала пытается разобрать значение как GUID. Если это не удаётся, значение интерпретируется как выражение и вычисляется. Результат выражения должен быть типа `Guid` или строкой, допускающей преобразование в GUID.

Примеры выражений:

```javascript
// UID файла из результата предыдущего шага (запрос вернул строку с uid)
_data.find_file.rows[0].uid

// UID из параметров процесса
_parameters.fileUid
```

## Результат шага

После выполнения содержимое файла сохраняется и становится доступно последующим шагам через `_data.<имя_шага>`.

- При `OutputFormat = Binary` результат — массив байтов (`byte[]`). Этот формат принимается шагами, работающими с бинарными данными (например, шаг Excel-маппинга).
- При `OutputFormat = Text` результат — строка с содержимым файла, декодированным из UTF-8.

## Обработка ошибок

Шаг завершает процесс со статусом `Terminated` в следующих случаях:

- Выражение `AttachedFileUidExpression` не может быть вычислено или результат не преобразуется в GUID.
- Не удалось получить конфигурацию базы данных или файлового хранилища.
- Файл с указанным UID не найден в хранилище или его содержимое пусто.
- Указан неподдерживаемый формат вывода.

Если UID вычислен, но равен пустому GUID (`00000000-0000-0000-0000-000000000000`), шаг записывает ошибку в лог и переходит к следующему шагу без прерывания процесса.

## Пример: чтение файла по UID из предыдущего шага

```json
{
  "Regime": 1,
  "OutputFormat": 0,
  "AttachedFileUidExpression": "_data.find_file.rows[0].uid",
  "KindName": "read_file",
  "Title": "Read file",
  "Name": "read_file",
  "IsActive": true
}
```

Шаг читает файл, UID которого получен на предыдущем шаге `find_file` (первая строка результата, поле `uid`). Содержимое сохраняется в бинарном формате и может быть передано далее в шаг Excel-маппинга.

## Пример: чтение текстового файла

```json
{
  "Regime": 1,
  "OutputFormat": 1,
  "AttachedFileUidExpression": "_parameters.fileUid",
  "KindName": "read_file",
  "Title": "Read config",
  "Name": "read_config",
  "IsActive": true
}
```

Шаг читает файл, UID которого передан в параметрах процесса. Содержимое декодируется в текст (UTF-8) и доступно в последующих шагах через `_data.read_config`.

## Типичная цепочка шагов

Чтение файла редко используется изолированно. Стандартный сценарий загрузки данных из Excel-файла включает несколько шагов:

1. **Скрипт** — получает данные операции или выполняет запрос для определения UID файла.
2. **Чтение файла** — загружает файл из хранилища в бинарном формате.
3. **Excel-маппинг** — разбирает содержимое файла, извлекает данные по заданному маппингу колонок.
4. **Скрипт** — обрабатывает извлечённые данные и формирует результат.

```json
{
  "Steps": [
    {
      "KindName": "java_script",
      "Name": "find_file",
      "Title": "Find file"
    },
    {
      "Regime": 1,
      "OutputFormat": 0,
      "AttachedFileUidExpression": "_data.find_file.rows[0].uid",
      "KindName": "read_file",
      "Name": "read_file",
      "Title": "Read file"
    },
    {
      "SourcePath": "read_file",
      "SheetName": "Sheet1",
      "KindName": "excel_mapping",
      "Name": "mapping",
      "Title": "Mapping"
    }
  ]
}
```

В этой цепочке шаг `excel_mapping` ссылается на шаг `read_file` через параметр `SourcePath`, получая из него бинарное содержимое файла для разбора.
