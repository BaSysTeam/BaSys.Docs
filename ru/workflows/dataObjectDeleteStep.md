# Удаление объектов данных

Шаг **Удаление объектов данных** (`data_object_delete`) удаляет объекты одного мета-объекта по идентификаторам, подготовленным предыдущими шагами процесса. Например, с его помощью можно очищать устаревшие записи регистра или помещать в корзину неиспользуемые элементы справочника.

Способ удаления определяется видом мета-объекта: объекты ссылочных видов помещаются в корзину, объекты нессылочных видов удаляются окончательно.

## Настройки

### MetaObjectKindUid

Идентификатор вида мета-объекта. В конструкторе доступны только виды, хранящие данные: справочники, операции, перечисления, регистры, регистры движений и пользовательские виды с хранением данных.

### MetaObjectUid

Идентификатор мета-объекта, объекты которого нужно удалить. Список в конструкторе зависит от выбранного вида. Один шаг удаляет объекты только этого мета-объекта.

После выбора вида редактор показывает подсказку: «Объекты будут помещены в корзину» или «Записи будут удалены окончательно».

### SourcePath

Обязательное JavaScript-выражение, возвращающее данные для удаления. В выражении доступны:

- `_data` — результаты предыдущих шагов по их техническому имени.
- `_parameters` — параметры процесса.
- `$m` — [общие модули](../calculations/sharedModules.md).

Примеры:

```javascript
_data.objects_to_delete
```

```javascript
_parameters.objectId
```

```javascript
$m.cleanup.ids()
```

Для обращения к результату шага нужно полное выражение `_data.objects_to_delete`. Простого имени `objects_to_delete`, которое используется в `SourcePath` [загрузчика объектов данных](dataObjectLoaderStep.md), недостаточно.

Выражение вычисляется синхронно. Запросы с `await` выполняйте в предшествующем шаге [«Скрипт»](scriptStep.md), затем передавайте его результат через `_data`.

### IdentifierField

Имя поля входного объекта или колонки входной таблицы, из которого берётся идентификатор. Параметр необязателен: если он пуст, используется имя первичного ключа выбранного мета-объекта. Имя поля сопоставляется без учёта регистра.

Например, для справочника с первичным ключом `id`:

- При пустом `IdentifierField` входные объекты `{"Id": 7}` и `{"id": 8}` задают идентификаторы `7` и `8`.
- При `IdentifierField = product_id` входной объект `{"product_id": 7}` задаёт идентификатор `7`.
- Для скаляров и массивов скаляров поле не используется: идентификатором является само значение.

Значение всегда трактуется как **первичный ключ удаляемого объекта**. `IdentifierField` задаёт поле во входных данных; поиск объекта по произвольному реквизиту, например названию или артикулу, шаг не выполняет.

## Входные данные

`SourcePath` может вернуть данные в следующих форматах:

| Формат | Пример | Как извлекаются идентификаторы |
|--------|--------|-------------------------------|
| Одиночный скаляр | `15` | Удаляется один объект с ключом `15` |
| Массив скаляров | `[15, 16]` | Каждый элемент — отдельный идентификатор |
| Одиночный объект | `{"id": 15}` | Значение поля `IdentifierField` или первичного ключа |
| Массив объектов | `[{"id": 15}, {"id": 16}]` | Поле читается у каждого объекта |
| Таблица запроса `from().query()` | `_data.objects_to_delete` | Поле читается в каждой строке таблицы |

Значения приводятся к типу первичного ключа. Повторы после приведения обрабатываются один раз: для целочисленного ключа массив `["101", 101, 102]` задаёт два объекта — `101` и `102`.

Пустой массив или таблица без строк означает, что удалять нечего: шаг записывает информационное сообщение, публикует пустой результат и продолжает процесс. Значения `null` и `undefined` в качестве результата всего выражения считаются ошибкой и останавливают процесс.

## Правила удаления

| Вид мета-объекта | Поведение |
|-----------------|-----------|
| Ссылочный, например справочник или операция | Объект помечается как удалённый и помещается в корзину; его можно восстановить |
| Нессылочный, например регистр или регистр движений | Объект и строки его табличных частей удаляются окончательно; запись в корзине не создаётся |

Настройки способа удаления нет. Окончательное удаление ссылочных объектов выполняется при очистке корзины.

При удалении объекта, создающего движения регистров, его движения удаляются, а признак «создавать движения» снимается. Восстановление объекта из корзины не восстанавливает движения.

Каждый объект обрабатывается независимо: изменения самого объекта, его движений и корзины фиксируются вместе. Если удаление объекта не удалось, эти изменения откатываются, а шаг переходит к следующему идентификатору. Уже выполненные удаления других объектов сохраняются.

Объект, уже находящийся в корзине, пропускается с информационным сообщением. Это не ошибка; повторная запись корзины не создаётся.

Шаг выполняет системную операцию: права пользователя на удаление не проверяются, процессы-триггеры на событие удаления не запускаются.

## Результат шага

Список успешно обработанных объектов доступен последующим шагам через `_data.<имя_шага>`. В него входят как помещённые в корзину, так и удалённые окончательно объекты. Каждый элемент содержит вид мета-объекта, мета-объект, первичный ключ, представление объекта и событие удаления (`EditEvent = Delete`).

Пропущенные объекты и объекты с ошибками в результат не попадают. Например, если шаг `delete_old` обработал идентификаторы `[15, 999, 16]`, а объект `999` не найден, следующий скрипт получит число `2`:

```javascript
return _data.delete_old.length;
```

## Логи и история

Для каждого успешно обработанного объекта шаг пишет сообщение в лог процесса и запись `DataObjectDelete` в общий лог событий. Сообщения различают помещение в корзину и окончательное удаление. В итоговом сообщении шага указаны количества помещённых в корзину, удалённых окончательно, пропущенных объектов и ошибок.

Ошибки удаления с корректным идентификатором, например отсутствие объекта или отказ базы данных, записываются в оба лога. Ошибки извлечения идентификатора и пропуск объекта, уже находящегося в корзине, записываются только в лог процесса.

Если для мета-объекта включено сохранение истории, сохраняется событие удаления с полным снимком объекта до удаления, включая табличные части. Ошибка сохранения истории фиксируется в логе процесса и не отменяет удаление.

В записях общего лога событий, истории и корзины указывается пользователь, от имени которого запущен процесс. Если идентификатор пользователя запуска пуст, в том числе при запуске по расписанию, используется имя `workflow:<имя процесса>`.

## Обработка ошибок

Шаг останавливает процесс со статусом `Terminated`, если:

- `SourcePath` пуст, выражение не удалось вычислить либо оно вернуло `null` или `undefined`.
- Не найден выбранный вид или мета-объект, мета-объект не принадлежит выбранному виду либо вид не хранит данные.
- Недоступен контекст данных процесса, конфигурация базы данных или описание первичного ключа.

Ошибки отдельного элемента записываются в лог и не прерывают обработку остальных элементов:

- Идентификатор пуст, в том числе ячейка таблицы содержит пустое значение.
- Идентификатор нельзя привести к типу первичного ключа.
- Во входном объекте или строке таблицы нет поля идентификатора.
- Объект с указанным первичным ключом не найден.
- При удалении произошла ошибка базы данных, например нарушение ссылочной целостности.

Процесс продолжается после шага даже при наличии ошибок отдельных элементов. Если дальнейшие действия зависят от числа успешных удалений, используйте результат шага.

## Пример: помещение операций в корзину

Процесс состоит из двух шагов: скрипт `objects_to_delete` возвращает номера операций, затем шаг `delete_old` помещает их в корзину.

Скрипт `objects_to_delete`:

```javascript
return [101, 102, 101];
```

Шаг удаления:

```json
{
  "metaObjectKindUid": "14a60875-e241-4e99-b32d-d45b2726d18b",
  "metaObjectUid": "a30177b3-bf29-4e3d-9215-9a1a5e2fcfdb",
  "sourcePath": "_data.objects_to_delete",
  "identifierField": "",
  "kindName": "data_object_delete",
  "title": "Удалить старые операции",
  "name": "delete_old",
  "isActive": true
}
```

Замените `MetaObjectKindUid` и `MetaObjectUid` идентификаторами вида и мета-объекта из вашей базы. Для операции с первичным ключом `number` значения `101` и `102` — номера операций. Каждая операция обрабатывается один раз. Если они существуют и ещё не находятся в корзине, результат `_data.delete_old` содержит два объекта.

## Пример: удаление по результату запроса

В шаге «Скрипт» с именем `objects_to_delete` выберите идентификаторы устаревших строк регистра:

```javascript
var objects = await from('register.cleanup_queue')
  .select(['id as record_id'])
  .where('period < @before')
  .parameter('before', _parameters.before)
  .query();

return objects;
```

В примере `cleanup_queue` — регистр с первичным ключом `id` и полем `period`, а `before` — параметр процесса. В шаге удаления выберите этот регистр и задайте:

| Параметр | Значение |
|----------|----------|
| `SourcePath` | `_data.objects_to_delete` |
| `IdentifierField` | `record_id` |

Шаг прочитает ключи из колонки `record_id` таблицы запроса и удалит соответствующие строки регистра окончательно. Если запрос не вернёт строк, процесс продолжится без удаления.
