# Параметры процессов

Параметры процесса — это именованные значения, которые передаются в процесс при его запуске и доступны во всех шагах через служебный объект `_parameters`. С их помощью один и тот же процесс можно использовать в разных сценариях: в качестве параметров можно указывать как примитивные значения, так и массивы и объекты с описанием типов свойств.

Список параметров задаётся на уровне процесса в свойстве `parameters` JSON-описания. Каждый элемент — это отдельное определение параметра с фиксированным набором полей.

## Определение параметра

Структура определения соответствует классу `WorkflowParameterDefinition`. Поля совпадают между внутренним представлением и JSON-файлом процесса (с поправкой на регистр).

| Поле           | Тип     | Описание                                                                                                  |
|----------------|---------|-----------------------------------------------------------------------------------------------------------|
| `uid`          | guid    | Уникальный идентификатор параметра. Назначается при создании и используется как ключ при редактировании.  |
| `name`         | string  | Техническое имя параметра. Используется для обращения из шагов через `_parameters.<name>`.                |
| `dataType`     | string  | Тип значения. Допустимые значения перечислены ниже.                                                       |
| `defaultValue` | string  | Значение по умолчанию. Хранится как строка; для составных типов содержит JSON-описание.                   |
| `required`     | boolean | Признак обязательного параметра. Если `true`, перед запуском процесса значение проверяется.               |
| `memo`         | string  | Произвольный комментарий к параметру. Полезен в качестве описания для пользователя при интерактивном запуске. |

Имя параметра должно быть непустым: при разборе входных значений пустое имя приводит к ошибке.

## Типы данных

Тип параметра определяет, как строковое значение преобразуется при запуске процесса. Поддерживаются следующие значения поля `dataType`:

| Тип       | Описание                                                                          |
|-----------|-----------------------------------------------------------------------------------|
| `string`  | Строка.                                                                           |
| `integer` | Целое 32-битное число.                                                            |
| `long`    | Целое 64-битное число.                                                            |
| `number`  | Десятичное число (`decimal`).                                                     |
| `boolean` | Логическое значение.                                                              |
| `date`    | Дата/время.                                                                       |
| `object`  | Структура с именованными свойствами. Каждое свойство имеет собственный тип.       |
| `array`   | Массив элементов. Каждый элемент имеет собственный тип.                           |

Неизвестное значение `dataType` приводит к ошибке разбора параметров.

### Примитивные параметры

Для примитивных типов значение задаётся обычной строкой и преобразуется к указанному типу:

```json
{
  "uid": "73b4f06a-407d-4ce8-b143-41565aff81db",
  "name": "person_to",
  "dataType": "integer",
  "defaultValue": "",
  "required": true,
  "memo": "Идентификатор получателя"
}
```

В шаге процесса значение доступно по имени:

```javascript
var personTo = _parameters.person_to;
```

### Объект (`object`)

Параметр типа `object` описывает структуру с именованными свойствами. В поле `defaultValue` сохраняется JSON-массив с описанием свойств; каждое свойство содержит собственное имя, тип и значение:

```json
{
  "uid": "9b632414-7be3-ef97-a6e3-ec99b2d8cd22",
  "name": "object_value",
  "dataType": "object",
  "defaultValue": "[{\"name\":\"message\",\"dataType\":\"string\",\"value\":\"Test message\"},{\"name\":\"count\",\"dataType\":\"integer\",\"value\":\"3\"}]",
  "required": false,
  "memo": ""
}
```

При запуске процесса `defaultValue` разбирается рекурсивно: каждое свойство преобразуется в соответствии со своим `dataType`. В скрипте параметр доступен как обычный объект:

```javascript
return _parameters.object_value;
// { message: 'Test message', count: 3 }
```

### Массив (`array`)

Параметр типа `array` описывает упорядоченный список значений. В отличие от `object`, элементы не имеют имён — указывается только тип и значение:

```json
{
  "uid": "964ce5ff-4b1a-28fe-42ec-eb66b664b5f2",
  "name": "array_value",
  "dataType": "array",
  "defaultValue": "[{\"dataType\":\"string\",\"value\":\"string-value\"},{\"dataType\":\"integer\",\"value\":\"5\"}]",
  "required": false,
  "memo": ""
}
```

В скрипте параметр доступен как массив:

```javascript
return _parameters.array_value;
// ['string-value', 5]
```

Элементы массивов и свойства объектов сами могут быть составными — это позволяет описывать вложенные структуры произвольной глубины.

## Значения по умолчанию

Если параметр не передан при запуске или передан с пустым значением, используется `defaultValue`. Правило применяется одинаково для интерактивного запуска, запуска по расписанию и запуска по триггеру.

Подстановка значений по умолчанию происходит до разбора. Это означает, что:

- Пустая строка во входных параметрах считается пропуском и заменяется значением по умолчанию.
- Если входное значение задано (даже как `"0"` или `"false"`), оно используется без изменений.
- Для составных типов `defaultValue` должен быть валидным JSON-массивом описаний свойств или элементов.

## Обязательные параметры

Параметр с `required = true` проверяется перед запуском процесса. Если значение не передано и значение по умолчанию не задано, процесс не запускается, а вызывающая сторона получает ошибку со списком имён незаполненных параметров.

Проверка работает одинаково для всех способов запуска: интерактивного, по расписанию и по триггеру. Параметр считается незаполненным в следующих случаях:

- Параметр отсутствует во входных данных.
- Значение равно `null`.
- Значение — пустая строка или строка, состоящая только из пробельных символов.
- Значение является `JsonElement` со значением `null` либо пустой строкой.

Если для обязательного параметра задано непустое `defaultValue`, оно подставляется до проверки и параметр считается заполненным.

С точки зрения разработчика процесса полезно явно помечать обязательные параметры и заполнять у них поле `memo`: это позволяет системе остановить запуск с понятным сообщением вместо того, чтобы процесс падал на одном из шагов из-за отсутствующих данных. Описание из `memo` помогает пользователю при интерактивном запуске понять, какое значение нужно ввести.

Пример обязательных параметров реального процесса:

```json
"parameters": [
  {
    "uid": "a2a45139-838b-d8d2-08ca-e80744268e52",
    "name": "person_from",
    "dataType": "integer",
    "defaultValue": "",
    "required": true,
    "memo": "Идентификатор отправителя"
  },
  {
    "uid": "73b4f06a-407d-4ce8-b143-41565aff81db",
    "name": "person_to",
    "dataType": "integer",
    "defaultValue": "",
    "required": true,
    "memo": "Идентификатор получателя"
  },
  {
    "uid": "e4a6fdd5-4a3a-2ecd-c790-28a69d345a88",
    "name": "task",
    "dataType": "integer",
    "defaultValue": "",
    "required": true,
    "memo": "Номер задачи"
  }
]
```

## Использование в шагах

Внутри любого шага параметры доступны через служебный объект `_parameters`. Имена соответствуют полю `name` в определении параметра:

```javascript
return _parameters.array_value;
```

```javascript
return _parameters.object_value;
```

Если имя параметра не является корректным JavaScript-идентификатором, используйте квадратные скобки: `_parameters['parameter-name']`. Полное описание контекста выполнения см. в статье [Шаг "Скрипт"](scriptStep.md).

В шагах загрузки данных, мэппинга и других прикладных шагах параметры используются так же, как и любые другие именованные значения, доступные процессу.

## Параметры при интерактивном запуске

При интерактивном запуске процесса панель параметров заполняется значениями из определения процесса: имя, тип и значение по умолчанию копируются в строки таблицы и доступны для редактирования пользователем. Пользователь может изменить значения примитивных параметров прямо в ячейке таблицы; для типов `object` и `array` открывается отдельный диалог редактирования сложного значения.

Из этого следует несколько практических рекомендаций:

- Указывайте осмысленные значения по умолчанию для параметров, которые в большинстве случаев не меняются. Они автоматически попадут в панель и сократят количество действий пользователя.
- Заполняйте поле `memo`: оно используется как описание параметра и помогает понять назначение поля без обращения к исходному JSON процесса.
- Помечайте действительно обязательные значения через `required`: без этого пользователь сможет запустить процесс с пустыми полями, и ошибка возникнет уже на этапе выполнения шагов, а не до запуска.

Изменения, внесённые пользователем в панели параметров, передаются на сервер при запуске и далее обрабатываются по тем же правилам, что и параметры программных запусков (по расписанию или по триггеру): сначала подставляются значения по умолчанию для пустых полей, затем выполняется проверка обязательных параметров, и только после этого процесс действительно стартует.

## Полный пример

Процесс `test_parameters` из эталонного набора демонстрирует одновременно объект и массив в качестве параметров:

```json
{
  "$schema": "../../system/schemas/workflowSettings.schema.json",
  "uid": "11c056be-dc05-047b-1bd0-810869f543cb",
  "name": "test_parameters",
  "title": "99.009 Test parameters",
  "isActive": true,
  "version": 7,
  "parameters": [
    {
      "uid": "964ce5ff-4b1a-28fe-42ec-eb66b664b5f2",
      "name": "array_value",
      "dataType": "array",
      "defaultValue": "[{\"dataType\":\"string\",\"value\":\"string-value\"},{\"dataType\":\"integer\",\"value\":\"5\"}]",
      "required": false,
      "memo": ""
    },
    {
      "uid": "9b632414-7be3-ef97-a6e3-ec99b2d8cd22",
      "name": "object_value",
      "dataType": "object",
      "defaultValue": "[{\"name\":\"message\",\"dataType\":\"string\",\"value\":\"Test message\"},{\"name\":\"count\",\"dataType\":\"integer\",\"value\":\"3\"}]",
      "required": false,
      "memo": ""
    },
    {
      "uid": "4e7bf438-c8fa-7392-7f82-19067e798f6d",
      "name": "id",
      "dataType": "integer",
      "defaultValue": "1",
      "required": false,
      "memo": ""
    }
  ],
  "steps": [
    {
      "expression": "workflow.test_parameters.step.read_parameters_1.bjs",
      "kindName": "java_script",
      "title": "Read parameters 1",
      "name": "read_parameters_1",
      "isActive": true
    },
    {
      "expression": "workflow.test_parameters.step.read_parameters_2.bjs",
      "kindName": "java_script",
      "title": "Read parameters 2",
      "name": "read_parameters_2",
      "isActive": true
    },
    {
      "expression": "workflow.test_parameters.step.read_parameters_3.bjs",
      "kindName": "java_script",
      "title": "Read parameters 3",
      "name": "read_parameters_3",
      "isActive": true
    }
  ]
}
```

Шаги процесса просто возвращают параметры:

```javascript
// read_parameters_1
return _parameters.array_value;
```

```javascript
// read_parameters_2
return _parameters.object_value;
```

```javascript
// read_parameters_3
return _parameters.id;
```

Результаты шагов содержат уже разобранные значения: массив `['string-value', 5]`, объект `{ message: 'Test message', count: 3 }` и целое число `1` (значение по умолчанию параметра `id`). Эти значения можно передавать дальше — в скрипты, шаги загрузки или построитель запросов.
