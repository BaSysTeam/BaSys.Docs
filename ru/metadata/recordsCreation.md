# Создание записей (Проведение по регистрам)

## Введение

Если у вида метаданных установлен флаг **canCreateRecords**, то объекты данного вида могут формировать записи в специально предназначенных для этого регистрах. Регистры для хранения записей — это неccылочные **DataObject** с набором стандартных колонок, необходимых для работы механизма создания записей. Вид метаданных, который порождает записи, традиционно называется **Операция** (Operation), а вид метаданных, принимающий записи, — **Регистр записей** (records).

Механизм создания записей важен для задач управленческого учёта, так как позволяет декомпозировать хозяйственную операцию по различным регистрам учёта. Например, при регистрации операции «Продажа» необходимо одновременно отразить изменение во взаиморасчётах с контрагентом и уменьшить количество товаров на складе — каждое из этих изменений попадёт в свой регистр.

Аналогичного поведения можно добиться с помощью триггеров и процессов, однако такая настройка получится более сложной и менее очевидной для пользователя. Поскольку проведение по регистрам — крайне важная функциональность для задач управленческого учёта, настройка создания записей реализована как специальный механизм в рамках **DataObject**.

## Общая схема работы

При записи объекта-источника (например, документа-операции) система выполняет следующие шаги:

1. Проверяет, что у вида метаданных включён флаг **canCreateRecords**.
2. Для каждого регистра-приёмника, указанного в настройках, удаляет ранее созданные записи, относящиеся к текущему объекту. Это гарантирует идемпотентность: повторное сохранение документа не приводит к дублированию записей.
3. Если у текущего объекта флаг «Создавать записи» (стандартная колонка **create_records**) снят, механизм на этом останавливается — старые записи удалены, новые не создаются. Такое поведение позволяет «отменять проведение» без удаления самого объекта.
4. Если флаг установлен, для каждого правила поочерёдно вычисляется источник данных (шапка, табличная часть или источник записей), применяется условие отбора строк и формируются новые записи регистра.
5. Сформированные записи вставляются в таблицу регистра в рамках текущей транзакции записи объекта.

## Структура записи регистра

Регистр записей — это обычный **DataObject**, у которого в шапке обязательно присутствует набор стандартных колонок. Соответствие этих колонок в регистре-приёмнике задаётся в настройках вида метаданных-источника в блоке `recordsSettings` (свойства `storageKindColumnUid`, `storageMetaObjectColumnUid`, `storageObjectColumnUid`, `storageRowColumnUid`, `storagePeriodColumnUid`).

| Колонка           | Настройка вида              | Назначение                                                                                      | Заполнение                                      |
|-------------------|-----------------------------|-------------------------------------------------------------------------------------------------|-------------------------------------------------|
| `MetaObjectKind`  | `storageKindColumnUid`      | Идентификатор вида метаданных объекта-источника (например, вида «Операция»).                    | Автоматически механизмом создания записей.      |
| `MetaObject`      | `storageMetaObjectColumnUid`| Идентификатор конкретного объекта метаданных-источника (например, «Продажа»).                   | Автоматически механизмом создания записей.      |
| `Object`          | `storageObjectColumnUid`    | Первичный ключ объекта-источника (`uid` конкретного документа-операции).                        | Автоматически механизмом создания записей.      |
| `Row`             | `storageRowColumnUid`       | Порядковый номер записи в пределах одного источника. При источнике «шапка» всегда равен 1.      | Автоматически механизмом создания записей.      |
| `Period`          | `storagePeriodColumnUid`    | Дата/период записи регистра. Используется для хронологической сортировки и построения итогов.   | Вручную через выражение (обычно `$h.date`).     |

По паре (`MetaObject`, `Object`) система определяет, какие записи нужно удалить при перезаписи объекта-источника.

Колонки `MetaObjectKind`, `MetaObject`, `Object` и `Row` механизм создания записей заполняет самостоятельно, и указывать их в правилах формирования записей не нужно.

Колонку `Period` система автоматически не заполняет — её значение обязательно задаётся пользовательским выражением в правиле формирования записей. Как правило, в `Period` подставляется дата шапки документа-источника (`$h.date`), но допустимо и любое другое выражение, возвращающее значение типа `DateTime`.

Остальные колонки регистра (измерения, ресурсы, реквизиты) также заполняются на основании пользовательских выражений.

## Настройка создания записей

Если у вида метаданных установлен флаг **canCreateRecords**, то в настройке объектов данного вида становится доступна закладка **Записи** с правилами формирования записей в регистры.

Настройка записей задаётся в виде списка правил. Каждое правило описывает создание записей в одном регистре-приёмнике и содержит одну или несколько строк (`Rows`). Каждая строка задаёт:

- **SourceUid** — источник данных (шапка, табличная часть или источник записей).
- **Direction** — направление записи (`0` — Приход/Plus, `1` — Расход/Minus). При значении `Minus` все десятичные (`decimal`) поля сформированной записи автоматически умножаются на `-1`. Это удобно для регистров остатков и взаиморасчётов.
- **Condition** — необязательное условие на языке JavaScript. Если условие возвращает `false`, запись пропускается.
- **Columns** — список колонок регистра-приёмника и выражений, по которым эти колонки заполняются.

Один документ-источник может формировать записи сразу в нескольких регистрах, а для одного регистра может быть задано несколько строк с разными источниками и направлениями.

## Источники данных для записей

Записи могут формироваться из трёх типов источников:

### 1. Шапка операции

Источник с именем `header` использует данные шапки объекта. На один объект-источник создаётся одна запись регистра. В выражениях колонок доступны только поля шапки через `$h.<columnName>`. Попытка использовать `$r.<columnName>` приведёт к ошибке, так как строка в этом случае отсутствует.

### 2. Табличная часть операции

В качестве источника можно указать любую табличную часть объекта. Для каждой строки табличной части создаётся отдельная запись регистра. В выражениях доступны:

- поля шапки через `$h.<columnName>`;
- поля текущей строки табличной части через `$r.<columnName>`.

### 3. Источник записей (RecordsSource)

Если формирование записей требует предварительной агрегации или преобразования данных (группировка, добавление расчётных колонок, умножение строк и т. п.), используется **источник записей**. Источник записей описывается на языке JavaScript и возвращает объект `DataTable`. Для каждой строки полученной таблицы создаётся отдельная запись регистра.

Подробнее источники записей описаны в следующем разделе.

## Выражения в правилах формирования записей

Каждая колонка регистра-приёмника заполняется одним выражением. Система различает три вида выражений:

- **Поле шапки** — выражение вида `$h.<columnName>`. Значение берётся напрямую из соответствующего поля шапки объекта-источника без преобразований.
- **Поле строки** — выражение вида `$r.<columnName>`. Значение берётся напрямую из соответствующего поля текущей строки (табличной части или источника записей). Недопустимо для источника «шапка».
- **Формула** — любое другое выражение, отличающееся от двух предыдущих форматов. Вычисляется интерпретатором JavaScript ([Jint](https://github.com/sebastienros/jint)). Внутри формулы также доступны конструкции `$h.<columnName>` и `$r.<columnName>`, которые на этапе подготовки выражения заменяются на обращения к контексту (`context.header.<columnName>` и `context.row.<columnName>`). Результат формулы автоматически приводится к типу данных целевой колонки регистра.

Примеры выражений:

- `$h.date` — дата из шапки документа;
- `$r.quantity` — количество из текущей строки табличной части;
- `$r.quantity * $r.price` — вычисляемая сумма;
- `$h.warehouse` — склад из шапки, используемый для всех строк документа;
- `"2"` — строковая константа (можно указать жёстко заданное значение, например, код статьи).

## Условия формирования записей

Для каждой строки правила можно задать **Condition** — выражение на языке JavaScript, возвращающее булево значение. Если условие возвращает `false`, для соответствующей строки-источника запись не формируется. В условии доступны те же обращения `$h.<columnName>` и `$r.<columnName>`, что и в выражениях колонок.

Примеры условий:

- `$r.вес_всех_кг > 0` — создавать запись только для строк с положительным весом;
- `$h.статус > 2 && $h.цех > 0` — создавать записи только для документов в определённом статусе и с заполненным цехом;
- `false` — временно отключить строку правила без её удаления.

Оставленное пустым условие означает, что запись формируется всегда.

## Флаг «Создавать записи» и отмена проведения

У каждой операции существует стандартная булева колонка `create_records` (в интерфейсе — «Записи»). Её значение влияет на поведение механизма:

- `true` — перед сохранением старые записи удаляются и формируются новые;
- `false` — старые записи удаляются, новые не формируются. Это эквивалент «отмены проведения».

При полном удалении объекта-источника все связанные записи регистров также удаляются автоматически (метод `DeleteAsync` класса `DataObjectsRecordsBuilder`).

## Источники записей

Источник записей — это выражение на языке JavaScript, возвращающее объект `DataTable`. Для каждой строки таблицы-результата формируется запись регистра по настройкам соответствующего правила.

Выражение вычисляется на сервере с помощью движка [ClearScript](https://github.com/microsoft/ClearScript). В контексте выражения доступны:

- `$h.<columnName>` — поля шапки текущего объекта-источника;
- `$t.<tableName>` — табличные части объекта-источника в виде `DataTable`.

> Обратите внимание: табличные части доступны через префикс `$t.`, а не через `$h.`. Префикс `$h.` зарезервирован для полей шапки.

`DataTable`, возвращаемый из табличной части или строящийся внутри источника записей, поддерживает цепочку вспомогательных методов: `.select(columns)`, `.addColumn(columnDef)`, `.process(fn)`, `.groupBy(keys, aggregates)` и [другие](/ru/calculations/dataTable.md).

Выполнение запросов к произвольным таблицам базы данных в источнике записей в текущей версии не поддерживается.

Вычисление источника записей происходит на сервере, поэтому не имеет смысла использовать выражения, доступные только в браузере. Например, вызов `alert` не приведёт к отображению сообщения пользователю.

### Примеры источников записей

Группировка табличной части по ключевым колонкам с суммированием мер:

```javascript
var source = $t.таблица
    .groupBy(['проект', 'марки'], ['общий_вес', 'сумма']);

return source;
```

Добавление расчётной колонки и смена знака перед записью в регистр (например, для документа расхода):

```javascript
var source = $t.таблица
    .addColumn({ name: 'кг', dataType: 'number' })
    .process(r => {
        r.колво_шт = r.колво_шт * -1;
        r.кг = r.общий_вес * -1000;
    });

return source;
```

Если выражение не возвращает `DataTable`, механизм записывает в журнал сообщение об ошибке и пропускает это правило, не прерывая создание записей по другим правилам.

## Пример: документ оприходования товаров

Ниже приведён фрагмент настроек реальной операции «Оприходование товаров». Для регистра остатков номенклатуры формируются записи по каждой строке табличной части `goods` с направлением «Приход» (`Direction: 0`):

```json
"recordsSettings": [
  {
    "destinationMetaObjectUid": "8a1c4e7b-2f3d-4a5b-9c6e-1d8f3b5e7a92",
    "rows": [
      {
        "sourceUid": "a5c6e39f-4b82-4d8e-9c1f-7e3a5b8d2c91",
        "direction": 0,
        "condition": "",
        "columns": [
          { "destinationColumnUid": "4b6d8e0a-...", "expression": "$h.date" },
          { "destinationColumnUid": "8c0e2d4f-...", "expression": "$r.nomenclature" },
          { "destinationColumnUid": "1d3e5f7a-...", "expression": "$h.warehouse" },
          { "destinationColumnUid": "4f6a8c0e-...", "expression": "$r.quantity" },
          { "destinationColumnUid": "7a9c1d3e-...", "expression": "$r.amount" }
        ]
      }
    ]
  }
]
```

Для документа «Списание товаров» настройки аналогичны, но `Direction` установлен в `1` (Расход): система автоматически инвертирует знак числовых полей записи, поэтому дополнительных преобразований в выражениях не требуется.

## Диагностика

Класс `DataObjectsRecordsBuilder` ведёт подробный журнал работы (`InMemoryLogger`). В журнал попадают:

- сообщения о начале и завершении формирования записей;
- количество созданных и пропущенных записей для каждого регистра;
- ошибки поиска регистров-приёмников, стандартных колонок, полей шапки или табличной части;
- результаты вычисления условий и выражений (при уровне логирования `Debug`).

Просмотр журнала позволяет быстро локализовать ошибку в настройках правил и выражений.
