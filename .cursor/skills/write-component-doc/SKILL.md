# Документация по BaSYS-компоненту

Скилл создаёт статью в `ru/userInterface/` по Vue-компоненту из репозитория `BaSys.Front` и проставляет ссылки на новую статью в обзорных статьях конструктора форм и программируемых компонентов.

## Когда применять

- Пользователь указал путь к Vue-компоненту (как правило вида `…/BaSys.Front/shared/src/components/BsXxxComponent.vue`).
- Пользователь просит написать статью / документацию / описание по этому компоненту.
- Скилл также применяется при формулировках типа «оформи аналогичную статью», «добавь статью по компоненту», когда речь идёт о компоненте BaSYS.

## Источники контекста (читать обязательно)

Прежде чем писать статью, прочитать:

1. **Сам компонент** — файл `BsXxxComponent.vue`, указанный пользователем. Извлечь:
   - Интерфейс `Props` (типы, обязательность, union-литералы для значений).
   - Маппинги/computed, которые расширяют семантику props (например, severity → CSS-класс).
   - События (`emits`), слоты (`<slot />`).
2. **Эталонные статьи** для стиля и оформления:
   - `ru/userInterface/bsViewTitleComponent.md` — минимальный пример.
   - `ru/userInterface/bsTextComponent.md` — расширенный пример с таблицами и JSON.
3. **`formElementBuilder.ts`** — `D:\_WORK\BaSysProject\REPO\BaSysApp\BaSys.Front\shared\src\models\forms\formElementBuilder.ts`. Найти метод `createXxx()` для текущего компонента и зафиксировать значения по умолчанию (`componentName`, `cssClass`, `style`, набор `addProperty`). Если соответствующего метода нет — указать это явно в статье.
4. **Примеры использования** — папка `D:\_WORK\BaSysProject\Experimental\Elevator\operation`. Искать по имени компонента в kebab-case (`bs-xxx`) для JSON-форм и в PascalCase (`BsXxxComponent`) для `.vue`-форм программируемых компонентов.

Использовать Grep по обоим вариантам имени параллельно, отбирать репрезентативные (разные) примеры: типовой минимальный случай, нестандартный (со стилем/severity/привязкой), пример из программируемой формы (`.vue`).

## Структура статьи

Файл сохранять в `ru/userInterface/bsXxxComponent.md` (имя файла — camelCase от имени компонента, как в эталонах).

Обязательные разделы (порядок и заголовки сохранять):

````markdown
# Компонент `BsXxxComponent`

<Краткое назначение в 1–3 предложениях. Если уместно — упомянуть имя в конструкторе форм (`bs-xxx`).>

<Типовые сценарии использования — маркированный список, 2–4 пункта.>

- **propName** (`type`, обязательный|необязательный) — описание.
- ...

<Если props влияет на класс/стиль через маппинг (как `severity`) — привести таблицу соответствия.>

## Свойства по умолчанию в конструкторе форм

<Из `FormElementBuilder.createXxx()`. Если метода нет — написать: «Компонент не создаётся через визуальный конструктор; добавляется вручную или из шаблонов программируемых компонентов» и пропустить таблицу.>

| Поле            | Значение по умолчанию |
| --------------- | --------------------- |

| `CssClass`      | `…`                   |

## Примеры использования

### Использование в шаблоне (программируемый компонент)

```html
<BsXxxComponent ... />
```

### Использование в форме-конструкторе (JSON)

```json
{
  "id": "bs-xxx-…",
  "componentName": "bs-xxx",
  ...
}
```
````

Правила оформления:

- Тон и стиль — как в `bsTextComponent.md` (нейтральный, технический, на «вы» не обращаться).
- Не дублировать общие сведения о конструкторе форм или программируемых компонентах — давать на них ссылки при необходимости.
- В JSON-примерах сохранять реальные `Id`, имена свойств (`Name`/`Value`) и порядок, как в исходных формах.
- В таблице маппингов значения брать буквально из исходного кода компонента.
- Для props, поддерживающих `v-bind` (`:propName`), приводить в JSON-примере вариант с `Name` вида `:propName`, если это типичный сценарий.

## Кросс-ссылки

После создания статьи обновить таблицы:

1. **`ru/userInterface/formConstructor.md`** — в разделе «Компоненты BaSYS» заменить голое имя компонента (` `bs-xxx` `) на ссылку (`[`bs-xxx`](bsXxxComponent.md)`). Сохранить ширину колонок таблицы.
2. **`ru/userInterface/programmableComponents.md`** — в разделе «Компоненты системы BaSYS» аналогично заменить ` `BsXxxComponent` ` на ссылку (`[`BsXxxComponent`](bsXxxComponent.md)`). Сохранить ширину колонок.

Если в одной из таблиц компонент отсутствует — добавить новую строку в правильную таблицу (с соблюдением алфавитного/смыслового порядка существующих строк) и сообщить пользователю, что строка добавлена.

После правок проверить, что обе ссылки указывают на созданный файл, например через Grep по имени файла `bsXxxComponent.md`.

## Рабочий процесс

1. Уточнить путь к `.vue`-компоненту (если не указан).
2. Параллельно прочитать: компонент, `bsTextComponent.md`, `formElementBuilder.ts`, обзорные статьи.
3. Параллельно Grep'ом найти JSON и `.vue` примеры использования.
4. Написать статью по шаблону выше.
5. Обновить кросс-ссылки в `formConstructor.md` и `programmableComponents.md`.
6. Кратко отчитаться: какие props описаны, какие примеры взяты (имя исходной формы), какие файлы обновлены.

## Что НЕ делать

- Не создавать статью на английском — все статьи в `ru/userInterface/` ведутся на русском.
- Не выдумывать props/значения по умолчанию — если данных нет в исходниках, явно отметить это.
- Не добавлять разделы «Установка», «Импорты», «История изменений» — они в данной документации не используются.
- Не менять `index.md` без явной просьбы пользователя — содержание индекса фиксированное.
